# 工作台视图、分屏与页面菜单方案

状态：2026-09-09 的方案，已实施（[实现与验收](../validation/2026-09-09-view-implementation/README.md)），不再维护；承接[模式审查](../validation/2026-09-09-mode-review/README.md)，「版本差异的边界」一节是 2026-09-10 补的。现行规则见[作者工作台设计](../web-product-design.md) 3.3 与 4.3。

## 目标与职责

顶部保留常用内容选择和阅读 / 编辑切换，低频操作集中到页面“更多”菜单。菜单按任务分组，不作为所有功能的总目录。

- 左侧大纲、文件、身份、依据、搜索决定查找方式。
- 已识别作品文件统一为作品页，普通文件使用通用文件页；文件树不引入另一种作品模式。
- 情节页保留设计 / 正文选择。它们是不同内容，不与阅读 / 编辑混为一组。
- 阅读 / 编辑由一个切换按钮完成，Tooltip 使用点击后的动作，如“切换到编辑视图”。属性局部编辑仍是后续设计方向，本轮保留属性只读表和源码编辑；未将源码编辑称为 Live Preview。
- 通用分屏负责同时摆放页面；设计与正文对照是打开配对内容的快捷命令。
- 版本差异仍是审查任务，标明比较版本、突出增删并支持逐块处理。

## 顶部操作

情节页顶部保留设计 / 正文两项内容选择、一个阅读 / 编辑切换按钮，以及更多菜单。人物、读者期待和普通文件页没有设计 / 正文选择。专用“并排对照”分段和常驻“版本差异”图标撤出顶部，操作进入菜单。

正文 / 设计的选中状态在编辑时继续可见。编辑状态不再只靠“返回阅读”表达，也不应因为开始编辑丢失参考页面。

## 设计与正文的组织及打开规则

左侧保留一套卷与情节目录，每个情节在中央页面内关联设计和正文。设计承载情节安排、关联人物、承诺等创作信息；正文承载实际叙述。两者都是作品内容，分别可阅读与编辑，不把设计等同于编辑模式，也不把正文等同于阅读模式。

首次从大纲打开一个情节且没有恢复现场或明确阅读意图时，默认显示设计。作者明确选择设计或正文后，当前窗格继续浏览其他情节时沿用这一内容偏好，不在每次导航时重置为正文，也不增加新的全局创作模式。

| 打开场景 | 目标内容 |
| --- | --- |
| 首次从大纲打开，无明确偏好 | 设计 |
| 当前窗格连续查看设计 | 设计，即使新情节已有正文 |
| 当前窗格连续阅读正文 | 有实际正文则显示正文；没有时显示设计，并说明“正文尚未开始，当前显示设计” |
| 显式点击正文、正文搜索结果、审稿原文链接或开始写作 | 正文，准确保留目标和定位；正文为空时显示可操作的写作空态，不强制跳回设计 |
| 显式打开设计或设计搜索结果 | 设计 |
| 切回标签页、前进后退、恢复工作区 | 恢复原视图与位置，不重新应用首次打开规则 |

内容不足引起的临时回退不改写作者明确选择的偏好，下一次打开已有正文的情节仍可继续阅读。只有新导航才计算默认内容，正文生成完成或后台刷新不能自动将正在看的设计换成正文。正文是否可阅读应依据实际正文和共享草稿，不只看文件存在与否、是否已提交；尚在加载时不能误判为空。

设计 / 正文两个选择的位置保持稳定；空正文回退到设计时，标题下只保留“尚无正文”，不显示横幅、toast 或额外 hover，也不在页面解释后续导航偏好。用户主动进入正文页时说明“正文尚未开始”，仍可开始写作。普通浏览不应先迫使作者经过空正文页面。分屏中各窗格独立保留内容偏好，让设计参考与正文写作可以同时进行。

## 更多菜单

正文统一使用情节页面的正文阅读 / 编辑视图，不附带设计属性和页末关系图；结构核对通过设计页或设计与正文分屏完成。原始字段在编辑视图中查看；文件树与大纲进入同一作品页，不另设源文件模式。

以下菜单已按当前文件和页面身份实现；不存在的能力不显示占位入口。

| 分组 | 条目 | 条件与对象 |
| --- | --- | --- |
| 当前视图 | 阅读视图、编辑视图 | 勾选当前项；与顶部按钮是同一命令和状态，正文模式切换可绑定统一快捷键 |
| 分屏与参考 | 设计与正文对照、左右分屏、上下分屏 | 对照只在情节页面提供；显式请求对照时，没有正文的一侧可提供开始写作入口。通用分屏作用于当前窗格 |
| 版本 | 查看版本差异、查看版本记录 | 当前作品内容有对应版本时提供；差异使用当前明确目标，不暗中选择另一份文件 |
| 文件与定位 | 在文件树中定位、复制相对路径、在 Finder 中显示 | 按当前目标生成。只定位不改变中央页面；从文件树打开已识别文件则激活同一作品页，明确对应设计或正文 |

采用分隔线区分任务，组序固定，快捷键靠右。不适用的条目隐藏，适用但暂不可用的条目禁用并说明原因。子菜单只用于有多个真实选项的操作，不为每一组增加一级嵌套。

固定、复制和关闭标签页继续留在标签页右键菜单；项目设置留在全局入口；保存状态和需要作者处理的冲突仍在当前工作面可见。不照搬重命名、移动、删除、合并、PDF 导出、新窗口等尚未纳入此次目标的文件管理能力。

## 分屏行为

通用分屏是工作区布局，不是文档显示模式。左右分屏和上下分屏创建相邻的标签页组，并打开当前页面的另一个视图。每个窗格有独立的当前标签页、访问历史、滚动位置、内容选择和阅读 / 编辑状态；同一文件的视图共享草稿与保存基线。

普通导航在当前活动窗格中按现有标签页规则打开；固定与未保存内容保护继续生效。用户可以在两个窗格打开不同对象，也可以让同一文件一边阅读、一边编辑。关闭一个视图不丢弃仍被其他视图使用的草稿；关闭最后一个有未保存改动的视图沿用现有保存处理。

“设计与正文对照”自动打开当前情节的设计与正文，建立一个明确的参考布局，无需作者手动找两份文件。它使用同一套分屏组件，不保留另一套专用只读双栏。没有必要默认同步滚动，因为两份内容长度和段落并不对应；默认也不将普通导航绑定到另一窗格。自动跟随情节若有后续需求，应显式表达。

分屏支持调整尺寸、关闭与恢复布局。“合并到相邻窗格”会保留并移动全部标签；关闭最后一个标签会移除该窗格。布局放不下时临时展示活动窗格并提供窗格切换，空间恢复后还原分屏与比例。它不等于左右辅助栏：文件导航与 Agent 等辅助面仍按现有职责工作。布局细节不能以牺牲正文可用宽度为代价，窄窗必须验收。

## 版本差异的边界

任意两页并置只能帮助人工参考，不能取代版本差异提供的比较基线、增删标记、变更块和处理动作。版本差异使用独立的比较标签，内部单栏或并排属于同一比较任务。设计与正文仍使用可独立导航的通用分屏。

2026-09-10 已落实以下规则：

- 从当前内容的更多菜单打开“标题 · 设计差异 / 正文差异 / 版本差异”；保留原标签、草稿、选区与位置。同一文件、同一基线跨窗格去重，关闭活跃比较优先回到来源标签。普通导航不覆盖比较标签。
- 默认以打开时的最新提交为基线，与当前内容（含未保存草稿）比较；并排时基线在左、当前内容在右，单栏时旧内容按位置显示在新内容上方。可选择历史版本；保存、新提交和刷新均不推进已选基线。没有变更时显示“没有未提交修改”，不暗中切换到更早版本。
- 基线内容只读、当前内容可编辑，提供上一处 / 下一处差异与逐块还原。还原写入共享草稿，可撤销；保存仍走原有 CAS，作品提交仍由 Checker 与版本事务处理。外部修改复用同一比较标签，保留冲突核对与合并基线操作。
- 提供单栏 / 并排切换。默认按实际内容区宽度选择：不足 760px 使用单栏，宽窗使用并排；显式选择按标签保存，缩放和重载不覆盖，更多菜单可恢复“跟随窗口宽度”。取消比较专用的上下布局，通用上下分屏不变。并排使用浅分割线和灰色拖拽反馈，可拖拽或键盘调宽。切换显示方式保留草稿、选区、阅读位置和撤销 / 重做记录，历史基线切换保留当前编辑器。
- 默认展示全文，并排默认联动滚动；“联动滚动”仅在并排时出现，“仅显示差异附近内容”在两种布局下均可用。比较文字统一 16px / 28px，正文使用中文长文排版；旧 / 新内容用淡红 / 淡绿底色及增删符号区分，折叠提示使用中文和灰色背景。读取期间或失败时明确显示状态，禁止对未读到的基线执行还原。

## 实施顺序与验收意图

1. 收敛顶部与菜单，共用动作定义和状态；保留现有可用功能，不显示假分屏入口。
2. 将当前单标签页组扩展为可分屏的工作区，复用页面、草稿和导航规则；这是实际布局能力改造，不只是移动按钮。
3. 让一键设计与正文对照复用分屏，再删除旧的专用并排实现，避免长期维护两套双栏。
4. 验证首次打开、连续设计浏览、正文缺失回退及偏好保持、显式正文定位与恢复规则；同时验证左右与上下分屏、分别阅读与编辑、同文件草稿同步、导航作用范围、关闭与重开、布局恢复及窄窗。版本差异继续验证真实增删和处理行为。

比较资料：[Obsidian 标签页与分屏](https://obsidian.md/help/tabs)、[阅读与编辑视图](https://obsidian.md/help/edit-and-read)。Obsidian 的实现提供参照；以上 Suiming 菜单分组和行为是本项目的已确认方案。
