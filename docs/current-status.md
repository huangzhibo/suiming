# 当前状态（2026-10-17）

本文只回答三件事：什么已经成立、证据到哪一级、还有哪些已知缺陷。形状以[系统架构](architecture.md)与 [Harness 设计](harness-design.md)为准；接下来做什么只在[路线图](roadmap.md)第 6 节维护，发生过什么见[变更记录](changelog.md)。

持续使用、数据保全及验证分工的长期要求见[需求与目标](vision-and-requirements.md)第 2、4.4、8 节；要求补齐不代表新增能力已实现，以下证据与已知限制仍分别有效。

## 概览

桌面工作台与自主 Agent 的主路径已贯通，可用性阶段已按[路线图](roadmap.md)第 6 节的出口于 2026-10-17 结束，转向斗破留出续写的全流程。短样例可以完成真实创作闭环，长篇副本可以浏览、搜索与核对修改，但还没有完整长篇质量、长期运行性能或正式发行的证据。

- **执行**：只有 Session（根 Agent，一份连续的消息列表，idle / running）与 Task（子智能体）。Agent 直接在作者的 checkout 上工作，与作者、host agent 共用一份候选和一条提交路径。创作路径没有预算，只有每轮用量检查点（[Harness 设计](harness-design.md)第 10 节）。
- **作品**：本地作品目录就是 git 仓，`refs/suiming/canon` 只由过 Checker 的提交推进；SQLite 只存执行数据。审稿与材料笔记是普通作品文件，正文 / 审稿时效与 Source 覆盖率从 git 历史派生。
- **入口**：Electron 桌面是核心产品；`suim` CLI 与 Codex / Claude Code / Grok 三个 host 共用同一 Runtime 与 Checker。旧 Cloud 实现已删除，未来按届时核心重新设计。
- **证据边界**：最高到「真实调用」。真实写作、真实流中断恢复与大型作品浏览均有证据；抽取原作、合成规模测试和少量正文不等于 Agent 完成真实长篇，也不能代替作者对文学效果的判断。

## 证据等级

| 等级 | 含义 |
| --- | --- |
| 机制 | faux provider 或内存 / 真实 store 上的确定性测试通过 |
| 真实调用 | 用真实模型 provider 在真实或样例作品上跑通 |

## 已知缺陷

- **历史观测缺失未能唯一归因，短超时问题已修复**：按需编辑同步验收的本地执行记录为 3 次模型 / 6 次工具，Langfuse 再查仍为 2 / 2。对应服务端时间窗有请求体读取失败，但未带 trace ID；已独立复现客户端 1500ms 短超时会放弃正常慢响应，现恢复上游默认超时和重试，并为每个失败批次补脱敏诊断。退出仍有界，不重建观测队列。旧批次未补造，不能因新运行成功就断言历史根因已经确证，见[排查记录](validation/2026-10-17-continuous-workbench/telemetry.md)。

- **持续使用的验收边界**：页面与短创作闭环已通过上述走查；已补齐 Agent 持续修改叠加多文件草稿、迟到保存成功 / 失败与重复冲突的受控组合，并有真实模型冲突后重读证据；跨作品、多轮修订与长对话叠加的多小时真实使用仍未系统验收。尚无完整无障碍验收。缺少这些证据不能靠要求作者反复排障来补，也不意味着已经验证的单项能力未实现。

- **长篇**：尚无 3 卷 30 Beat 的完整真实作品验收。最大的真实运行是 Agent 对《三国演义》前五十回的忠实抽取（231 节；隔离副本已继续补全与全 Source 复核）与斗破前 120 章的抽取和两组共 8 节的留出评测，都不是 Agent 自己写成的长篇。大型 checkpoint 的消息 / Context 对象去重、长列表和持续运行性能仍需规模数据测量；百万字符单文件已有合成编辑证据，不能代替真实长篇。[C 题库](c-question-bank.md) 17 道（目标不少于 20），2026-09-06 补硬状态后的回归是 13 / 17。
- **作者体验**：v7 工作台已在 2 Beat 样例上验收。Library 有最近作品列表与打开 / 新建，打开任意 Open Story Directory 会就地初始化；旧仓格式不迁移，初始化失败时文件夹保持原样。上下文栏与右栏可以拖拽调宽（[调宽验收](validation/2026-09-09-pane-resize/README.md)）。邻域图只画 frontmatter 声明的引用，看二跳就再点一次，不推断隐含关系。finding 的 Runtime 锚点仍只到文件，段落定位是窗口用审稿引文在 mdast 上对出来的，Reviewer 没引原文时退回到只锚文件。同一个文件被编辑器 buffer 与外部改动（作者、host agent、Agent）同时修改时只做 CAS 比较，入口是「比较外部修改」，不自动解决或覆盖任一方。Agent 整篇覆盖与删除也核对本轮读取版本；这些保护不等于外部任意进程写文件的全局锁，最终 hash 检查与文件替换间仍有跨进程竞态边界。
- **A / B 决策卡**（针对一段给两个改法让作者选）还没做，但不是做不了：零件都在，缺的只是 `validateProductEvent` 的 CUSTOM 白名单里的一个事件名，以及一次「作者读到一段不满意」的真实场景来定给几个改法、怎么呈现。它也是「作者否决」这类证据最干净的采集口。零件清单见[作者工作台设计](workbench-design.md) 4.4 节「A / B 决策卡」。
- **发行与认证**：已有 macOS arm64 自含 `.app` / zip 预览与同格式手工替换、冷备份回退验收；签名 / 公证脚本、ad-hoc 演练和篡改拒绝已验证，真实 Developer ID、公证、独立机器下载首次打开尚未完成，现按作者要求暂缓；没有自动更新器，详见[安装验收](validation/2026-10-15-macos-install/README.md)。设置页的登录向导接通了 pi-ai 全部 provider 的 API key / OAuth 流程（浏览器回调、设备码、手动粘贴授权码都能转述）。到「真实调用」的：API key（另经桌面 E2E）；`openai` 的 Sign in with ChatGPT——2026-10-02 登录并真实调用，10-03 凭据文件在一次真实刷新中被重写，当天 CLI 连跑多个一到两小时的运行没有一次因凭据失败。隔离服务的失效恢复与并发刷新已通过真实桌面 / CLI 组合验收，凭据轮换仍复用 pi-ai 和原文件锁；实际服务商的 refresh token 撤销及重新登录尚未验证，`openai-codex`、Anthropic 等其余 provider 的 OAuth 也不能因此标为已支持。订阅额度与作者自己的 Codex 共用，界面上的花费是按 API 价的估算，不是扣费。本地执行库暂不做跨 schema 转换，遇到旧版会拒绝且不改表；提示先完整备份、用兼容版本读取旧对话，只续作品则另建完整副本处理。同为 v6 / 当前 Story Language 的两个开发构建已验证替换安装与回退；不等于跨 schema 或历史正式版本升级已解决。启动失败现在通过原有工作台显示原因并可打开其他作品；正式交付仍须保证旧作品与对话可取回，不能以执行数据可丢代替。
- **命令边界**：CLI 与桌面 IPC 保留两份手写传输目录，共用领域 schema 和摘要投影，理由见[系统架构](architecture.md)。旧 Cloud API、存储 adapter、同步服务与专属协议已按 [ADR-0030](adr/0030-remove-frozen-cloud.md) 删除。未来 Cloud 不是当前能力或桌面验收缺口。
- **模型预检范围**：启动只预检这次对话用的模型。没单独配置的角色从 2026-10-05 起跟随对话的模型，预检查过的就是它们要用的；单独配置过的 writer / reviewer / source-extractor 不在预检里，凭据或模型有问题时失败发生在 turn 中途、token 已经花掉。可续做的调用失败现会给父模型真实 Task ID 和已有 `resume_task` 入口，独立模型失败、重载与原任务续做已定向验证；这不等于所有角色都做过提前预检。按实际会用到的 profile 预检需要先知道 Agent 会不会委派，未实现。
- **无人值守没有方向闸**：创作路径没有预算，兜底有 `run_no_progress`、每轮用量检查点与作者打断。检查点保证没人看着时一轮最多用掉约一次整本抽取的量（GPT-6.1 Sol 上约 $12），但它只封住用量、不判断方向，**停不住「持续产出但方向错了」的 turn**，只能靠作者发现（完整说明见 [Harness 设计](harness-design.md)第 10 节）。检查点的阈值作者在设置页或 config.toml 的 `session.usage_checkpoint` 调。带交付工具的子任务另有 `unsubmittedStops >= 3` 的收口，那不是方向闸。真正的结构性改善是让作者补充的意图能沉淀回作品，见 [AGENTS.md](../AGENTS.md) 不变量 5。
- **Agent 会为了自洽改动作者定下的 Design**：斗破留出第二次运行，审稿指出四星到五星没有交代，根 Agent 把一节抽自原作的 Design 改成与原作相反的星级，而意图写明前 120 章照原作建模、不改设定。回复与 turn 结束对账都列出了 Design 改动，作者看得见；但「先查原作或保留幕后突破」这样的判断仍靠模型，没有闸，也不该加闸（[记录](validation/2026-10-17-doupo-holdout-pipeline/README.md)）。
- **长期意图已验证短场景的持续维护，尚非全面覆盖**：六节三轮真实创作已验证首次写回、后续改口替换同一意图文件、保留未撤销偏好和新对话仅读复用，见[组合验收](validation/2026-10-14-continuous-recovery/README.md)。写回仍由 prompt 指导；每轮确定性对账只显示哪些文件改变，不判断全部要求是否正确保存。脚本偏好不冒充作者判断，多来源矛盾消解、长期组织和大上下文压缩后保持仍无充分证据。
- **大材料补全已覆盖全部分段，审稿仍受窗口与语义判断限制**：三国隔离副本五段 231 节均实际回读；76 份延后情节全部读取，Source Checker 与覆盖对账通过。真实摘要后继续整合、正常停止后原任务恢复已有证据。全 Source 审稿约 656 KB，默认模型的开场预检拒绝；此次单独选用更大窗口的 Reviewer，不裁剪范围。首份正式 pass 漏掉辅助核查的四条问题，根 Agent 回读后修正；不能将完整输入、覆盖率或 pass 当作无语义遗漏的保证。跨卷整合与摘要成本仍高，见[验收](validation/2026-10-15-large-source/README.md)。
- **`refs.beat` 的新写法尚未全量复核旧抽取**：抽取方法原来要「每节依赖的更早那一节写进 refs.beat」，与 Story Language 不一致，Agent 抽出的作品大量连上一节：示例三国 231 节 403 条、一半只跨一节；斗破前 120 章 153 节 449 条、28% 只跨一节。依赖闭包沿这条链传下去，`impact` 改前半本任何一节都召回后文的近九成。2026-10-04 两处措辞对齐为「紧挨着的上一节不用连」，闭包对上一节的依赖只算一跳、改 Beat 时总带上下一节（示例三国的召回降到后文的 3%）。同日斗破前 24 章重抽：只连上一节的从 22 条（33%）降到 0，跨节的依赖 44 → 42（[第七圈](validation/2026-10-03-doupo-mini/README.md)）；2026-10-15 又在三国隔离副本全部五段 231 节上验证跨卷补全，修正遗漏的早期依据并去除相邻冗余引用；120 章与公开三国样例仍没有全量重抽，旧数据里的相邻连线由闭包与故事轴兜住。
- **只活在对话里的事实，在别处看不见**：Session 的消息列表持久、完整，但不过 Checker、没有版本、不进 Open Story Package，换一个 Session 或换 host agent 就看不见；Context 头部那句「非作品事实」只是标签，不是边界。风险判断见 [Harness 设计](harness-design.md)第 2 节。
- **执行对象回收已接线，诊断还只在进程日志**：turn 结束后最多每天做一次，保留最近一小时对象；沿现存 Session / Task 的引用回收不可达节点与孤儿文件。删除事务核对活跃 turn 与扫描开始时的实体版本，跨连接启动又结束的 turn 也会使回收停止；可达对象丢失时停止删除并报警，不再静默忽略。历史旧库曾有大量字节丢失（2026-09-12），本次没有修复那些旧数据，也未提供桌面维护面板。故障注入已通过，见[边界回归](validation/2026-10-07-runtime-boundaries/README.md)。
- **命令回执从不清理**：每条执行命令留一条，三国作品一次长运行后 9,108 条、库里约 12 MB。2026-10-07 起构造执行状态不再读它们，只在命令撞上没见过的 commandId 时按 id 查一条（原来整份读，每次约 160 ms，现在 0.2 ms），所以它只占磁盘、不再拖慢 turn。簿记成本随历史平方增长的问题 2026-10-01 已修（[Harness 审查](validation/2026-10-01-harness-review/README.md) F1，数字在那里）；一整部长篇的 Context payload 与主进程响应仍需真实负载验收。
- **摘要已实测，长篇持续运行仍待验收**：2026-10-15 已替换旧的清空工具结果与 50% / 70% 压缩附注。真实模型在合成历史压力下分三批摘要，摘要结果落盘后受控退出再恢复，最新改口、已废止要求与原历史均保留；4 次调用与 Langfuse 的 purpose / ID / 用量对账一致。阈值仍需长篇负载调优，这不等于整部长篇持续运行验收，见[对齐记录](validation/2026-10-15-harness-alignment/README.md)。
- **长对话历史浏览与受控流式响应已复测**：详情按动作键逐块读取，不再解开完整 checkpoint；保留 10,000 节点 / 32 MiB 编码字节缓存上限，完整恢复与格式不变。真实 1314 动作历史的首项 / 末项冷读在独立 Node 中分别为 2–6 / 85–90ms；桌面 IPC 的末项首次读取为 275–369ms，切换历史为 454–494ms，三轮未见渲染异常或详情横向溢出（[测量边界与逐次数据](validation/2026-10-14-version-and-conversation/README.md)）。查找仍按序扫描。[流式响应验收](validation/2026-10-16-streaming-responsiveness/README.md)已另用合成长历史和受控提供商覆盖持续输出、动作展开、输入、停止与断线补读，复用 React / Streamdown 缓存减少重复渲染；其中主工作面持续输出约 29 秒、当前回复约 1.4 万字符。两份记录都不是全部 checkpoint 恢复或长期内存的性能结论。
- **版本查找的语义范围**：版本页、比较基准和材料侧栏已经共用搜索，可按 rN / 数字 / 提交编号查找；10 / 100 / 500 版本完整结果、窄窗和跨版本文件保持已验收。revision 投影目前缺少有意义的修改摘要与日期，尚不能凭故事内容找到未知版本；不虚构对话归属或日期分组，不把「另一稿」做成 git 分支界面，见[作者工作台设计](workbench-design.md)第 4.4 节。
- **花费是估算**：界面与 `suim session` 显示的花费是 token 数乘 pi-ai 目录里的单一美元单价，约等于 DeepSeek 的忙时价。DeepSeek 实际分忙闲时计费（[官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)：忙时只在北京时间工作日 9–12、14–18 点，节假日全天闲时，闲时减半），所以闲时跑的运行实际花费约为显示值的一半到七成。2026-10-02 升级 pi-ai 之前，配置里的旧 id `deepseek-v4-flash` 已被 DeepSeek 路由到 V4.1（官方公告 V4 Flash 下线），那段时间按旧目录单价记的花费偏低，实际约为记账值的 1.5 倍（闲时）到 3 倍（忙时）。对账以服务商账单为准；要显示得准，得按 provider 接入分时与币种的计价，目前没做。

## 可以声明的能力与限制

可以声明：共享领域内核、本地 git Canon、开放作品格式、CLI 与三个 host adapter 成立；自有 Harness、自主 Agent、标准事件与 Electron 创作闭环已实现，经过机制、真实进程与真实调用的验证。

不能声明：完整长篇文学质量、不劣于 host 的文学效果、桌面产品全部视觉与性能目标、正式发行、生产多用户 Cloud 或 SOTA。2026-09-06 的作者盲读仍优先于更早的「效果不劣于」判断。
