# 工作台审查与收敛（2026-09-10）

## 范围与判定

检查历次工作台修改及其 Desktop / SDK / Runtime 接入，结合全仓静态检查、状态测试和 Electron 回归。以作者工作台设计第 7 节为行为与视觉基准。源码中有必要的兼容恢复、CAS、编辑器历史和事件幂等边界不能按“补丁”直接删除；历史验收保留当时结果。

## 收敛方案

1. **共享状态脱离窗格。** Agent 草稿、未确认发送和附件是作品级共享状态，却经 `updateGroup` 写入；发起窗格关闭后，迟到回调可能被丢弃。直接更新 workspace 的共享字段，项目身份在长存活的根节点核对。
2. **引用只保留一种表示。** 内部统一 attachments；旧 context 字符串只在恢复入口一次性转换，移除界面、拼接和移除操作中的双分支。
3. **恢复只有一个入口。** 合并重复读取同一 localStorage key 的 loadView / loadWorkspace。页、标签、草稿规范化集中在存储边界，保留旧草稿与未确认命令；无效窗格树不能让可恢复标签与草稿一起消失。
4. **布局职责明确。** 分屏尺寸适应与树渲染从 workspace.tsx 独立出来；Agent 输入更新也有明确入口，不引入第二份状态或额外控制器层。
5. **公共样式归位。** 工具按钮尺寸和状态进入现有 Button 变体；栏高、图标、选中 / 悬停色、分隔线反馈使用共享 token。CSS 按阅读、导航、比较、输入器、分隔线和响应式归组，清理重复覆盖；保持原有视觉尺寸。

## 保留边界

现有 SDK 命令目录、只读事件快照、steering 派生查询和原生保存对话框各有独立职责，不因文件较长另建 Runtime 或服务。设计 / 正文是不同文件内容，阅读 / 编辑是操作，通用分屏与版本 diff 是不同用途。不同业务组件不强行共享业务状态。

不将这次收敛扩大为尚未实现的语音、多模态、Cloud 或领域重构。未发现问题的模块不为缩短行数机械拆分。

## 验收

覆盖恢复与迁移、关闭窗格期间的发送和附件回包、原有导航 / 分屏 / 版本比较 / 编辑历史、中文 IME 与滚动位置，以及普通 / 窄窗口下三栏工具和分隔线。执行结果见下方。


## 实施结果

- 已将共享输入操作移到根节点的 `useComposerWorkspace`，不经过 `updateGroup`；共享会话位置按最新 workspace 合并。文档窗格只负责页面定位与内容读取。
- `ComposerDraft.context` 已移除，旧值由 `restoreComposerDrafts` 转为引用。`loadView` 已删除，`loadWorkspace` 一次读取后调用纯函数 `restoreWorkspace`；页和历史表示只在该边界规范化。
- `WorkspacePanes` 负责分屏树及临时尺寸适配，通过渲染回调接入文档工作面。页面内容仍集中在 `WorkspaceSurface`，未为缩短行数拆出相互依赖的业务模块。
- 公共 Button 增加 `tool` 变体，`ToolButton` 仅保留提示和可访问禁用行为；委托菜单补齐同一点击范围。工具行高度、按钮尺寸、图标尺寸与列表状态色归入 token；分屏、侧栏和比较手柄合并反馈色规则，保留独立拖动算法。
- 当前设计文档移除与实际冲突的“待实施”表述；历史方案继续保留形成记录，当前行为与完成度分别指向工作台规范和当前状态。

全仓检查通过，281 项测试通过、9 项按环境跳过；13 条桌面流程均获得通过结果（首次全量 1 条全屏等待超时后单独重跑通过）。原生窗口已核对默认、窄窗口及展开对话。详见[验收与截图](validation/2026-09-10-consolidation/README.md)。

## 未扩大的范围

本轮没有证据要求改动 Runtime 执行模型、SDK 命令目录或新增持久实体，因此保留这些边界。主包和 CodeMirror chunk 仍有构建体积提示；后续应依据启动 / 加载实测再决定拆包，未直接改高警告阈值。此次审查不意味着全仓领域算法已完成逐行审计，也不覆盖尚未接入的语音与多模态能力。
