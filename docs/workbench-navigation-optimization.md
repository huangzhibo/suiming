# 工作台导航与文档交互优化方案

> 内容视图、菜单与分屏部分已由[后续方案](workbench-view-and-menu-proposal.md)取代，下文保留本轮导航决策的形成记录。

日期：2026-09-09。状态：已实施并通过本轮验证。本方案保留讨论结论、交互边界与验收要求；实际结果见[验收记录](validation/2026-09-09-navigation/README.md)。

长期交互规范见[作者工作台设计](web-product-design.md)，实际完成度见[当前状态](current-status.md)。本轮依据包括[工具栏实测](validation/2026-09-09-toolbar-review/README.md)、作者提供的 Obsidian 截图，以及随后对文件浏览、导航独立性和 tab 行为的讨论。

## 1. 优化目标与最终结论

作者应能在连续阅读、查找对象、检查源文件和直接编辑之间切换，同时保留当前工作现场。导航方式、页面身份、内容表示和编辑目标必须分别表达清楚。

| 讨论项 | 本轮采用的结论 |
| --- | --- |
| 左侧导航 | 大纲、文件、身份、依据、搜索切换的是查找方式；以作品大纲为首位和首次打开的默认入口，仅切换入口不改变中央内容 |
| 文件入口 | 增加文件夹按钮，在同一上下文栏浏览项目真实目录；复用现有标签页和文本编辑能力 |
| 面包屑 | 保留居中位置栏；作品页显示语义位置，文件页显示真实相对路径，由中央页面身份决定 |
| 内容视图 | Beat 保留一组「正文 / 设计 / 并排对照」，表示同一对象的不同内容展示 |
| 编辑与差异 | 编辑是目标明确的动作；「版本差异」是独立任务，不再与阅读组成第二组分段选项 |
| 标签页 | 普通导航复用当前 tab；显式新开、固定和未保存编辑保护有清楚的规则 |
| 一致性 | 相同职责共享尺寸、位置、状态和恢复规则；不同职责不强行使用同一种控件 |

撤回前面「面包屑必须左对齐」和「因为标题重复就删除面包屑」两项建议。重复名称是否合理，要看它是否补充位置或在不同可见状态下维持定位；当前 `text / 五色棒下` 的信息不足，不能推导出面包屑没有用途。

## 2. 区域职责与状态归属

本轮后续细化：左右栏可拖拽调宽，分别默认 244 / 384px；只有导航区实际放不下完整图标组时，才用当前导航菜单收纳五种模式，收起按钮独立保留。已撤回固定 280px 的菜单切换阈值，按钮保持 28px 点击宽度，间距随可用宽度从 6px 收至 2px，macOS 普通窗口在 224px 栏宽仍能显示全部图标；全屏时回收原生窗口按钮的留白，200px 即可保持完整图标组，退出全屏恢复避让。原「顺序」入口命名为「大纲」并排在首位，首次打开以作品对象为中心，已有工作现场仍恢复。顶部与内容区共享实际宽度；双击或 Enter 恢复默认，方向键与 Home / End 可调宽。宽度按作品保存，拖动不新增 tab 历史或改变页面；窗口临时收窄不覆盖宽度偏好。普通主区保留至少 600px；空间不足时先临时压缩右栏，再压缩左栏，达到两栏最小宽度仍不足时优先最近主动打开的一侧，窗口恢复后再显示两栏及原偏好宽度。具体尺寸与交互规范见[作者工作台设计](web-product-design.md)第 3.2 节。

| 区域 | 职责 | 保留的状态 |
| --- | --- | --- |
| 左侧导航入口与上下文栏 | 决定怎样查找对象或文件 | 每种导航各自的展开、筛选、选中与滚动位置 |
| 标签页 | 保留和切换打开的工作面 | 当前页面、固定状态、访问历史及页面视图状态 |
| 历史箭头 | 返回当前 tab 访问过的位置 | 页面的身份、表示、定位锚点与阅读位置 |
| 面包屑 | 表达当前中央页面的位置并提供有效父级定位 | 从当前页面派生，不另存一套路径 |
| 中央内容区 | 阅读、编辑和查看差异 | 对象表示、光标、选区、滚动位置；编辑缓冲按实际文件管理 |
| 右侧辅助面 | Agent、依据、反向链接、显式故事状态查询 | 复用已有模式恢复；故事状态的观察条件独立于页面导航 |

点击已激活的导航入口不隐式收起左栏。切换导航不新增历史记录，不替换中央 tab，不改变中央面包屑，不关闭编辑，也不把新对象自动选为故事状态查询位置。只有明确打开一个对象、文件或完整工作面，才进入中央导航规则。

这次细化的是现有上下文栏的浏览行为，不借此重建顶层业务模块或设置流程。

## 3. 页面身份与面包屑

### 3.1 作品页与文件页

已识别作品文件统一使用作品页；索引、配置、普通或未识别文件使用通用文件页。两者复用按文件路径保存的草稿与保存基线。

- **作品页**以既有作品对象为目标。一个 Beat 可以同时展示其设计和正文，当前表示不是对象身份的一部分。
- **文件页**以项目内真实相对路径为目标。用于索引、配置、辅助文件或未识别的文件；标题使用文件名。已识别的作品文档直接打开作品页。
- 故事轴、Review、版本差异等页面使用各自已有的范围或版本身份，不伪装成文件。
- 当前版本与历史版本明确区分；同一文件的不同版本不能因名称相同被合并成同一页面。

### 3.2 面包屑规则

| 中央页面 | 示例 | 父级操作 |
| --- | --- | --- |
| Beat 作品页 | 黄天将裂 / 五色棒下 | 卷名定位到左侧顺序目录中的所属卷；保留当前正文 |
| 人物作品页 | 人物 / 曹操 | 定位到人物列表，不为人物虚构所属卷 |
| 普通文件页 | notes / ideas.md | 文件夹定位到文件树的实际目录；末项保留真实文件名 |
| 故事轴卷视图 | 故事轴 / 黄天将裂 | 沿用已有返回全书范围的操作 |
| Review / 版本页 | 审稿 / 报告标题，或版本 / r8 | 只展示已有有效层级与入口 |

面包屑不得由左栏当前模式、文件点击来源或临时 `editPath` 决定。在 Beat 页切换正文、设计或并排对照，语义位置保持不变；在文件页切换阅读与编辑，真实路径保持不变。源文件路径可以通过更多菜单定位和复制。

没有父级数据时如实显示对象，不猜测归属、不静默归入第一卷。长标题只在展示层省略，完整文本可通过 Tooltip 或可访问名称获得。父级确有操作才呈现为链接；当前项不伪装成可点击按钮。

### 3.3 文件入口与作品页

作品页保留「在文件树中定位」「复制相对路径」「在 Finder 中显示」，目标是当前设计或正文文件。定位只切换并展开左栏，不改变中央内容。

点击文件树中的已识别文件，按统一 tab 规则打开或激活作品页。设计文件明确显示设计，正文文件明确显示正文；已有编辑页同步切换编辑目标，分别保留草稿与光标。普通打开不因文件入口生成另一份作品页，显式新标签或分屏仍允许副本。

已识别文件格式错误时显示诊断并允许编辑修复；无法建立作品索引时保留通用文件入口。不再提供「查看源文件 / 查看对应作品对象」。

## 4. 源文件浏览

### 4.1 入口与交互

- 在左栏视图入口中增加文件夹图标，名称为「文件」，与顺序、身份、依据、搜索采用同一尺寸、选中态与 Tooltip。
- 文件树复用当前上下文栏，不再增加一栏。首次使用仍默认故事目录，文件浏览保留自己的展开与滚动状态。
- 展开文件夹只改变树；点击已识别文件打开同一作品页，普通文件进入通用文件页。进入文件树本身不等于切换源码或开始编辑。
- 文件名和目录名来自磁盘真实路径；作品标题可作为辅助信息，不能替代文件名。
- 提供定位当前文件、复制相对路径，以及在 Finder 中显示的操作；当前位置没有单一文件时，不暗中选择一个。
- 文件页直接显示原始内容；Markdown 的阅读预览与源码属于同一文件页的内容表示，不额外生成 tab。编辑须经明确动作进入。

### 4.2 内容范围

浏览当前项目 checkout 中的作品文件、portable evidence 和项目辅助文件，例如 `AGENTS.md`、说明文档。辅助文件可以查看与编辑，但其存在或保存不会使其成为 Story Artifact，也不会进入作品提交、作品包或 Cloud 推送。

`.suiming`、`.git` 和临时文件不进入默认作者文件树。二进制或当前编辑器不支持的文件可列出、查看类型与大小，并在系统应用中打开；不按文本损坏其内容。portable evidence 保留现有不可变语义，通过领域能力产生新 evidence，文件浏览不提供改写已生成证据的捷径。

目录浏览应能列出无法解析或位于未知保留路径的文件并标明问题，便于作者修复。文件是否可见与文件是否能通过 Checker 提交是两个判断；不能因一个文件不合法导致整个文件入口失效。

新建、批量移动、重命名和删除文件不属于这轮新增的文件管理范围。已有作品创建与提交能力继续沿用领域规则。

## 5. 工具栏与内容操作

### 5.1 布局

保持左侧历史箭头、中部面包屑、右侧内容与操作区。面包屑在主工作面居中；同一窗口宽度下，不因编辑按钮文字或内容视图改变而左右漂移。各区有明确宽度约束，不能用无约束绝对定位叠在一起。

继续使用共享 `PanelToolbar` 的 36px 内容高度与 1px 边界。面包屑居中与分栏边界对齐是不同问题，不通过改变局部 padding 破坏既有横向分割线。

宽度不足时先收纳低频操作、截短面包屑中间层；仍不足时将内容视图组收纳为含相同选项的视图菜单。编辑目标始终明确，面包屑与按钮不重叠。沿用已有侧栏收起规则，不无限缩小文字。

### 5.2 控件职责

| 控件 | 行为 |
| --- | --- |
| 正文 / 设计 / 并排对照 | 同一个 Beat 的三种阅读表示；保留最后选择，不新增 tab |
| 编辑正文 / 编辑设计 | 编辑明确的实际文件；并排时在各栏提供对应入口，不能点「编辑」后静默选正文 |
| 保存 / 取消编辑 | 保存到 checkout，保持「已保存候选」与「已提交」的区别；取消涉及丢弃实际修改时给出明确选择 |
| 版本差异 | 比较明确文件与明确版本；从分段选择中移出，默认在当前 tab 进入差异任务并保留返回原视图的入口 |
| 更多 | 真实存在的低频操作，例如打开源文件、定位与复制路径；没有条目时不显示空触发器 |

进入编辑或差异任务后，用相应任务操作替换普通阅读控件；返回时恢复之前的内容表示与阅读位置。任一高亮都必须对应当前实际可见内容，不允许「并排对照」仍高亮而页面已只剩版本差异。

进入版本差异时默认比较当前已提交 head 与该文件的已保存 checkout。若作者有未保存编辑，须明确将右侧显示为「未保存编辑」并使用该缓冲，不能将它标成已保存候选；左侧版本固定，不被后续提交自动替换。切换比较对象属于明确操作。

无正文时展示真实空状态；需要正文的对照和编辑入口说明不可用原因，保留有效的设计操作，不静默打开其他 Beat。

## 6. 标签页打开与恢复规则

### 6.1 默认规则

采用「普通导航复用、明确保留新开」的一套规则。侧栏临时预览不等于 VS Code 的预览 tab，本轮不混入「单击临时 tab、双击保留」的第二套标签规则。

| 操作或条件 | 结果 |
| --- | --- |
| 切换导航、筛选或展开文件夹 | 中央 tab 不变 |
| 普通点击目录项、搜索结果或内容链接 | 目标已在其他 tab 打开则激活；否则复用当前未固定且无未保存编辑的 tab，记录历史 |
| 当前 tab 固定或有未保存编辑，打开不同目标 | 保留当前 tab；优先激活已有目标，没有则新建并激活 |
| 当前对象内切换正文、设计、预览、源码或进入编辑 | 保持当前 tab；不属于跨对象导航 |
| 菜单「在新标签页打开」 | 明确新建并激活，允许与已有目标并存 |
| ⌘/Ctrl + 点击，或中键点击可导航目标 | 明确在后台新建；加 Shift 则激活新 tab；右键菜单为无需快捷键的等价入口 |
| 点击已有 tab | 切换工作面，保留各自视图、光标、选区与滚动位置 |
| Review 中选择 finding | 更新该 Review 的证据区并定位原文；不为每条 finding 自动开 tab |
| 明确选择「打开原文」 | 遵循普通导航规则；同时提供新 tab 打开选项 |
| AI 完成、收到事件、新增 Review | 更新状态与结果入口，不自动导航、打开 tab 或抢焦点 |

普通请求的去重依据是页面类型、真实目标与版本，而不是显示标题。同一作品的文件入口与对象入口统一身份，正文 / 设计表示不造成重复 tab。明确复制页面或新 tab 的请求不被去重规则取消。

固定用于保护页面不被外部新导航替换，不阻止作者切换该页的内容表示。后退 / 前进只访问当前 tab 的历史；需要离开有未保存修改的文档时，保留原 tab 并在另一 tab 打开历史目标，不丢弃缓冲或推进原 tab 的历史游标。

### 6.2 新建、关闭与比较

- 「＋」和 ⌘/Ctrl + T 打开空白选择页，可搜索对象 / 文件并显示最近访问；不复制当前页面，不因此创建作品文件。
- 「复制当前标签页」是单独命名的操作。重复视图指向同一个实际文件时共享同一编辑缓冲，不产生互不知情的两份修改。
- 关闭最后一个 tab 后显示空白选择页，关闭按钮不能无响应。
- 关闭包含未保存内容的最后一个视图时，提供保存、放弃、取消；如果该缓冲仍由其他打开的视图持有，关闭单个视图不丢弃它。
- 同时看两份内容使用现有并排对照 / diff 工作面。通用自由分栏和多窗口不作为本轮实施前提。

### 6.3 恢复与文件变化

后退、前进、切换 tab 和重载须恢复原页面的表示、滚动位置及适用的光标 / 选区。历史记录保存位置快照，不只保存一个路径字符串。

未保存缓冲按项目和文件保留，关联读取时的内容 hash。外部 host 或 Agent 改动文件后，不覆盖已有缓冲；继续复用内容 hash 检查与冲突处理。重载恢复的草稿不自动写入 checkout，也不因恢复就成为候选或提交。

打开的对象被删除或失效时保留可理解的缺失状态，允许返回或定位，不静默关闭 tab、跳到第一份文件或丢弃可恢复草稿。

## 7. 工程落点与边界

实施前 `tabs` 只是路径数组，历史仅保存字符串，`beatView`、`edit` 和编辑缓冲由工作台全局持有；源文件列表来自已识别的 Story Artifact。本轮已按下表调整这些边界。

| 落点 | 调整 |
| --- | --- |
| `apps/web/src/model.ts` | 区分作品页、文件页、已有专题页及空白页的客户端身份；由身份派生标题、面包屑与导航目标 |
| `apps/web/src/view-state.ts` | 使用稳定 tab 标识，整合 tab 自己的历史和表示；各左栏视图独立恢复；客户端草稿按文件保存 |
| `apps/web/src/workspace.tsx` | 统一打开、激活、固定、关闭与历史导航规则；移出单个全局编辑缓冲；避免每个点击来源自行决定新开或替换 |
| `apps/web/src/left-pane.tsx`、`pages.tsx`、`ui-bits.tsx` | 文件树、作品 / 文件页面、居中面包屑、明确的编辑与版本差异入口；复用现有基础组件 |
| `packages/sdk/src/workspace-commands.ts` 与 Local 应用服务 | 补项目目录列举、源文件读取和辅助文本文件保存能力；IPC 继续从同一命令目录接入 |
| `apps/desktop` | 复用项目根限制与系统打开能力；主进程持有文件访问，renderer 不直接操作磁盘 |

同一 checkout 文件在不同页面出现时，共用一份编辑文档状态；tab 仅持有视图和光标等各自状态。历史版本只读自己的快照，不与当前 checkout 的编辑缓冲混用。此状态属于可恢复客户端草稿，不新增 Runtime 执行实体、第二作品存储或独立提交通道。

目录列举必须能在局部格式错误下工作，但不放宽原有 codec、Checker 与提交规则。项目已打开而作品投影失败时，仍须保留项目外框和文件入口；目录浏览不能以整个 `workspace.show` 成功为前提。路径分类继续复用现有实现；未知保留路径的诊断用于列表展示，不使其成为合法 Artifact。Story Artifact 保存继续走现有内容 hash 与 checkout 写入；辅助文件复用本地文件边界，明确不参与 Artifact diff、提交和作品同步。

现有[故事状态](visualization-design.md)查询、Agent 草稿、引用预览、Review 快照及外部修改检查都属于必须保留的行为。只调整 UI 状态与必要的本地文件能力；不改 Story Language、Run / Harness、Cloud 产品范围和作品格式。

## 8. 实施顺序

| 顺序 | 交付 | 完成条件 |
| --- | --- | --- |
| 1. 页面与工作状态 | 页面身份、tab 状态、共享文件缓冲、统一导航策略 | 普通打开 / 显式新开 / 去重 / 固定 / 未保存保护 / 历史恢复贯通，不再依赖单个全局 buffer |
| 2. 文件能力与入口 | 容错文件列举与读写边界、文件树、文件页、双向定位 | 真实文件、辅助文件和无效作品文件都能找到；保存与作品提交范围正确 |
| 3. 工具栏与面包屑 | 语义 / 真实路径切换、居中布局、一组内容视图、明确编辑与差异任务 | 同对象表示切换不改变位置；没有无效高亮、空菜单或隐式编辑目标 |
| 4. 整体验收 | 真实作品副本、窄窗口、重载、外部修改、键盘与截图复核 | 以下矩阵通过，更新验收记录与当前状态 |

各步按依赖顺序推进，但作为同一轮优化交付，不把文件树或未保存保护降成只有视觉入口的占位功能。

## 9. 验收矩阵

| 场景 | 必须观察到的结果 |
| --- | --- |
| 正文阅读时切换顺序 → 文件 → 身份 → 搜索 | 正文、tab、面包屑、阅读位置、右栏观察条件不变；左栏各自恢复 |
| Beat 页切换设计 → 正文 → 并排对照 | 同一个对象、同一条语义面包屑；仅对应视图高亮 |
| 从并排对照分别编辑设计、正文 | 目标路径与按钮一致，返回后恢复并排和阅读位置 |
| 并排对照后进入版本差异 | 清楚显示比较文件和双方版本；不残留「并排对照」的无效高亮 |
| 作者有未保存修改时查看差异 | 右侧显示真实缓冲并标为未保存编辑，不误称 checkout 候选 |
| 作品页定位文件，再打开文件 | 定位只改变左栏；打开已识别文件则激活同一作品页并选择对应内容 |
| 从文件页切换左侧故事目录 | 当前内容保持不变；点击对象才按普通导航规则打开作品页 |
| 连续普通点击多个对象 | 未保护 tab 复用；后退恢复对象、表示与阅读位置，不无限增加 tab |
| 固定或编辑未保存时打开别的对象 | 原工作面与缓冲保留，目标使用已有或新 tab；不要求先保存才能查阅 |
| 相同目标普通打开与显式新开 | 普通请求激活已有；显式新开允许副本；同名不同目标或版本不误合并 |
| 同一文件在多个标签或窗格编辑 | 共用缓冲和基线，不出现两份相互覆盖的候选 |
| 「＋」、复制 tab、关闭最后一个 tab | 空白选择、复制、回到空白分别符合名称，按钮无静默失效 |
| 重载与外部修改 | 草稿和页面可恢复；外部修改不覆盖草稿；失效页面有真实提示 |
| 非法 frontmatter、未知保留路径、辅助文件 | 文件树仍可用，诊断可见；辅助文件不进入作品 diff / commit / package |
| 越界路径、symlink、二进制与 evidence | 沿用项目文件边界，不越界读取、不错误文本写入、不改写不可变证据 |
| Review 逐条定位与 AI 后台事件 | 原 Review 工作现场保留；事件不抢 tab、焦点或故事状态条件 |
| 1460px 常用窗口、960×640 最小窗口、长路径与无正文 | 栏头边界一致，面包屑居中且无重叠；操作可发现，无内容时不出现假数据 |
| 键盘、中文输入法、树与菜单焦点 | 等价的新开入口、清楚的焦点和控件名称；输入法组合不触发导航 |
