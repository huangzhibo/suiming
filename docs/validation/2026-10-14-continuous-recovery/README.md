# 连续创作与异常恢复组合验收

## 范围与预期

从 `f518ef7` 的干净工作区开始，按路线图第 6 节第一项执行。公共赤壁样例拆为六个连续情节，使用隔离的作品、应用数据和凭据副本。全程由维护者自主操作，不占用作者反馈；六节短文不代表完整长篇质量。

预先设定三轮创作：写第 1–2 节并保存长期偏好；改口为允许长短句交替、轻修第 2 节并写第 3–4 节；写第 5–6 节并独立审稿。每轮只提交一次。篇幅与本轮范围不得写成长期规则，禁止感叹号的规则继续有效。另开新对话仅读意图，随后人工修订、保存、提交、退出重开。

异常组合包括运行中重载、退出中断后原对话继续、未保存草稿与外部修改、跨作品切换、迟到的附件回包，以及独立配置的 Reviewer 模型失败后的续做。真实调用、可控故障和测试脚本失误分别记录。

## 真实桌面创作

模型为 GPT-6.1 Sol、高思考深度。真实桌面主进程与同一 Runtime 工作，未注入 faux。六节正文共 1,408 个字符（含空白与标点），三轮创作提交 r2、r3、r4；一次独立 Reviewer 审六节并保存一份报告。人工将结尾的一处「他」改为「阚泽」，经桌面保存并提交 r5；重开后文本完整、无未提交修改、旧审稿 `current=false`。初始版本算在内共五个 Canon 版本。

| 场景 | 核对结果 |
| --- | --- |
| 首轮运行中重载 | 同一 session、第 1 轮继续；只提交 r2，未重发作者消息 |
| 第二轮退出后续做 | 改口消息已持久化，退出回 idle；原对话下一句继续，完成第 3–4 节和第 2 节轻修，只提交 r3 |
| 长期偏好改口 | 同一 `intent/正文风格.md` 改为允许长短句交替；保留克制、禁止旁白直接解释计谋与感叹号；本轮篇幅和情节范围未写入 |
| 退出重开后第三轮 | 原对话继续，完成第 5–6 节与独立审稿，只提交 r4 |
| 新对话复用 | 实际读取两份 intent，明确回答「现在不要求所有句子都短」，引用文件依据；未改文件、未提交 |
| 人工修订与再重开 | 编辑草稿重载后仍在，保存、提交 r5 后重开内容一致；审稿时效变旧，设计、状态、六节正文检查均通过 |

六节正文逐份检查无感叹号。Checker 保留样例起始的两条引用提示：第 3 节提及黄盖未声明引用、第 1 节建立诈降期待未引用火船；它们不阻止提交，未为消除警告擅改本轮设计。独立审稿通过只代表本次模型判断，不替代作者对文学效果的评价。

## 发现并修复的问题

独立子任务发生模型调用失败后，Task 和已读 checkpoint 均存在，但父模型拿不到任务编号，无法可靠使用已有 `resume_task`。先加入独立 Reviewer provider 的故障回归，修复前在「父模型必须拿到真实任务编号」处失败。

修复复用作者停止时已有的 `childProgress`，给可续做的调用失败、输出截断和未交付结果补上任务编号与续做办法；超窗、模型不可用和反复无进展不提示原样重试。没有新增状态或恢复流程，决定见 [ADR-0025](../../adr/0025-actionable-child-failure.md)。

修复后的 Runtime 与 Electron 验证：先读取人物档，独立审稿模型报错；根对话显示失败原因并回 idle；重载后发送继续，沿用同一 Task 和独立模型、保留此前读取，只生成一份审稿和一个新版本。完成后再重载，没有重复提交或渲染异常。

## 跨作品与迟到结果

真实 Electron 操作覆盖两部作品的同名正文路径：甲作品保留未保存草稿，引用设计文件的回包被闸门截住；切换乙作品后再释放，同时从外部修改甲作品正文。乙作品输入草稿重载后仍在，没有收到甲作品附件。回到甲作品，编辑草稿仍在，外部修改提示可见，重载也不消失。

比较页两侧分别显示外部文本和未保存稿；人工合并后保存、提交，只增加甲作品一个版本，乙作品文件与版本不变。另验证运行中的作品切换被明确拒绝，原对话结束后可正常切换；另一部作品没有混入其会话。停止子任务再续做另复跑既有 Electron 用例。

## Langfuse 对账

本轮隔离作品显式开启内容采集，常规配置保持关闭。按 session、入口 `desktop`、环境 `validation`、构建 `continuous-20261014` 查询 observations：

- 主对话 4 轮、35 次已确认调用，107 条 observation；三轮 `completed`，退出中断那轮 `stopped` / `WARNING`。
- 新对话 1 轮、3 次已确认调用，7 条 observation，`completed`。
- 共 38 次调用，747,461 token（含缓存），按目录价估算约 $0.2572，不是实际扣费。
- generation 数与本地 confirmedCalls 一致；调用编号唯一，每条工具均能关联到 generation；709 条持久事件 ID 唯一，5 条作者消息没有重复，AG-UI 生命周期验证通过。

补验使用真实 GPT-6.1 Sol 根模型和独立配置的合成 Reviewer：后者连续 6 次失败，耗尽 5 次自动重试；根模型先报告失败并结束，下一轮自行调用 `resume_task`。只有一个 Task、一份审稿和一次提交。Langfuse 收录 26 条 observation，6 次真实根调用、8 次合成 Reviewer 调用；两个子任务 span 的任务编号相同，先 ERROR 后成功，父轮均正常结束（子任务故障已被父模型处理）。失败的 review 结果包含正确任务编号，后续 resume_task 使用同一编号。

真实主模型处理受控 Reviewer 故障的补验及最终检查数据见 [measurements.json](measurements.json)。[probe.mts](probe.mts)可在已构建的仓库中用已配置模型重跑，只有根模型真实，Reviewer 的失败与交付是合成数据，不能作为审稿质量证据。

## 测试过程中的修正

首次编排脚本误用了不存在的停止命令，随后正常退出应用，中断了第二轮；这是脚本错误，不是产品异常。记录按实际发生的「退出中断」验收，不冒充点击停止测试。恢复时没有重建作品或重复发送改口指令。

跨作品脚本最初在 renderer 完成作品切换前就输入，后改为等待新作品标题可见；正文草稿引用不走文件读取，因此迟到回包改用设计文档触发。人工重开断言原先把「不要求」误写成「不再要求」，纠正选择器后复验通过。真实根模型故障探测的首轮短故障被自动重试消化；第二轮混用了 src 与 dist 的异常类，未到达目标路径。这些失败不计入产品通过证据，最终探测的 Harness 与 agentTurn 统一使用构建产物并耗尽受控自动重试。另有一次并发启动原生窗口的定向运行超时，按仓库要求串行复跑 3/3 通过；未把并发那次记为通过。
