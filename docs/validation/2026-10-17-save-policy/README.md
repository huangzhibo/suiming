# 保存时机对照实验

## 目标与验收（先定边界）

比较手动保存、显式交给 Agent 时同步所选文件、停止输入 1.5 秒后保存三种方式。生产默认、工具、协议与数据格式不改；原型只放在本目录。三个模式用同一份公共样例，分别建立临时 checkout 和真实 Git Canon，不读取日常作品、配置、凭据，不调用模型。

验收先核对事实，不以通过用例推断作者偏好：

1. 同时编辑人物和意图文件；交付人物文件时，检查另一份半成品是否仍只在草稿。
2. Agent 读后作者保存，迟到整篇写入必须被拒；Agent 先写后作者保存，作者草稿与 Agent 文件都保留。
3. 保存回执迟到时继续输入并切换文件，不能清除新内容或抢焦点。
4. 批量交付中一份保存失败，不能开始 Agent 操作；已成功保存的文件不假装回滚。
5. 删除后不自动复活；输入法组合期间不触发计时保存；后台文件的计时器独立工作。
6. 分别把「语法合法但句子没写完」和「YAML 尚未写完」交给实际 Checker / commitCheckout，核对候选、检查和 Canon 的边界。
7. 计时保存冲突后不循环重试；只读操作不偷偷保存；更换实验模式撤销旧计时器。

## 实现与复现

- [交互原型](prototype.tsx)复用生产 `CodeEditor`、`editDocument`、`savedDocument`。只有保存触发、选中文件集合和实验操作面板属于原型，没有复制领域模型。
- [驱动与验收](probe.mts)调用生产 `readProjectFile` / `saveProjectFile`、`fileTools`、`LocalProjectService.check` / `commitCheckout` / `exportRevision`。保存沿用桌面同一底层 CAS 与原子替换；直接执行 Agent 文件工具，固定读写顺序，避免模型选择不同操作造成不可比。
- 每个场景新建公共样例副本和独立浏览器上下文。Playwright 拦截页面请求并在本机提供原型文件，不启动网络服务；不加载 provider、不读取凭据、不输出 Langfuse trace。运行结束删除临时作品；截图与构建后的原型保留在本机临时目录。
- 原型草稿只保存在内存，不承诺重载恢复；生产草稿持久化没有改变。原型的勾选表示这次同步和读取的文件，**不构成 Agent 后续工具权限范围，也不是局部 Canon 提交范围**。

从仓库根运行；首次使用或跨包源码变更后先 `npm run build`，避免跨包 import 读取旧 dist：

```sh
node --import tsx docs/validation/2026-10-17-save-policy/probe.mts
npx tsc -p docs/validation/2026-10-17-save-policy/tsconfig.json --pretty false

# 可交互体验，选择模式后再编辑；要比较同一起点，关闭并重新启动。
node --import tsx docs/validation/2026-10-17-save-policy/probe.mts --interactive
```

## 实测结果

**26 / 26 组独立场景通过，真实模型调用 0 次。**逐项结果见 [measurements.json](measurements.json)。生产测试数不因此增加，这组原型不是正式桌面 E2E，也不是 Claude Code 插件的运行测试。

同组数据：人物文件补完一句；意图文件只写到“第二幕人物最终决定”；只勾选人物交给 Agent。下面的保存数是第一次交付时实际调用生产保存函数的次数，不是体验耗时或用户点击数。

| 观察 | 手动保存 | 交付时同步所选文件 | 停顿 1.5 秒保存 |
| --- | --- | --- | --- |
| 停顿后首次交付的保存次数 | 0 | 1 | 2 |
| 首次交付读到人物新句 | 否；显式保存再交付后读到 | 是 | 是 |
| 尚未停顿就立即交付 | 读到旧磁盘内容 | 读到此次交付的内容 | 读到旧磁盘内容 |
| 未勾选的意图半句话进入候选 | 否 | 否 | 是 |
| 实际提交后，意图半句话进入 Canon | 否 | 否 | 是 |

手动组在初次读取旧稿后补一次显式保存和交付，再执行同一提交检查；没有把“用户忘记保存”当作手动模式的全部体验。停顿组既检查等待超过阈值，也检查未到阈值立即交付：后一种情况下，计时器随后落盘使 Agent 旧整篇结果被 `file_write_conflict` 拒绝。这是版本保护在起作用，同时说明单靠 debounce 不能确保交付新鲜内容。

**半成品的两个不同结果：**

- 普通段落中的半句话是合法 Story Artifact；实际 Checker 通过，`commitCheckout` 推进 Canon，再从 `exportRevision` 逐字确认它已经进入版本。保存本身没有推进 Canon，是后续明确执行的实验提交纳入了整个候选。
- 未完成的 YAML 也可被编辑器保存到候选，但实际提交被拒，Canon 保持原版本。手动组未保存时，磁盘仍合法，坏语法留在草稿；这不是手动保存拥有额外 Checker 能力。

**覆盖与多文件结果：**

- 三组均拒绝 Agent 读后作者落盘所造成的迟到整篇写入；反向顺序中，作者保存受阻，磁盘 Agent 内容与作者草稿都保留。
- 保存落盘后暂扣回执，继续输入并切到另一文件：生产 `savedDocument` 保留后续输入，回执不抢活动编辑器焦点。停顿组随后按新基线保存剩余输入。
- 外部删除后三组均拒绝普通保存，没有复活文件。停顿组失败后不持续重试，也没有用空基线强行重建。
- 定向交付不保存无关文件；**全选交付同样会把合法半句话送进 Canon**，所以“发送前保存所有草稿”不是推荐方案。
- 批量第二份注入保存失败：Agent 读取次数为 0，第二份草稿保留，第一份已成功落盘，明确反馈部分保存，未新增事务或回滚机制。
- 批量交付捕获点击时的各文件内容；暂扣第一份回执期间继续编辑第二份，第二份新输入留在草稿，不偷偷加入此前的交付。
- 合成 `compositionstart` / `compositionend` 事件验证组合输入期间不触发计时保存，结束后重新计时；切换模式取消尚未执行的计时器。普通读取不会调用保存。
- 宽窗与 800px 窄窗走查、截图检查通过。原型沿用编辑器，窄窗把实验操作面板移到下方，没有水平溢出；不是生产布局改版。

## 迭代与验收边界

原型首次通过 `file://` 加载模块被 Chromium CORS 拦住，改为 Playwright 本地响应资源；没有关闭浏览器安全设置。首次迟到回执验收只等磁盘字节变化就断言草稿清除，发现落盘早于回执；改为分别核对落盘与回执完成，保留对迟到阶段草稿存在的断言。随后 23 组通过，再加入三组“尚未停顿就立即交付”，最终 26 组通过。原型类型检查与文档链接检查通过。

没有修改生产 `apps/**` / `packages/**`，没有重跑全仓与完整 Electron 并冒充新增证据。没有做真实模型适应性试验、原生中文输入法人工操作、原型崩溃恢复或用户偏好测试；输入法结果限于组合事件处理。1.5 秒是本轮对照参数，不能据此宣称它是最佳阈值。外部进程在 hash 检查与 rename 之间的竞态仍沿用 [ADR-0035](../../adr/0035-shared-checkout-write-protection.md) 的尽力检测边界。

## 推荐方案（尚未进入生产）

**优先采用“默认手动保存 + 显式、定向保存并发送”的组合。**核心收益是少一次独立保存操作，同时让作者能预知这次把哪些编辑交给 Agent；不是认为自主 Agent 与自动保存不可共存。

1. 作者针对已有文件请求修改或附带当前编辑时，在原发送操作中明确展示将同步的文件，并使用“保存并发送”的语义。不增加常驻横幅，也不要求每次再弹一个确认框。
2. 只同步作者本次明确选择交出的文件；不因切页、普通提问、Agent 自己的 `read` 或全书检索而自动保存其他草稿。引用文件不应无条件等同于授权保存，交互须说明实际行为。
3. 捕获点击时的内容，等待全部相关保存成功才发送；等待期间的新输入继续留在草稿。若保存受阻，保留消息和草稿，显示具体失败文件与已经保存的部分，不自动覆盖或回滚。
4. 保存、Agent 整篇写入、删除与迟到回执继续复用现有保护。同步成功只说明当时的落盘结果，后续仍可能有新编辑或外部变化；不引入文件锁、自动合并或第二套候选。
5. 明确“已同步文件”与 Canon 提交范围不同：Agent 后续提交仍扫描整个 checkout。该操作不能保证只提交本次选中文件，更不能让 Checker 判断半句话是否完成。

全局停顿保存暂不推荐为默认：它在本轮同时带来非目标草稿进入候选，以及立即交付仍读到旧内容两种问题。未来若选择它，需要接受工作中间态随时可读、可被提交的产品语义，并补上交付时的刷新保证；不能靠调长延迟宣称解决。没有证据证明现在需要新建草稿发布层或逐文件提交机制。

现行工作台说明只纠正“有 Agent 就必须手动保存”的论据，生产仍按原方式工作。Claude Code 扩展的读写前 autosave 参照来自[官方设置说明](https://code.claude.com/docs/en/vs-code#extension-settings)；这里推荐的显式交付方式与其触发时机不同。实现与否留待方案选定，后续队列只在[路线图第 6 节](../../roadmap.md#6-立即执行队列)维护。
