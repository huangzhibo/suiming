## 结果

| | host 版 | 上午先读后抽 | 新流程 |
| --- | --- | --- | --- |
| 用时 / 调用 / 估算 | — | 3 小时 / 337 / $10.77 | 1 小时 53 分 / 387 / $14.99 |
| 卷 / 节 | 7 / 29 | 6 / 115 | 2 / 153 |

| `refs.beat` / 秘密 / Contract | 37 / 9 / 5 | 182 / 18 / 14 | 449 / 31 / 13 |

| Source 审稿 | — | 三轮，每轮有 major | 一轮，0 major / 4 minor |

- **并行在全量上成立**：6 段分段与 6 段补全都在同一次回复里派出，各 15 分钟。上午那次光读原文写笔记就 24 分钟、抽取 90 分钟、审稿来回一小时。
- **内容更完整也更干净**：Beat 正文总量与 host 版相当、是上午的两倍；因果依赖、秘密、World 都明显更多；审稿一轮没有 major。
- **补全最贵，补的是实东西**：6 段补全改了 87 个文件、114 处，抽样看是第一遍记不全的东西——给后面的 Beat 补跨段 `refs.beat`；新声明「萧炎隐秘师承」，补「薰儿助力九段突破」及其 `revealed`；「加列奥的手多半废了」改成原文的「恐怕只有三品以上丹药才能救」；萧媚「暗想自己与他没多少血缘关系」这种没被强调的心思，只有知道后文才认得出。代价是每次请求带整份抽取，约 15 万 token。
- **四个 minor 里三个是同一类**：人物档末尾写给续写者的防误读提醒——「不应让他凭现场记忆判断」「不能以她后来亲眼所见倒填早先认知」「不据称呼建立实际祖孙血缘」。方法只禁了「此处有出入」这类按语，补上这一类（`87fc59b`）。

## 暴露的缺口与处理

| 现象 | 处理 |
| --- | --- |
| 分卷太粗：第一卷第 1–106 章 129 节，第二卷恰好等于第 6 段。整合没有挪文件的工具，只能逐节 `copy` 再 `delete`，就沿用了段界少挪 | 文件工具加 `move`，换卷是改 index 再挪文件，方法写明一卷一次（`ebddbbe`）；分卷是否合理下次运行再看，不先改 Story Language 的卷定义 |
| 人物档里的防误读提醒 | 抽取方法写明证据边界写成故事内的事实（`87fc59b`） |
| 章节对应核对又花了一个子任务、19 分钟、$1.13 | 评测才要的信息，各段笔记里已有每节的章节与起点；暂不进方法 |
