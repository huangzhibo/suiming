# Agent 按需同步作者编辑

## 范围与验收

采用 [ADR-0036](../../adr/0036-agent-editor-sync.md)：普通操作只需输入并发送；Agent 实际访问哪个文件，就通过现有保存 CAS 同步哪个文件，不增加保存范围菜单。保存只改变 checkout，不推进 Canon。冲突返回模型，由原 `read` / `write` 读取两边、比较、合并或恢复，不要求作者先操作按钮。

先以真实文件和受控时序验证范围与保护，再用隔离 Electron 走生产 IPC、编辑器与文件工具，最后用真实模型核对其能理解拒绝并自行完成合并。临时作品来自公共样例，应用数据与配置隔离；不改日常作品。凭据不复制，真实调用沿用原有加锁凭据存储。

## Claude Code 参照

官方 [VS Code 设置文档](https://code.claude.com/docs/en/vs-code#extension-settings)说明 `claudeCode.autosave` 在 Claude 读写前保存。另核对 Anthropic 官方扩展在 Open VSX 的 2.1.301 发行包（未安装），SHA-256：`6bdac01ea938a1870cdc51bf82131c8bbd92c4732e4b7133355a6c0b9e8e3f78`。

[探针](claude-probe.mjs)从给定发行包 JS 提取保存函数，用临时文件和模拟 VS Code 文档接口验证：

- 只处理 `Read / Edit / Write` 的 `file_path`；其他打开文件不保存。
- `Glob / Grep / Bash / MultiEdit`、干净文档和关闭 autosave 不触发保存。
- 保存失败、打不开文档或等待超时后，钩子仍返回 `continue: true`。这不代表最外层执行器取消后还会执行工具。

[测量结果](claude-measurements.json)是发行包函数验收，不是实际 Claude IDE 并发测试。Suiming 借鉴目标路径同步，但同步失败明确返回模型，避免把旧磁盘内容当作作者最新稿。

## 组合走查

- Runtime：路径边界先于编辑器回调；读、写、复制、移动、删除只同步相关路径；目录浏览不触发。准备写入后又有作者编辑，原 CAS 拒绝旧写入。角色权限保持原边界。
- 桌面：三份草稿只处理甲乙，丙与未发送消息保留；延迟保存回执时继续输入、切页，Agent 旧结果必须重读，焦点不跳转。
- 冲突：甲成功、乙遇外部修改，模型读取草稿 / 原基线 / 磁盘。读取后作者继续输入，旧合并被 draft hash 拒绝；磁盘也有独立 CAS。合并落盘后的迟到回执不把继续输入变成可覆盖新磁盘的旧稿。
- 恢复：renderer 重载后恢复草稿再响应；关窗后按需创建隐藏工作台，沿原草稿与对话继续，不要求作者手动重开。
- 保存与 Canon：自动同步及冲突合并不提交版本；既有 Checker / commit 流程保持独立。

旧持续 Agent 测试因“读取仍保留未保存稿”的前提改变而更新：改为在首次自动同步后，再注入手动保存的迟到回执，继续验证作者输入、另一文件草稿与焦点保留；没有撤掉覆盖保护验收。

## 真实模型与界面

[真实探针](probe.mts)只发送一条消息，让 Agent 整理公共样例的意图文件与一份辅助笔记。两份均有未保存编辑，笔记另有外部新增内容，第三份未触及草稿继续留在编辑器。实际模型为 GPT-6.1 Sol / high，3 次调用、约 27.5 秒，保留两边新增句子并完成要求的补充；Canon 仍为初始版本。模型直接选择 `read(editor: true)`，随后两次 `write(draftSHA)`，无需人工保存、比较或确认；因此本次真实调用证明主动合并能力，自动保存失败后的重试与竞态由受控 E2E 证明，不混写证据。

[结构化测量](real-measurements.json)保留用量与工具序列，不存模型原文。第一次探针在文件、界面与重载断言通过后，读取 checkpoint 时传错 `LocalProjectService.open` 参数；修正脚本后回读同一隔离副本完成验证，没有重新调用模型，也没有把探针错误记成产品故障。

逐图检查 [正常窗口](real-desktop.png)与 [960px 窄窗](real-narrow.png)：消息区仍是原输入框与发送按钮，无保存范围菜单、额外横幅或待人工处理卡片；未触及的第三份文件仍显示草稿标记，其他文件已保存。窄窗发送入口可见，重载后第三份草稿和下一条未发送消息保留，renderer 未捕获异常为 0。

## 复跑

```sh

node --env-file-if-exists=.env --import tsx docs/validation/2026-10-17-agent-editor-sync/probe.mts
```

## 证据等级与限制

受控桌面故障不等于真实模型创作质量；单次真实模型合并也不代表多小时持续使用。CLI / 外部 host 不读取桌面缓冲，目录搜索和提交不冲刷所有草稿。语法合法的半句话可能进入候选，Checker 不能判断作者是否写完。
