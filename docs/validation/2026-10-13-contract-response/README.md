# 期待回应语义与桌面验证

本轮删除结构化回应期限，依据 [ADR-0020](../../adr/0020-contract-response-without-deadlines.md)；实际事件路径沿用已确认布局。

## 验证范围

- 领域：完整作品的处理记录、未完待续与 Source 边界、回应可为有意义的否定、旧字段不再静默接受；引用和生命周期顺序检查保留。
- Runtime：写作上下文、状态查询、影响分析、Agent 检查文本与语义指南同步。
- 桌面：空记录、等待回应、实际回应、多次推进、非法候选、宽窄窗、提示、来源跳转和故事轴。
- 数据：公共示例移除 12 个重复期限；五份本机作品完整备份后迁移 71 个字段，其中 36 个独立节奏安排转入正文，35 个与已有回应重复。所有迁移经 Checker 后由 Runtime 提交，原版本不改写。私有作品与备份不入仓。

## 结果与迭代

- 先补领域验收，确认旧实现不能通过新语义，再更新实现。全仓 `npm run check` 通过。
- `npm test`：480 项，475 通过；5 项外部数据库、对象存储或跨进程集成测试按配置跳过。
- 桌面首轮 32 / 32 通过。迁移后的实际作品走查发现旧格式历史导致正文时效被误报为全书设计已变；改为明确的「时效无法确认」，增加不可解析历史与发布阻塞回归。不能比较历史时不伪造变化，也不宣称设计未变。
- 上述迭代后的桌面全量复测有一项提示位置断言失败，单项复测通过。原断言没有等待进入动画结束；改为等待动画完成后检验原方向与窗口边界，单项再次通过。最终全量复测 **32 / 32 通过**。

- 重启当前桌面后，在已迁移作品中核对实际回应路径和正文时效：没有期限徽标，原有蓝绿节点和连线保留，旧格式历史显示「时效无法确认」。本机作品的截图不入公开仓库。

## 有限真实调用

`check-issues` 与 `contract-response` 各运行一次，2 / 2 通过，均未改动作品。后一任务要求核对三日之约、首节处理的节奏计划与次节实际回应，Agent 主动查询规则、运行检查，明确不应前移回应标记，并指出故事内失约原因及前后时间表述仍需语义审查。完整脱敏回复及构建指纹见 [model-results.json](model-results.json)。

这两次调用验证的是规则理解和检查使用，不是长篇质量结论；自动文本匹配之外也人工核对了回复。运行发生在正文时效 `unknown` 的现场修正之前，后者由领域回归与桌面走查覆盖，不能把该真实调用证据延伸到后续修改。
