# 斗破接着往下写第 121–140 章（2026-10-18）

[路线图](../../roadmap.md)第 6 节第 6 项，留出评测阶段的最后一项：抽取截在第 120 章，Agent 按作品意图自己设计并写第 121–140 章，原作同号章节作参照。原作不是唯一正确的写法，这里看的是 Agent 定的情节会不会让设定与人物走样、推进与原作差多少；评委只量「离这部书有多远」。

## 做法

- **作品**：2026-10-03 新流程的 [120 章抽取](../2026-10-03-doupo-segmented/README.md)，153 节正文全放原作，`source/` 去掉。第 121 章以后没有 Design。
- **意图不改**：用的是作者原来写的续写要求——每节一万字左右、分三到四章、每章两千五到三千字，章号从第一百二十一章接着往下编。
- **作者消息**：「接着第 120 章往下写第 121 到第 140 章，写到第 140 章为止：先把这一段的情节设计写进 Design，再按设计写正文，语气、节奏和人物说话方式与前文一致。写完独立审稿，按意见修，检查并提交。」
- **一条命令**：[continuation.py](continuation.py)，搭作品用 [build_eval_work.py](../2026-10-03-doupo-agent-gpt/build_eval_work.py) 的续写模式，执行、dist 指纹与评委配置复用[留出脚本](../2026-10-17-doupo-holdout-pipeline/holdout.py)。没写到第 140 章才替作者说「继续」，最多两次。
- **模型**：根 Agent 与子任务 `openai/gpt-6.1-sol`（思考 high）；评委 deepseek-flash 开思考、读者口径、4 轮（[评委位置偏差](../2026-10-17-judge-position/README.md)定下的配置）。构建 `5126471`。

```sh
DOUPO_CHAPTERS=<按章拆分的原文目录> python3 -I docs/validation/2026-10-18-doupo-continuation/continuation.py \
  <120 章抽取作品> <那次 Agent 的回复.md> <输出目录>
```

## 情节：设定接得上，推进慢一半

逐章对了星级、穆力与穆蛇父子、小医仙和紫晶几条线。Agent 没有和前 120 章立下的设定冲突：萧炎的星级从五星接着往上走，穆蛇按二星斗师写，小医仙仍在青山镇行医、研读毒经，地阶斗技焰分噬浪尺与报复狼头佣兵团两条是前 120 章的 Contract 留下的线，都接着做了。药老一直只在戒中提醒，没有出手代打。

推进差得多。原作这 20 章里，萧炎第 121 章升六星，第 122 章学会地阶斗技，第 123–126 章报复狼头佣兵团、杀了团里第三强者八星斗者赫蒙（穆力这 20 章里没死），第 128–129 章独战二星斗师穆蛇，第 130 章突破七星，第 131–139 章遇上神秘女人与紫晶翼狮王、夺得紫灵晶，第 140 章到九星斗者。Agent 的 20 章：第 121–125 章学斗技，第 127 章才升六星，第 131 章杀穆力，第 133–136 章与小医仙重逢、交出搜杀手令，第 137–138 章被穆蛇追杀、断涧脱身，第 140 章到七星——大约只走到原作第 130 章的进度，没有碰紫晶翼狮王这条线。杀穆力是 Agent 自己的选择，与原作分了岔，但不违背前 120 章的设定。每章照作者意图写短了，但一件事用的章数多：练功、猎食、换药、算回气丹这些日常写成了场面。这与留出评测里「Agent 每个 Design 字写出约两倍正文」是同一个倾向，只是这次落在情节密度上。

## 评委

| 节 | 对应章 | 前文 | 4 轮结果 |
| --- | --- | --- | --- |
| beat-0525 | 121–124 | 原作第 120 章 | 原作 4:0 |
| beat-0526 | 125–128 | Agent 的上一节 | 2:2 |
| beat-0527–0529 | 129–140 | Agent 的上一节 | Agent 4:0（三节都是） |

只有第一节能比：两版接的是同一段原作。评委的理由是 Agent 稿「更像精细化的同人重写：对白太密太现代，节奏拖在日常小挫折上」，原作「训练、突破、杀佣兵、反派议事一路往前推」，与上一节的情节对照一致。后四节的前文是 Agent 自己写的情节，评委判原作「和前文接不上」「像翻回了前头很远的一段」——情节已经分岔，问哪一版接得上前文，答案只能是 Agent，这三个 4:0 不说明文字更好。另外，原作参照里还残留几处章首、章末的求票留言（`build_eval_work.py` 的清洗没剔干净），评委也拿它扣原作。

## 证据边界

- 只跑了一次；作者还没有抽读（本项做完的判定里要作者抽读一章给一句话，与第 5 项的盲读一起问）。
- 设定走样只对了星级、人物实力与几条主线的事实，没有逐句核对；审稿覆盖的是与本作 Design 的一致性。
- 篇幅短于原作是照作者意图写的，不是写手的问题；意图里每章两千五到三千字与原作这一段的实际章长（多在三千一到三千八）不符，要不要改由作者定。
- 走的是 CLI，构建 `5126471`，不含 [4b](../../roadmap.md) 对 Write Context 的改动。
