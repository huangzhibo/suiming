# 多文件草稿与跨作品恢复验收（2026-10-16）

## 范围与隔离

本轮补齐多个未保存文件在真实退出进程、关窗重开和跨作品切换中的组合验收。每次经 `launchDesktop` 启动真实 Electron，使用临时作品、独立 user-data、配置与凭据；不访问日常作品与账号，不调用真实模型，也不刷新作者正在使用的窗口。

两部作品分别保存相同路径的正文、人物和辅助笔记，另有各自的未发送对话草稿。所有文件原文、未保存修改和 Canon 历史分开核对，不能只凭重开后页面可见就判定保全。

## 发现与迭代

现有跨作品用例直接调用 bridge，覆盖了草稿和迟到回包的隔离，却绕过了实际作品选择弹层。新验收从「切换作品 → 打开作品」以及「最近作品」进入，复现切换成功后弹层仍打开，后续 `⌘T` 被弹层拦住、不能继续搜索编辑的问题。

修正只在作品成功切换后收起已有弹层，再恢复目标作品的工作区；取消选择或打开失败仍留在原作品。未新增草稿库、退出协议或焦点持久字段。沿用 [ADR-0032](../../adr/0032-document-shell-feedback.md) 的临时反馈与焦点边界。

## 实际路径与断言

- **同路径隔离：** 两部作品各编辑三份文件，保留不同草稿和三字符处的光标位置。从真实入口往返，逐一切页直接续写，再撤销这次输入，确认焦点与插入位置；同时逐字核对磁盘原文未改。
- **退出进程与重开：** 正常调用 Electron `app.quit()`，等待原进程关闭；用同一个隔离 user-data 启动新进程，不传作品路径，让应用重开最近作品。逐一回读三份草稿、未发送消息，再切到另一作品复验。单独保存乙作品正文后，甲作品所有原文以及乙作品另外两份文件仍未变，Canon 不因草稿恢复或保存自动推进。
- **草稿存储失败：** 对 renderer 原有存储注入写入失败，再新增一句话；实际切换操作被保存失败拦住。退出时经原生确认选择「继续编辑」，进程、编辑焦点和最新内容保持。恢复存储后关闭窗口，主进程仍运行，再走原生 `activate` 路径创建新窗口，三份草稿和对话草稿完整恢复。
- **窄窗与视觉：** 在 960 × 640 窗口检查重开后的多个未保存标签、工具栏和正文，截图核对没有残留作品选择弹层或额外反馈层。渲染异常单独收集并断言为空。

回归位于 `apps/desktop/test/multi-draft-recovery.test.ts`。系统目录选择和原生确认的返回值由隔离测试控制，其余切换、关闭、持久化、重开与文件保存均走产品代码。

## 结果与边界

两项新增组合验收定向通过，并在最终完整 Electron 回归中再次通过：69 / 69、0 skip，包含原生全屏、长正文、跨作品冲突、文件恢复、搜索与键盘操作。全仓检查通过，单元与集成测试 479 / 479、0 skip。

本轮恢复的是草稿内容、活动文档、光标位置和编辑焦点。重开后验证的撤销是新输入的撤销；没有把跨进程恢复历史撤销栈宣称为支持。存储失败是故障注入，不代表磁盘损坏或系统断电验收。未验证新的真实创作质量或模型认证能力。
