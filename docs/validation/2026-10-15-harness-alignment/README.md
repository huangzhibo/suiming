# Harness 通用机制对齐

2026-10-15。决策见 [ADR-0026](../../adr/0026-harness-context-lifecycle.md)。只使用公共样例与隔离副本，未改真实作品；trace payload、凭据与执行数据库不入仓。

## 已实现

- Runtime、CLI、desktop 共用 pi-ai 1.2.0，pi-telemetry 同步到 1.2.0。直接复用上游瞬时故障分类和 token 估计工具；未引入 Experimental 的 pi-durable，也未复制 main 上尚未发布的修复。Google SDK 仍为 2.21.0，不需变更安装脚本许可。模型目录由 1537 增至 1554 个，新增 47、移除 30；当前已配置档位没有使用被移除的模型，设置页与真实调用均通过。
- `read` 同时限制行数与 50 KiB UTF-8 内容；长单行按行 / 码点列续读，中文、emoji 与组合字符重组无遗漏、无重复。Source 补全只预载当前号段的 Beat（正文上限 48 KiB），跨段索引与依据仍可主动读取，写范围不扩大。
- 自动摘要和 provider 超限恢复共用现有 loop。旧作者消息纳入摘要，保留任务开场、最新作者原话与近期完整交互；每批摘要同时读取最新输入。原消息与动作不删。删除清空工具结果与两档压缩附注，模型主动 `compact_context` 复用同一投影。
- 摘要走原 Gateway、checkpoint、用量与调用关联，以 `purpose=compaction` 标识。AG-UI 显示工具执行、重试与整理进度；异常活动与执行结束在同一 SQLite 事务中收尾，没有额外 pending 状态库。

走查先复现再修复：

1. 动作开始事件使“续做子任务”入口提前，旧分组仍按结果位置查找，入口跑到了组外；现在兼容开始与结束两种事件顺序，失败的重复续做不会被认领。
2. 超限摘要后遇到普通瞬时错误会再次强制摘要；现在只在超限发生时安排恢复摘要，后续重试正常进行。
3. 摘要开始与退避开始使用同一事件身份而冲突；两者身份分离，原调用照常记账。
4. 强退不执行 finally，活动可能永久显示执行中；改用已有持久执行收尾位置，删除 Harness 临时 pending Map 与 finally。
5. 较早历史的分批摘要若看不到最新输入，会把已废止要求仍写成有效；每批都附最新输入，真实模型复验已明确标出旧要求废止。

停止测试用明确的模型请求信号对齐时点，避免把“动作行刚出现”当成“下一次请求已经发出”。并发运行原生桌面用例的一次追问未送达，未记通过；使用项目规定的串行方式复测通过。

## 真实连续创作与 Langfuse

[验证脚本](probe.mts) 在公共赤壁样例副本上运行三轮：第一节正文与长期偏好写回；第二节续写与偏好改口，独立 Reviewer 受控失败；沿原 Reviewer 任务恢复，检查后提交。最终有两节正文、4 个版本，审稿 taskId 未改变。Langfuse 的 edit 输入另核对两次 Intent 修改：先写入“不用议论解释”，随后替换为关键转折允许一句简短点明。

执行存储与 Langfuse 对账：21 个唯一 model_call_id，18 次真实 GPT-6.1 Sol 调用、3 次受控 faux Reviewer 调用；费用约 $0.15234 一致。真实模型中 1 次瞬时错误自行恢复；Reviewer 的受控错误也在观测中标 ERROR。三个整轮 observation 均有 completed、不同 turn_id、同一 session_id 与 validation 来源。合成 Reviewer 的通过结果不作为文学评价。

另以合成旧对话施加 8k 窗口压力，使用真实模型分三批摘要，再生成三句话场景。第一份摘要结果确认保存后故意退出，恢复直接应用已有响应；原 34 条消息完整保留，没有重复摘要调用。最终摘要明确取消悲剧结局、守塔人活着返回但失去一艘船；实际续写符合这一改口。4 次真实调用（3 compaction、1 execution）与 Langfuse 的唯一 ID、purpose、用量及约 $0.038738 费用一致。早期未附最新输入的一次运行已由这次复验取代，不混算最终证据。

观测通过 Langfuse CLI 的 observations API 查询，未使用 trace API。原始结果留在本机，不提交 trace payload。内容采集仅在此隔离验证显式打开，产品默认仍关闭。

## 重跑与边界

先构建，再运行：

```sh
node --env-file=.env --import tsx docs/validation/2026-10-15-harness-alignment/probe.mts
```

只复测真实摘要可设 `SUIMING_VALIDATION_ONLY=context`，聚合结果可用 `SUIMING_VALIDATION_RESULT` 指向仓库外的文件。完整回归按 Runtime AGENTS 的节奏运行。
