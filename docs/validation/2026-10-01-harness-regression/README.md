## 两处没过，各是什么

- **review #2：判分规则错了，不是 Reviewer 的问题。**脚本拿每条 finding 的引文去正文里找，可 finding 可以锚在 Design 文件上——引文是否出自锚定文件，`submit_review` 落盘前已经确定性地校验过（`review-authoring.ts` 的 `quoteMissing`，2026-09-13 起）。这一项现在改成只量锚在正文上的 finding 能不能落到段落（工作台要做的那一步），并记下锚不到的引文；这次的 2 / 3 无法按新规则重判，作废。
- **delegate-writer #2：turn 以 `EISDIR` 失败。**`read` 一个目录时文件系统抛的原始错误没有变成工具拒绝，loop 把它当基础设施故障，整个 turn 结束——委派出去的 Writer 读错一个路径，作者这一轮就白跑了。本地复现：`ConfinedExecutionEnv.readTextFile("text")` 抛 `Error: EISDIR`。这是真缺陷，不是模型的问题，`3b54f13` 修掉。

另外记下两个数：委派出去的 Writer 每次读 7–8 个文件，而它的 system prompt 说「你没有其它文件的读取权」（审查 F7：prompt 与权限不一致）。它确实在读。
