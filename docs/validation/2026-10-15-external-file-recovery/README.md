# 外部文件变化与草稿恢复（2026-10-15 至 2026-10-16）

## 范围与隔离

在真实 Electron 中使用公开的两节样例和辅助笔记，验证外部删除、重命名、未保存编辑、切页返回、阅读 / 编辑切换、窗口重载及焦点恢复。作品、user-data、配置和凭据均放在临时目录，经 `launchDesktop` 启动；不修改日常作品，不连接真实模型或日常账号。本轮没有新增 Langfuse 调用或文学质量证据。

按 [ADR-0031](../../adr/0031-external-file-draft-recovery.md)，沿用现有作品目录、共享草稿、CodeMirror 历史和 `workspace.file.save`，不增加备份服务、重命名映射表或自动迁移草稿的机制。草稿属于原物理路径；重命名后的文件独立打开，不根据相似内容猜测它是不是原文件。

## 发现与修正

1. 对象从作品投影消失后，文件查询被禁用，编辑页面可能继续沿用旧缓存。现在已打开的路径继续读取实际文件状态；缺失的辅助文件不再展示查询缓存中的旧正文。无草稿的辅助文件删除用例在修复前明确复现“错误提示出现，但旧正文仍在”。
2. 文件不存在时只剩泛化的修改冲突，辅助文件没有显式恢复入口，阅读态也可能失去返回草稿编辑的入口。现在保留草稿可编辑性，区分“尚未创建”与“曾存在、现已缺失”，提供“恢复到原路径”。普通保存继续拒绝过期基线；恢复通过原保存命令传空基线，只在原路径仍不存在时写入候选，不自动提交 Canon。
3. 保存失败后选择外部版本作为合并基线，旧错误仍优先显示，遮住了成功提示。设置基线时同步清除已处理的错误；未保存内容保留，作者继续合并后再保存。
4. 正文草稿所在情节的设计文件被移动后，切回阅读再编辑会误选缺失的设计路径，显示空内容。原正文草稿仍在存储里，但入口丢失；现在复用页面已有的编辑目标，在对象缺失时继续保留，菜单与快捷键走同一读编切换路径。
5. 全仓回归遇到既有 Harness 测试的偶发误报：它在整段 transcript 中查找 `v1`，随机工具调用 ID 也可能包含这两个字符。固定一个含 `v1` 的 ID 可稳定复现；改为检查 system 消息里的工具声明，保留历史 ID，不改执行行为。

验收用例先于修复补入。测试自身也经过校正：文件创建完成前按 ENOENT 等待而不直接退出；短文用 CodeMirror 的实际行内容核对，避免 `innerText` 重复计入空行；合并输入用真实键盘替换，不用 `contenteditable.fill` 引入额外空行。窄窗按真实可用的新标签检索入口操作，不假设收起的侧栏按钮仍然可见。

## 验收路径

- 人物、正文、辅助文件各自带未保存草稿删除：提示更新不抢编辑焦点；普通保存不恢复文件；切页返回后继续输入的位置正确，撤销可用；读编切换、重载保留原文与草稿；关闭时保存失败可取消，焦点回原编辑器；明确恢复后内容落盘，Canon 版本不变。
- 人物与辅助文件重命名：新路径显示磁盘内容，不套用旧草稿；返回旧标签和重载后仍保留草稿。原路径被外部重新创建时转为修改冲突，不抢对话输入焦点；普通保存不能覆盖它，比较合并后保存保留双方内容，改名后的文件原样保留。
- 无草稿的人物与辅助文件删除：失效提示出现，不继续展示旧正文；外部恢复原路径后可重新编辑。
- 正文有草稿时删除其情节设计：切换阅读 / 编辑、重载仍打开原正文；保存只写正文，不错误新建设计文件；设计文件外部恢复后仍显示同一正文。
- 从未创建的正文首次编辑：不误报为外部删除，重载后正常保存。
- Runtime 层验证删除 / 改名后的普通保存拒绝、空基线恢复、原路径后来出现时拒绝覆盖、私有路径与越界保护，以及 Canon 不自动推进。
- 辅助文件删除组合在 960×640 窗口执行，提示无横向溢出；其余操作在常规桌面窗口执行。检查正常与窄窗截图，保留原页面布局及公共控件。
