# 2026-09-09 可视化操作验收

本文保留当时的操作与结果。此后全局时点已改为显式状态查询，T3a / T3b 的旧交互不再适用，当前行为与验证见[状态查询验收](2026-09-09-story-state.md)。

按[作者工作台设计](../web-product-design.md)第 4 节的口径：可视化按"定位问题、比较变化、判断人物知情"的实际操作验收，记录步数、耗时与解释负担，不只评截图。作品是 eval-022《史诗三国》（9 卷 69 Beat，正文 6 篇），在临时副本上操作，真实作品未改动。操作由 Playwright 脚本代替人执行并与作品数据的真值比对；它证明视图能答对、要几步，不能代替作者本人的解释负担判断。

第一次跑脚本时 T3 三项全部超时：T2b 留下未保存的编辑，工作台拒绝切换标签。这是产品的既定行为（人会看到"当前页面尚未保存"提示），脚本补上"撤销本页编辑"后通过。

## 发现

- **F1 已修**：承诺状态写"已在第 47 个 Beat resolve"，作者不认序号。改为点名 Beat："已在 白帝托孤（beat-0045）resolve"，open 处同样点名；时点状态写明时点 id。
- **F2 未修，记入已知缺陷**：r8 是只有 evidence 变化（审稿报告）的版本，版本页却说"与父版本内容相同"。差分只看作品文件，evidence 不在 `workspace.diff` 里。需要 Runtime 投影补"本版本新增 / 失效的 evidence"，再在版本页列出。
- **F3 已修**：人物轨迹的首次出现与死亡只在 hover 里，且不带卷名。页头现在直接写"首次出现 三顾与赤壁 · 髀肉复生（beat-0024）"、"✕ 死于 未竟 · 五丈原秋"，hover 也带卷名。
- 三类问题在当前数据上都能一到四次点击答出；最长的路径是人物知情（设时点 → 身份栏 → 人物），因为时点只能在故事轴或左栏改，人物页里没有时点控件。是否值得在人物页放一个时点选择，等作者用过再定。
- 尚未验收：作者本人的解释负担与误操作；300 Beat 规模的性能；语义解释层是否需要。这些要等作者在自己的作品上用过之后才有依据。
