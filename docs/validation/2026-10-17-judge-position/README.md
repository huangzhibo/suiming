# 评委位置偏差：在已有的留出稿子上换配置重跑（2026-10-17）

[路线图](../../roadmap.md)第 6 节第 3 项「先让评委能用」。[斗破留出](../2026-10-17-doupo-holdout-pipeline/README.md)四次运行的读者口径评委（deepseek-v4-pro，每节 2 轮）里，先出场的候选赢了 141 / 188 轮（75%），大多数节两轮结论相反。这一轮不写新稿，只换评委配置重跑同一批稿子，弄清问题在轮数、思考还是模型，再定评测用的配置。

## 做法

- **稿子**：四次留出（两次不带目标、两次带目标）各 24 节 Agent 稿，加原作对应章节；去掉章标题，前文与样章取自参照作品，与留出时相同。
- **两组对比**：
  - Agent 稿对原作，96 对。
  - 两次运行的 Agent 稿互比，96 对：四组配对（不带目标的两次、带目标的两次、两组交叉各一），每组 24 节。以后改写法要比的是改前改后两版 Agent 稿，这一组才是评委真正的用法。
- **评委**：读者口径，每对 2 轮，两轮顺序相反。评委的模型与思考档位取自每个评委子任务的模型记录，不看配置。
- **构建** `57a3757`（工具参数拒绝信息修复之后）。[judge.py](judge.py) 把参照作品复制一份再跑，原来的评测记录不动；`--versus` 做互比，`--compare` 对照几次运行的逐对结论。

```sh
python3 -I docs/validation/2026-10-17-judge-position/judge.py <输出目录> <配置名> <留出输出目录>... \
  [--versus] [--env 'SUIMING_JUDGE_MODEL_OPTIONS={"maxTokens":32768,"reasoningEffort":"high"}']
python3 -I docs/validation/2026-10-17-judge-position/judge.py <输出目录> --compare <配置名> <配置名>
```

「两种顺序一致」指一对稿子两轮的第一名是同一版，下文叫「明确」；不一致叫「平局」。

## 读法

1. **问题在没开思考，不在轮数。**留出时 `.env` 设了 judge 的模型与参数，按 `user-config.ts` 的规则配置文件里的思考档位就不再生效，评委任务的模型记录是 `thinking: off`，每轮只输出约 280 token。不开思考时先出场的候选赢八成，2 个候选时第 3、4 轮只是同两种顺序再各抽一次，加轮数只会多出平局。开思考后，对原作的 96 对里先出场胜率回到一半，两种顺序几乎全部一致，两个不同的评委模型逐对结论完全相同。
2. **位置偏向在正反顺序平衡时变成平局，不变成错判。**两版稿子差不多时，评委无论偏向哪个位置，正反两轮各选一次就是平局；只有两种顺序都选同一版才算明确。所以真正要量的是明确的结论能不能复现，而不是先出场胜率本身。原定的验收是「先出场胜率在 40%–60% 之间，两种顺序一致的节数过半，全部交出结果」：flash 在互比上先出场胜 36%（偏向后出场），这一条没达到；明确 55 / 96 过半；没有失败。改看复测，见下一条。
3. **定 4 轮，只认各轮一致。**flash 的三次互比各 2 轮。任取两次合成 4 轮，用剩下那次检验：4 轮全一致的 26–33 对里，三种组合都只有 1 对被第三次推翻（约 3%），其余相同或平局；3:1 的 38–40 对里有 4–8 对被推翻（10%–21%）。只跑 2 轮时，「两轮一致」的 51–55 个结论在另一次里被推翻 3–7 个（5%–13%）。所以默认 4 轮，只有 4:0 算明确，3:1 只算倾向；两版相近时大约三成的节能得到明确结论。
4. **Agent 稿对原作没有区分度。**开思考的评委几乎每对都判原作更像这部书接着往下写，理由是节奏、口气与推进密度：Agent 稿更细、更慢、更长，与篇幅是原作 1.9 倍一致；第一次留出的 48 轮理由里有 40 轮提到原作、原书或原著。这一组只能当「离这部书有多远」的粗信号，比两版写法要用互比。
5. **同一配置两次运行的稿子差别本来就小。**互比里大约三分之一的对评委能稳定分出高下，其余是平局。作者盲读如果用同配置两次的稿子，多半读出「差不多」，量不出一致率；路线图第 5 项改用改前改后的两版。
6. **v4-pro 开思考在相近的稿子上又慢又会想过头。**对原作时与 flash 结论完全相同；互比时每对中位约四分钟，一对想到超过 32768 token 被截断（`model_output_truncated`）。日常预筛用 flash。

## 顺带修掉的

- **评委交不出结果**：留出时两次在同一节，这次重跑又有一次，都是 deepseek-v4-pro（不开思考）把整批总评 `summary` 写进 `ranking` 的条目。先把所有工具的参数拒绝信息改成点明顶层与这一层认的字段（`57a3757`），评委第三次删掉了条目里的 `summary`，却忘了在顶层补上。`summary` 没有任何地方读，已从评委的工具参数里删掉。
- **评委结果记下思考档位**：`suim rank` 的结果多了 `judge.thinking`。留出时评委没开思考，结果里只有 provider 与 model，看不出来。
- 这两处改完后在新构建上实跑：flash 开思考、默认 4 轮，一节四轮全判原作，结果带 `judge.thinking: high`；不开思考的 v4-pro 显示 `off`。

## 定下的

- 评委用 deepseek-flash，开思考，读者口径。[holdout.py](../2026-10-17-doupo-holdout-pipeline/holdout.py) 把这套配置写死，不跟本机 `.env` 走；`.env.example` 的示例改成同样的配置并写明原因。v4-pro 开思考结论与它一致，但在相近的稿子上慢五倍、贵五倍还会想过头，不用。
- `suim rank` 默认 4 轮（原来 2 轮）。holdout.py 的汇总按 Agent 赢的轮数分档，只有 4:0 算明确。按这次的用量，flash 每对 4 轮约 1.5–2.5 美分；24 节依次跑，对原作约 20 分钟，两版 Agent 稿互比约 35–40 分钟。
- 改写法之后比改前改后：两次留出各跑完，用 `judge.py --versus --rounds 4` 加上与 holdout.py 相同的三个 `SUIMING_JUDGE_*` 变量比两次的 Agent 稿；Agent 稿对原作那组只当「离这部书有多远」的参考。

## 证据边界

- 这次的评委都是 2 轮，4 轮的可靠性是用两次 2 轮合成后拿第三次检验得来的，还没有直接跑过 4 轮的复测。
- 能用的评委只有 DeepSeek 一家：Qwen Token Plan 下的 qwen3.8-max、qwen3.7-max、glm-5.3、kimi-k2.6 都返回 403 未开通。两个评委模型同源，对原作完全一致不能排除同源的共同偏好。
- 复测证明的是评委自己稳定，不证明它与作者一致；一致率要等作者盲读（路线图第 6 节第 5 项）。
- 前文与样章都是原作，评委对「像不像这部书」的判断有现成的标准；没有原作可比的真实创作里，读者口径的稳定性还没量过。
