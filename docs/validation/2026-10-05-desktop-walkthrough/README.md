# 模拟作者使用桌面：界面与执行循环走查（2026-10-05）

切片 C（边界折叠与边界压缩）刚做完，只有 faux 测试。回归用的样例作品太小，碰不到 10 KB 以上的读取结果。这次在示例三国（9 卷 231 节）的副本上，用真实桌面应用像作者那样操作：读正文、问问题、让 Agent 改写一节并提交、追问、纠正。目的是同时看界面和执行循环在长篇上的表现。

## 做法

- 应用：当天 main 上构建的桌面应用（Electron + `apps/web`），用 Playwright 启动并逐步操作。界面状态靠截图与无障碍树核对，执行状态从执行库的 checkpoint 只读取出。
- 模型：`openai/gpt-6.1-sol`，思考 high，ChatGPT 订阅。
- 作品：`examples/sanguo` 的副本，不改仓库里的示例。

| 作者说的 | Agent 做了什么 | 结果 |

合计 28 次模型调用（含 2 个子任务），未缓存输入约 43 万 token，缓存读约 183 万，输出约 7 千。按 API 价估算 $1.12。

## 执行循环

- **边界折叠第一次在真实模型上触发。**提交 r2 之前，根 Agent 取过一份 86,912 字节（41,012 字）的写作依据。提交之后的那次请求里，它被折成 1,251 字节的头尾与重调方法；消息列表与 checkpoint 一字不改。新一轮开始时，前一轮的读取都在 10 KB 以下，没有可折的，与规则一致。边界压缩没有触发，上下文从未过半。
- **`read_source` 的说明叫所有角色「读完写笔记」，已修。**第三轮作者只问了一句，根 Agent 读了原著，随后照工具说明写了一份 `source/…/notes/华容道.md`。这压过了 `AGENT_PROMPT` 里「只有作者要求执行才修改作品」。turn 结束的对账如实点出「其它改了 1 个文件、还有 1 个未提交」，作者看得见。写笔记的要求本来就在读原文子任务的提示里，工具说明改成只说读。
- **根 Agent 先取写作依据、再委派 writer。**writer 自己会拿到同一份，所以这 4 万字在提交前的每次请求里都是重复的。工具说明已写「委派 writer 时不必先取」，模型没照做。这次的代价由提交后的折叠封顶，先记下，不改。

## 界面

修掉的三处：

- **右栏被程序滚动后输入框浮到中间，下面空出一块。**对话滚动区没有定位，消息里给读屏的「你 / 燧明」标签（绝对定位）以外层为包含块，排到几千像素深，把 `overflow: hidden` 的右栏撑成能被程序滚动。任何 `scrollIntoView` 都会把整栏推上去 387 px，又没有滚动条拉回来。这次是自动化重试悬停时触发的；作者用键盘聚焦或引用消息时同样会撞到。滚动区加了 `relative`，右栏改成 `overflow: clip`，E2E 复现了「↑407」后守住。
- **面包屑被截成两三个字。**工具行中间列写死最多 24%：主工作面约 770 px 时只有 178 px，两侧各空 280 px，「黄巾… / 宦官乱政与黄巾起兵」。改为两侧等宽、中间按需取宽，宽度够时完整且居中。
- **操作列表显示路径。**作者看到的是一列 `outline/story/vol-0009/beat-0440.md`，认不出是哪一节。改为显示作品标题（正文带「· 正文」），路径放进提示。

看过、保留现状的：

- 回车换行、⌘ / Ctrl + Enter 发送：[作者工作台设计](../../web-product-design.md) 4.1「输入器」定的，发送按钮的提示里有快捷键。第一次用时按回车只得到一个换行。
- 「查看版本差异」在没有未提交修改时只说「没有未提交修改」：作者工作台设计 4.3 写明不自动比较上一版本。Agent 已经提交的改动从「查看版本记录」看，那里直接是 r1 → r2 的左右对照。
- 故事轴两侧栏都开着时，231 节放不下，「适应窗口」仍显示按下：列宽有下限，卷级聚合在[可视化设计](../../visualization-design.md)第 7 节排为待做。
- 有一次主工作面在没有点击的情况下从第 1 节跳到了《辞曹不得挂印封金》（标签页历史里多了一步）。按当时的操作顺序重做了两遍，没有复现；可能是驱动脚本的副作用，先记下。

## 第二轮：斗破前 120 章（北京时间 17:50–18:05）

同一天第二轮换成《斗破苍穹》前 120 章的忠实抽取（153 节、37 个人物、没有正文；[分段抽取记录](../2026-10-03-doupo-segmented/README.md)）。用的是副本，连同当时抽取留下的执行数据一起复制，所以对话列表里有那次很长的抽取会话，像作者打开一部用过很久的作品。版权所限，这里只记结构与行为，不写人名、节名和原文。

| 作者说的 | Agent 做了什么 | 结果 |
| --- | --- | --- |
| 主角和导师的关系到目前为止经历了哪几次转折？ | 读 16 次，按先后列出五次转折，每次给节名 | 回答扎实 |

| 继续 | 从原处接着做，两节各提交一次（r4、r5） | 与原文逐句对照：41 / 42 句、58 / 59 句一字不差，差的是把原文的分章标记改成了 Markdown 标题 |

合计 27 次模型调用，未缓存输入约 12 万 token，缓存读约 130 万，输出约 8 千，按 API 价估算 $0.45。

执行循环：

- 折叠又触发了几次：三份写作依据（5,631、8,822、7,748 字）与一段 6,800 码点的原文读取，过了边界都折成了头尾；9 KB 的那段原文读取没到 10 KB，没折。
- 第一次写第一节时整节写成了一段，`write` 返回的「段落 1，平均段长 1424 字」让模型自己发现，随即重写成 30 段。写入结果附段落统计是有用的反馈。
- 选段修改只改一段，Agent 也照提示先取了这一节 7,748 字的写作依据。对小改动偏重，先记下。
- 搬原文的那节没先取写作依据，turn 结束的对账点了出来（「其中 1 个没先读取写作依据」）。这次是照搬，提醒可以不理；它说明对账在起作用。

界面，修掉的三处：

- **作者自己的消息里摊着引用的版本与内容 SHA。**选段修改发出去后，气泡里是一整块「作品引用：text/… / revision: … / contentSHA: …」。发给 Agent 的文本需要这些定位信息，对话里不该给作者看。现在原话照常显示，引用折成「节名 · 正文 · 第 3 段选段」的标签，展开只看被引的文字。
- **人物页的家族关系是三行原始键**（`family.0.kind`、`family.0.character`、`family.0.role`）。现在是一行「家族关系：人名（生父）」，人名可点。
- **选段栏显示 `beat-0009`。**改成作品标题。

看过、先记下的：

- 按「停止」后对话里没有「已停止」的标记，被打断的那一轮也没有结尾对账；只能从「已执行 10 项操作」后面没有回复看出来。
- 人物页出场轨迹上方的说明是「refs.character 表示实质使用……来自 changes」，给作者看的文字里带着字段名。
- 模型回答里把 Beat 设计的正文部分也叫「正文」，在本产品里「正文」专指 StoryText，作者可能误会。
- 切到那个很长的抽取会话只要 0.6 秒，但其中的 Markdown 表格前一两秒是空框，之后才出字。
- 输入框里的引用标签带「· 设计」，发出去之后的标签没有。
- 全屏那条桌面 E2E 在这一轮之后连续失败；在已推送的代码上同样失败，按它自己的说明是本机窗口状态所致，与这批改动无关（下午那轮 19 / 19）。
