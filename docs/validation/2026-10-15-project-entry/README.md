# 作品入口与失败保全（2026-10-15）

## 目标和隔离

正式签名、公证按作者要求暂缓。本轮沿日常使用路径验证新建、打开、取消、误选与移动后重开，不增加发行机制或改变页面设计。

真实 Electron + typed IPC + 本地文件系统，所有作品为公开样例生成的临时副本；配置、凭据与 user-data 由 `launchDesktop` 隔离。只把系统文件选择框替换成确定的选择结果，后续主进程、Runtime 和 renderer 都走生产实现。未调用真实模型，不涉及 Langfuse 或服务商账号；组合恢复用既有 faux 故障，不计真实调用证据。

## 发现与修正

1. “新建作品”界面要求空目录，主进程却在 `create=true` 时绕过非作品目录检查，也可能直接打开已有作品。增加初始化前目录检查，非空即明确拒绝，已有作品提示使用打开入口。普通隐藏文件同样属于内容，只有 Finder 的 `.DS_Store` 不阻塞新建。
2. 最近作品路径移动 / 外置磁盘未连接时，原路径的文件系统错误缺少恢复指引。现在显示失效位置与重新选择说明；非目录、无读取权限分别给出对应提示，不重建原路径，不改变当前作品或最近记录。

先添加两条端到端验收，旧实现均在预期诊断处失败，再修改主进程；没有把失败记为环境问题。沿用原有打开串行队列、草稿存储和 Canon，没有增加持久状态或 Runtime 分支。具体边界记入[工作台设计](../../workbench-design.md#33-导航选择与恢复)及 [ADR-0028](../../adr/0028-macos-preview-delivery.md)。

## 验证

- 真实点击取消打开、新建误选非空目录：原作品、最近记录、正文 buffer、未发送消息不变；重载后两种草稿保留，原正文文件仍未被保存覆盖。
- 非空目录的 `notes.txt` 内容与条目逐项不变，没有 `.suiming` / `.git` / starter 文件；仅隐藏文件和已有作品均拒绝新建。带 `.DS_Store` 的空目录能创建独立作品及初始版本。
- 临时目录真实撤去读取权限后打开失败，恢复权限再清理；错误路径是普通文件时拒绝。两种失败均不改最近作品记录。
- 移动完整目录后启动，欢迎页显示旧位置和恢复入口；取消不修改记录，重新选择新位置后 project ID、Canon 版本和未提交候选保持，重载可继续。
- 正常窗口非空目录错误横幅、960×640 路径失效欢迎页已截图走查：诊断与操作入口可见，既有编辑现场不被错误页替换。
- 新增 2 条与既有跨作品 / 子任务恢复 2 条、启动不兼容恢复 2 条串行 **6 / 6 通过，0 skip**，渲染异常为空。

另外串行补跑 `desktop.test.ts` 基础桌面 **8 / 8 通过，0 skip**，含没有 `.suiming` 的作品就地初始化、typed IPC、SIGKILL 恢复、设置、导航、分栏和悬停提示；本轮合计 **14 / 14**。`npm run build:desktop`、`npm run check` 与文档链接检查通过。没有重跑整个桌面套件或默认全仓单测，上一轮 48 / 48 和 505 通过 / 5 skip 保留原验收归属。

复验文件为 `apps/desktop/test/project-entry.test.ts`、`startup-recovery.test.ts`、`continuous-recovery.test.ts` 和 `desktop.test.ts`；按桌面测试约定构建 renderer / 测试入口后，以 `node --import tsx --test --test-concurrency=1` 串行运行。权限故障验证使用当前 macOS 文件权限，未模拟其他平台行为。
