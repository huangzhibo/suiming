# 桌面真实使用与跨层优化（2026-09-11）

## 范围与方法

先查看真实桌面窗口，再把作品已提交快照复制到独立临时 Project。复制保留 69 个情节、6 篇正文和既有 evidence，测试 Project 从 r1 开始；原作品内容未修改。使用桌面输入框调用当前 DeepSeek V4 Flash，核对 SQLite 执行记录、版本 diff 与本机 Langfuse observation。测试数据与观测不是新的作品权威。

审查覆盖作品阅读与设计切换、对话、提供商设置、执行完成与恢复、父子 Task 交付、作品提交、事件订阅与查询刷新。采用已有导航轨、上下文栏、文档窗格和右侧对话布局；没有另建 Runtime、graph engine、消息协议或模型设置入口。

## 发现与共同修正

| 证据与问题 | 根因 | 已实施修正 |
| --- | --- | --- |
| 原窗口回答“描述当前状态”后显示未提交错误；已有版本被说成没有提交 | 自然语言停下直接结束 loop；模型看不到持久版本事实 | 提交工具声明交付语义；在同一 Attempt 内最多提醒两次，连续三次未交付则暂停。保留明确 finish / submit 校验；显式继续重新进入 ready |
| 独立作品的“几个版本”查询执行 20 项操作后仍无法确认 | 工作树文件和初始 Design 不包含 ProjectRevision 历史 | 起始 Context 与 project_status 共用权威作品状态读取；分开已提交版本、候选计数和未提交改动 |
| 每次流式消息通知都让整个工作台失效 | IPC change 没有区分消息、执行与作品查询 | 合并分类失效提示；stream 只唤醒 attach，execution 只刷新 run.list / tasks / steering，作品变化才刷新目录与内容；执行订阅随 controller 更换与退出释放 |
| UI 按“未知”、credential 等文字判断操作，暂停原因默认隐藏 | 查询丢弃结构化错误；各组件自行推测状态 | 暂停保留已有 ExecutionFailure，命令查询与 AG-UI 扩展共用错误 schema；UI 统一状态与原因映射，原始详情按需展开 |
| 预算耗尽后只有继续，无法从界面提高预算 | Runtime 命令已有能力，作者操作缺失 | 暂停处显示已累计用量与原上限，作者明确调整后调用同一 resume 命令；累计用量不归零 |
| “设计”页显示 12,114 字正文计数与正文绑定状态 | 元信息混用了另一个视图的文件 | 标题和页脚复用码点计数，按当前显示的设计 / 正文内容计数；绑定与正文审稿只在正文视图展示 |
| 审稿条出现 finding / stale / revise，不同表面称呼不一致 | 私有文案与不完整 verdict 映射 | 复用审稿结论映射，补齐 block / insufficient_context，说明依据已变化；去掉执行区私有颜色值 |

完成补全是执行协议恢复，不是把任意模型停下判定为完成。候选、未交付子任务、Checker 和范围验收仍可拒绝 finish。提醒、预算、错误原因和恢复沿用原 checkpoint 与执行状态，不新增持久层。

## 真实模型结果

同一问题：“请简要描述当前作品状态：多少情节、多少篇正文、多少个已提交版本？只说明，不修改。”

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 模型调用 | 10 | 2 |
| 界面显示操作数 | 20 | 2 |
| 已提交版本回答 | 无法确认 | 1 个 |
| 情节 / 正文 / 待写 | 69 / 6；大段搜索报告 | 69 / 6 / 63 |
| 本轮用量 | 187,769 tokens | 28,973 tokens |
| 本轮估算费用 | $0.005053 | $0.002067 |

以上是一次相同作品、相同问题的实测，不是长期质量或普遍性能结论。随后还收紧了简短状态问题的回答风格，并提供人类可读版本标签，避免输出内部 UUID。

第二个真实流程要求只在正文风格 Intent 末尾补充一句要求，独立审稿后提交。结果为 9 次模型调用、一个 Agent 和一个 Review Task，Run 完成，Project 从 r1 推进到 r2。diff 只有指定 Intent 和新审稿所需的 evidence / manifest；指定句子逐字存在，没有改写其他故事文件。Langfuse 读回 34 条 observation，包含真实 generation 与父子 Task 关联。

查询对照：同一 69 情节测试作品上，各执行 15 次查询，workspace.show 中位数约 118.9 ms，run.list 约 2.35 ms；最大值分别约 460.3 / 3.41 ms。这是单机热缓存测量，不能当作启动性能或大规模负载保证。

完整关联 ID、用量、父子任务和 observation 摘要见 [measurements.json](measurements.json)。文件不保存密钥或模型输入输出正文。

## 验证边界

回归覆盖协议补全、提醒上限、同 Attempt 恢复、候选不能自动进入 Canon、更新后的作品状态、结构化原因与错误文字解耦，以及坏作品文件不阻断执行查询。桌面回归覆盖实际 IPC、预算调整、模型设置、导航、编辑、比较、重载与退出。

本轮不是完整长篇质量验收，也未验证真实 OAuth 刷新、Cloud engine host、生产发布和多人协作。后段人工界面验证遇到 Mac 锁屏；相关最终结果必须区分已完成自动化检查与尚未完成的人工复核，不能把截图当作全部验收。


最终检查：`npm run check` 通过；常规测试 321 项，312 通过、9 项因 PostgreSQL / S3 等环境门跳过、0 失败。桌面回归中 16 项通过。分栏与原生全屏组合用例在 Mac 锁屏期间超时，已独立保留为待验收项；16 项的重跑显式排除了该用例，不把排除计为通过。后续人工重验需先解锁 Mac，再单独运行该用例。

恢复操作区的最终布局调整后，连续对话与预算恢复两项 Electron 用例再次通过，`check:web` 与文档链接检查通过。
