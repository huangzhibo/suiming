# 仓库迁移、备份与恢复验收

2026-10-15。范围是本地自含作品仓库，不涉及 Cloud、签名发行或旧执行库转换。方案见[迁移与恢复](../../repository-recovery.md)，取舍见 [ADR-0027](../../adr/0027-repository-recovery-boundaries.md)。

## 发现与修正

现有路径登记已支持搬动目录，无需新增迁移服务。缺口在恢复提示：Canon 丢失时原文案建议移走 SQLite 再 init，容易把重新建仓误当恢复；执行库版本不兼容时只提 SQLite，未说明 objects 和日志也需保存，旧对话不能自动迁入。

先让既有故障验收断言保全提示，在旧文案下复现失败；再修改错误源头。Canon 缺失仍拒绝打开，优先恢复原 `.git` / ref；旧 schema 仍拒绝且不改表，说明完整备份、兼容版本及只续作品的独立副本路径。没有改存储格式、Canon 判定、提交路径或恢复状态机。

新增完整冷备份组合验收：三次 Canon 提交、一个已完成子任务、长历史回复、未提交候选、仓库辅助文件和待发送 inbox；关闭后复制为备份，再换目录恢复。逐版本导出、执行实体、事件、checkpoint 完整解码均一致。旧目录已改名，恢复后仍沿原会话继续，只产生一次新请求，不重跑子任务、不自动提交候选。

## 实际恢复结果

使用[上一轮大材料补全](../2026-10-15-large-source/README.md)的公开三国隔离副本，不接触作者作品。原对话已 idle，验证期间无其他写入进程；本轮没有新增模型调用，也不以 Langfuse 代替执行库。

| 核对项 | 结果 |
| --- | --- |
| 完整目录 | 51,575 份文件逐字节 SHA-256 一致，包含 Git、执行库、对象与作品文件；备份在恢复检查后保持不变 |
| Canon | 7 个版本及各版本全部 artifact 摘要一致，当前 r7、231 个情节 |
| 对话与任务 | 1 份对话、14 个子任务、354 次历史调用的执行实体一致 |
| 事件与恢复点 | 10,366 条事件、13 份存在的 checkpoint 完整解码后一致；任务结果对象可读，attach 投影一致 |
| 独立进程 | 新目录经独立 CLI 进程读回 7 个版本 |
| 普通 clone | 未携带 `refs/suiming/canon`；本样本普通 HEAD 尚未提交，Git 报空仓，符合实际边界 |
| 显式 fetch 与 bundle | 均恢复同一条 7 版本链和逐版本文件；没有旧对话 |
| 作品快照 | 重新初始化只有 1 个版本、0 份对话，文件等于原最新 Canon；不是历史备份 |
| Electron | 隔离配置打开恢复目录，选择原对话、滚动阅读末轮真实回复，再重载；回复全文一致，渲染异常为零，执行实体及 Canon 未变，无新调用 |

桌面首次截图停在历史开头，虽然末轮回复已在 DOM 中，仍不足以目视确认；补上滚动定位后复跑并检查截图，确认恢复的真实回复可读。截图和原始输出仅保存在本机临时目录，未提交消息、执行库或作品副本。

全仓 `npm run check` 通过；`npm test` 共 499 项，494 通过、原有 5 条集成 skip，无失败。旧 schema 和 Canon 缺失两条故障用例与新增组合回归通过。测试中的“沿原会话继续”使用 faux provider，实际长任务副本只读恢复与桌面重载，不冒充新增真实创作。

## 仍未覆盖的边界

本次验证同版本、停止写入后的自含目录复制，以及 Canon 历史的原生 Git 传递。未验证旧执行 schema 自动转换、安装包升级、热备份、linked worktree / 外置 Git 对象目录或全局凭据迁移。旧 schema 用例确认拒绝且不改表，不等于支持转换；兼容版本读取旧对话仍取决于该版本及完整备份可用。正式交付任务保留在[路线图](../../roadmap.md#6-立即执行队列)。

## 重跑

先构建，在隔离作品没有其他进程写入时指定 `SUIMING_VALIDATION_SOURCE`，并指定一个不存在的仓库外 `SUIMING_VALIDATION_ROOT`：

```sh
node --import tsx docs/validation/2026-10-15-repository-recovery/probe.mts
```

[脚本](probe.mts)复用现有 Runtime / CLI 与系统 Git，不发模型请求；对冷备份逐文件核验，然后检查复制换目录、独立 CLI 查询、普通 clone 缺失 Canon、显式 fetch、bundle 和快照导出的不同保留范围。副本与 result.json 留在仓库外，不提交执行库、原始消息或作品副本。

桌面部分使用[独立脚本](desktop.mts)，复用现有 E2E 启动器和隔离凭据。先按桌面测试命令准备 renderer 与测试入口构建，再将 `SUIMING_VALIDATION_RESTORED` 指向上述 `restored` 副本：

```sh
node --import tsx docs/validation/2026-10-15-repository-recovery/desktop.mts
```

该桌面脚本按本次三国数据的末轮回复定位；更换作品时应调整该断言，不能据此声称任意数据都已验收。
