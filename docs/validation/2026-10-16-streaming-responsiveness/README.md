# 长对话流式响应验收（2026-10-16）

## 范围与方法

本轮验证长对话持续输出时的输入、动作展开、停止和重连。所有 Electron 进程经 `launchDesktop` 使用临时作品、独立 user-data、配置和凭据；不接触日常作品、不刷新作者窗口、不调用真实模型，不向 Langfuse 写入合成记录。

使用公开测试作品，向执行事件日志写入合成规模历史：120 组作者与 Agent 消息，共 240 条、1,320 个已完成读取动作。历史用于 renderer 压力，并非真实模型产生的连续消息 checkpoint。新一轮则通过实际 Harness、测试提供商、SQLite、IPC、AG-UI 和 Streamdown 执行一次真实文件读取并持续流入文字。测试提供商设为每秒 120 token、每块 32 字符；其 token 换算约为每秒 480 字符，实际显示受事件合批影响。回复预留足够长度，由测试点击停止收尾，不以短回复结束时间与停止操作赛跑。

覆盖 1460 × 940 侧栏、同尺寸主工作面、960 × 740 窄窗。主工作面等当前回复累积超过 1.2 万字符再操作，另外两种形态在输出初期操作。输入为 44 个 ASCII 字符、逐键间隔 30ms，断线时再输入 17 个字符；记录 `beforeinput` 到下一次 `requestAnimationFrame`，这不包含系统按键进入 renderer 前的排队，也不等于屏幕呈现时间。整体输入、动作展开、重连、重载和停止时间从 Playwright 发起操作开始计时，包含自动等待和 IPC。另用 50ms 定时器采样 renderer 事件循环的额外延迟。

测量串行运行，不与构建或其他测试争用资源。机器为 macOS 26.6.2 / arm64，启动测试的 Node 为 26.5.0，Electron 44.6.0。数值是本机观测，不是跨机器的性能承诺。

`npm run test:desktop` 会构建并运行全部桌面验收。已有最新构建时，可单独运行 `node --import tsx --test apps/desktop/test/streaming-responsiveness.test.ts`；设置 `SUIMING_CAPTURE_DIR` 为临时输出目录即可保存逐次测量和截图。侧栏基线来自本轮修改前的 `4f0922b`，最终实现使用相同 fixture 与测量方式。

## 发现与修正

1. 流式更新和输入都会重新渲染未变化的历史消息；AG-UI 还会复制消息对象，直接比较消息对象身份无法跳过。消息行改为按实际显示的标量与作品链接比较，复用 React 的 memo；点击回调保持最新，作品标题改变时仍会更新。
2. 每个片段都会拼接整份导出文本、更新父窗格。现在仅在点击导出时从当前消息生成全文，父窗格只持有当前对话的读取入口。验收逐字核对导出包含停止前的最新回复。
3. 文字已由 `useConversation` 按帧更新，动作视图又为同一文字事件调度刷新。动作视图现在只对自己持有的动作和轮末对账更新。
4. 当前回复较长时，Markdown 的链接组件函数逐片段重建，使 Streamdown 对已完成段落的缓存失效。固定同一份链接映射的组件配置，继续使用上游分块缓存；没有增加另一份 Markdown 解析、事件归并或持久数据。

动作详情仍按需查询，memo 只跳过参数未变的父级重绘；查询完成、失败或动作状态变化仍由原有 Query 更新。未引入虚拟列表、第二份消息状态或新的重连机制，也未改变页面布局。

完整桌面回归首次为 71 / 72：多文件草稿用例切换作品后，紧接着按下的 ⌘T 被吞掉。定位到快捷键守卫把退场动画中已关闭的弹层仍视为打开；在键盘回归中延长真实弹层退场动画，稳定复现失败。守卫改为排除 `data-closed`，继续阻止打开弹层中的快捷键穿透，不增加延迟等待或焦点恢复机制。

第二次完整回归也为 71 / 72，键盘与多文件恢复均通过，模型选择用例则在重载后的模型目录尚未返回时，把已恢复的 ID `second` 与显示名称“测试模型 B”立即比较而误报。改为等待异步名称解析，并检查高思考强度；后续实际模型调用的断言保留，没有把错误选择当作成功，也没有增加固定等待或改动产品绑定行为。

## 正确性与交互

回归位于 `apps/desktop/test/streaming-responsiveness.test.ts`，三种窗口形态均执行：

- 持续输出时向上阅读，展开本轮真实读取动作；输入过程中输出继续增长、动作保持展开、阅读位置不被拉回底部，输入焦点不丢失。
- 仅令 `session.attach` 失败，执行继续。断线期间可以输入，解除故障后沿原游标补读；随后重载 renderer，历史、半截回复和未发送草稿仍保留。
- 重连和重载后仍只有本轮两次模型请求（读取与回复），消息数量不增生；停止后用持久快照逐字核对 UI 内容，除排版空白外不缺字、不重复片段。
- 窄窗在再次断线时点击停止，直接核对主进程已回 idle；重连后再核对停止摘要和文本。命令不依赖 attach 的成功，状态摘要仍按既有重连节奏补齐。
- 导出包含历史末条与最新回复，停止不清除草稿，再发一句仍接着同一对话。

## 测量与验收结果

逐次数据见 [measurements.json](measurements.json)。同一侧栏场景，改前 / 最终实现各三次独立启动：

| 指标 | 改前 | 最终实现 |
| --- | --- | --- |
| 输入到下一帧 P95 | 39.5–41.5ms | 9.8–11.5ms |
| 单次输入最大值 | 42.5–63.4ms | 10.5–16.9ms |
| 连续输入 44 字符（含每键 30ms 间隔） | 3,212–3,345ms | 1,844–1,903ms |
| 采样期事件循环额外延迟最大值 | 80–102ms | 12–14ms |
| 展开本轮动作至结果可见 | 165–205ms | 79–91ms |
| 重载至当前回复可见 | 520–640ms | 527–651ms |
| 点击停止至停止摘要可见 | 295–564ms | 266–443ms |

重连没有改策略：既有失败重试间隔为 1.5 秒。解除故障至恢复显示改前为 343–401ms，最终为 851–861ms；输入更快后，解除故障落在重试周期的不同位置，这一项不应解读成吞吐优化或退化。窄窗再次断线时停止，主进程约 155ms 回到 idle，摘要在恢复读取后约 1.48 秒可见。原有停止与只读补读边界保持有效。

第二轮迭代专门看长回复：仅做历史行优化后，当前回复约 1.46 万字符时，事件循环采样最大延迟 64ms，单次输入最大 61ms。稳定 Markdown 组件配置后，两轮约 29 秒持续输出、1.43 万字符的复测中，事件循环最大延迟为 20 / 29ms，单次输入最大为 13 / 15ms。不是消除了所有耗时，而是去掉了每个片段重复处理已完成段落的工作。

主工作面和窄窗都核对无横向溢出；重载后再次展开动作的截图见[主工作面](expanded-action.png)、[窄窗](narrow-action.png)。截图中的历史为合成测试文字，不是文学质量样章。

最终 `npm run check` 通过；`npm test` 为 479 / 479、0 skip。键盘与多文件草稿定向 8 / 8、模型选择定向 1 / 1 通过；修正后用同一构建串行运行完整桌面套件，72 / 72、0 skip、0 fail，含 macOS 原生全屏。新增 3 条流式组合回归，其他测试没有删除；此前两轮失败及其原因如上保留。

## 证据边界

这是合成长历史与受控提供商的真实桌面交互验收，不是文学质量、真实网络提供商故障、完整 checkpoint 恢复或数小时持续运行验收。真实 1,314 动作历史的加载证据仍见[此前记录](../2026-10-14-version-and-conversation/README.md)。本轮没有替换 AG-UI reducer，也没有降低已有草稿或 Canon 保全规则。
