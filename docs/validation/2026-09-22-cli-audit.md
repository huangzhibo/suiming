## 已复现问题

### 1. 刷新 Codex 接入会删除作者的模型配置

优先级：P1。

复现：安装 Codex 接入，在 `.codex/agents/suim_candidate.toml` 增加有效的 `model = "custom-author-model"` 配置，再执行 `suim host install codex`。命令成功，但该配置被删除。

[Codex 接入说明](../../integrations/codex/README.md)明确让作者自行补充 `model` 和 `model_reasoning_effort`；[安装实现](../../apps/cli/src/host-install.ts)却逐个整体覆盖 `.codex/agents/*.toml`。现有测试只检查了 `AGENTS.md` 和 `.gitignore` 标记段之外的内容保留，没有检查 agent 配置保留。

修复边界：明确接入器管理的角色字段与作者配置字段；刷新角色指示时保留作者模型设置。新 `update` 命令若复用当前实现，也会继承这个问题。

### 2. `init` 返回失败，但作品目录已经变化

优先级：P2。

复现 A：

```sh
suim init /tmp/example-book
# 准备一份非空的创作意图文件后执行：
suim --project /tmp/example-book init --intent-file /tmp/example-intent.md
```

第二条命令返回 `local_project_already_initialized` / exit 4，但此前不存在的 `intent/book.md` 已被写入，作品从 clean 变成 dirty。

复现 B：在未初始化目录放入无效的 `world/characters/bad.md`，执行 `init`。命令返回 `invalid_document` / exit 3，却留下新建的 `outline/story/index.yaml`。

原因：[CLI 的 init](../../apps/cli/src/cli.ts)先执行 scaffold，再调用 `LocalProjectService.init`，没有在失败时撤回本次新增文件。[桌面打开路径](../../apps/desktop/src/main.ts)已有失败后撤回 scaffold 文件的处理，CLI 未复用同一边界。

修复边界：已初始化等可预判条件应在写入前检查；失败时仅撤回本次创建的文件，保留原有作品与作者修改。不能通过把失败改报成功掩盖副作用。

### 3. 使用文档和安装后的指示仍推荐已删除的能力

优先级：P2。

- [README](../../README.md)仍称 `suim run` 启动自有 Agent、无子命令进入 TUI；当前 `run` 是未知命令，无子命令只显示帮助。
- [共享 Skill](../../integrations/shared/suiming/SKILL.md)的 Write Context 说明仍出现 `suim run write`，同样会被安装进作品仓。
- [接入安装器](../../apps/cli/src/host-install.ts)写入 `AGENTS.md` 的标记段仍要求 evidence 记录和禁止修改 `evidence/**`，而当前审稿与材料笔记已经是普通作品文件。
- [集成入口文档](../../integrations/README.md)仍用 `suim run` 解释模型凭据的切换。

这些问题在 `npm run check` 全部通过时仍存在：现有检查验证命令片段是否出现、生成文件是否同步，但不会识别额外残留的旧命令。

修复边界：同步 README、host 指示及其生成产物到 `session send` 和当前审稿 / 笔记语义；历史验收记录中的旧命令保留原意，不做全仓机械替换。

## 命令设计与行为差异

以下是待收敛的产品接口，不冒充已完成的修改：

- 当前没有 `suim update`，运行返回 `invalid_cli_usage` / exit 2。前面对话提出的 `init` 开工、`update` 维护、删除 `host` 命令组仍是建议。
- `--project-id` 仍在 `init --help` 暴露；它覆盖自动生成的内部 ID，没有必要成为普通作者的开工步骤。
- `host install` 可以在未初始化的普通目录成功安装文件，但紧接着 `open` 返回 `local_project_not_initialized`。需要在新的命令面明确补接和初始化的前置关系。
- `init` 会把含普通 `notes.txt` 的非空目录直接初始化成作品；桌面的“打开”会拒绝没有作品文件的非空目录。这是两入口的行为差异，需要明确 `init` 是否允许“把现有普通目录变成作品”，并让帮助说明与选择保持一致。
- `-V` 当前输出 `0.0.0` 与 package version 一致，不属于运行故障；若需要区分开发构建，应另行确定版本标识方式，而不是随意把版本改大。
