# 斗破忠实抽取重跑：补齐方法之后（2026-10-03）

2026-10-02 桌面 Agent 用 GPT-6.1 Sol 抽了一遍斗破前 120 章，作者看故事轴发现英文 Contract id、标题带章节括注、一整卷；对照 [host 版](../2026-10-02-doupo-host/README.md)又查出 Beat 速记、零个秘密、零条 `refs.beat` 等。10-03 上午按审查清单补齐（见[当前状态](../../current-status.md)同日变更记录），这次用同一份材料、同一句作者消息重跑，看补的东西是否生效、还剩什么。

## 做法

- 作品：`doupo-agent-gpt-2026-10-03`，与前两份同一份 Source（sha `1735ab9c…`，307,785 码点），意图文件同 10-02。
- 模型：`openai/gpt-6.1-sol`，思考 high，ChatGPT 订阅；所有子任务同一模型。
- 作者消息与 10-02 那次逐字相同：读原作写笔记 → 抽取 → 独立审稿 source 层并按意见修 → 原样提升为 Target → 检查并提交，回复里列每节对应原作章节。
- 用 `suim --json session send --events` 从 CLI 跑，事件流存在会话 scratchpad，不入库。

- **10-03 上午补的都生效了**：分卷、中文 id、标题、因果依赖、秘密声明、World 只写设定、出处不进作品、并行阅读。
- **审稿查得出实在的错**：父子关系写反、雅妃知情越界、药老重生条件与骨中卷轴用途的 `revealed` 投影比原文确证得多、量词与行动归属改写、World 把萧炎当前能力写成通则、人物档预载后文事件。
- **Beat 偏短、偏速记**：初稿中位数 185 字，「同龄人畏八段无人上，宁骂胆小，玉拦同级未必胜」这种电报体，萧宁、萧玉缩成单字；自检时改顺了大半，但篇幅只有 host 版的八分之一。10-02 那次也是这种写法，根 Agent 写给子任务的 goal 同样是压缩体——这是这个模型的倾向，方法里一句「用完整的句子」压不住。
- **粒度**：115 节，平均一章一节，host 版约四章一节。Story Language 只给软粒度建议，这次不判对错，留给续写评测看哪种粒度让 Writer 写得更接近原作。
