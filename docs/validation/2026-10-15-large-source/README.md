# 大材料补全、跨卷关联与恢复

2026-10-15。接续 [Harness 通用机制对齐](../2026-10-15-harness-alignment/README.md)，使用公开三国样例的隔离副本；原样例与作者作品不改，执行库、trace payload 与模型原始回复不入仓。

## 范围与验证办法

材料为前五十回、249,272 码点，已有 9 卷 231 个情节。公开样例曾把抽取提升为 Target 并移除了重复 Source Design；此次将其 outline / world 复制回 Source，仅作为已有抽取的验证起点，不记为本轮重新抽取的成果。

先检查两个小范围，始终保留完整大材料供跨卷回读：

- 第二十五回的原文 `[123150,128193)`，补全 `beat-0223–0224`。
- 第五十回的原文 `[245323,249272)`，补全 `beat-0439–0440`。
- 在副本中移除华容放曹的早期跨卷引用，仅保留本卷最近依据，检查真实模型能否查回因果关系。
- 缩短一份已有笔记，制造 `[47500,48181)` 的 681 码点缺口；加入覆盖同一区间、sha 已失效的笔记，检查它不会抵消缺口。
- 在补全子任务确认一次写入后，通过正常停止信号打断；进程结束后重新打开同一作品、同一 Session，沿原任务续做。此项验证正常停止后重开，不冒充 SIGKILL。
- 对 Target 的完整路径集与每份文件的 SHA 做前后对比，检查抽取没有修改本作。

## 发现与修复

检查覆盖对账到审稿输入的路径时发现：`renderSourceNotes` 只按笔记 local id 找正文。两份材料都有 `notes/1.md` 时，覆盖率和展示路径属于第二份材料，正文却可能来自第一份。

先加回归，旧实现实际输出「续作路径 + 前作事实」；改为按覆盖对账已经返回的完整 `note.path` 查找，不增加新索引或状态。Source 审稿与 host 合并 Context 继续共用这一处。相关 Source / host / 规模测试 35 / 35，派生状态与恢复测试 16 / 16，`npm run check` 通过；全仓测试 498 项，493 通过、原有 5 条外部服务集成按条件 skip。

## 小范围真实恢复结果

两个原 source-extractor 均从原 taskId 续做并完成，没有另建替代任务；已完成的 source-reader 不重跑。停止前写入的候选保留，恢复后统一检查，提交为副本 r2；初始 r1 保留，未因恢复重复提交。全书 Target 的完整文件集和每份内容 SHA 均未改变。

本轮修改 11 个 Source 文件：四个指定情节、三个笔记，以及由根 Agent 核实处理的两个号段外情节、关羽档和余恩期待。华容放曹恢复了来自早期卷的依据，关羽归刘与余恩报曹分别处理；华容军令状、周瑜谋害孔明、曹仁守郡密计仍在材料边界保持开放，没有为了检查通过而编造结局。

原文覆盖从两个区间变为 `[0,249272)`，失效笔记仍不计入；新 Reader 笔记记录当前 sha 和缺失范围，执行记录确认它确实调用了 `read_source`，不是只改覆盖数字。Source Checker 通过，既有引用提醒不等于错误，也没有要求为了清空提醒扩大修改。

两轮共 52 次真实模型调用（包含一次受控停止的 aborted 响应），停止前 28 次、恢复后增加 24 次。两个补全任务首个请求约 58 KB，分别只预载 3,511 / 3,495 字节的指定情节内容；后续按需读取会让请求增长，最大约 446 KB。未发生摘要空转。52 个 model_call_id 与 Langfuse 全部匹配，费用估算 $1.435192 一致；整轮 observation 分别为 stopped / completed，受控中断调用标记 aborted。此处对齐的是两边的同一估算口径，不是服务商账单。

## 扩大到完整末段

沿同一 Session 再补全原末段 `[197346,249272)`，共 51,926 码点、跨两卷 41 个情节。子任务用五次连续 `read_source` 读完原段，再向前跨卷回读十个区间；开场预载 25 份情节，其余 16 份全部在执行记录中找到成功读取，未把文件路径提示当作已读。

| 扩展轮调用 | 根 Agent 8 次、子任务 24 次，共新增 32 次真实调用 |
| 输入规模 | 子任务首请求 105,588 字节，最大 619,737 字节；无摘要调用，未触发开场过大拒绝 |

| 内容纠错 | 蒋干询问庞统身份不再写成「认出」；连船数量写清每排三十或五十只；粮船识别依据恢复为粮重船稳、来船轻浮；孔明归期不提前明示祭风 |

对照原文抽查上述语义修正，均有出处。检查通过仍带既有引用提醒；没有为了清空提醒改动 Target 或重写全书。

三轮合计 84 次模型调用，与 Langfuse 的 84 个唯一 model_call_id 全部对应；460 条 observation 的来源为 validation，整轮结果为 stopped / completed / completed，总估算 $2.6484052 与执行库一致。错误观测分别对应受控中断、一次读错卷路径和一次越权写入：读错后模型找回正确文件，越权写入交由根 Agent 处理，没有未处理失败。前两者的恢复与最终成功没有抹掉原错误记录。

## 验收边界

这次证明了大材料中的按范围补全、跨卷回读、覆盖缺口修补与正常停止后跨进程沿原任务恢复；原段从小范围扩大到 41 节，仍能完成。覆盖率来自当前材料 sha 下笔记区间的并集，不代表所有 231 节都在本轮复核过，更不代表语义完整性。指定补全范围合计 43 个不重复情节，另有根 Agent 核实的范围外修正；剩余原文分段与全 Source 独立审稿尚未完成。

本轮没有摘要发生，因此不能把「未发生摘要空转」写成「大材料摘要后要求完整保留」。正常停止也不替代强杀恢复证据。没有因这次成功增加执行层、覆盖状态或权限例外；唯一产品代码变化是材料笔记按完整路径隔离。

## 重跑

[验证脚本](probe.mts) 只从公开样例创建全新的仓库外副本。先构建，设置 `SUIMING_VALIDATION_ROOT` 为一个不存在的仓库外目录，再依次运行：

```sh
node --env-file=.env --import tsx docs/validation/2026-10-15-large-source/probe.mts prepare
node --env-file=.env --import tsx docs/validation/2026-10-15-large-source/probe.mts stop
node --env-file=.env --import tsx docs/validation/2026-10-15-large-source/probe.mts resume
node --env-file=.env --import tsx docs/validation/2026-10-15-large-source/probe.mts expand
node --env-file=.env --import tsx docs/validation/2026-10-15-large-source/probe.mts inspect
node docs/validation/2026-10-15-large-source/verify.mjs "${SUIMING_VALIDATION_ROOT}.validation.json"
```

`expand` 把范围扩大到原末段的 41 个情节。`inspect` 只导出当前执行与作品结果，不发起模型调用。[离线核对脚本](verify.mjs) 按工具实际返回的区间核对原文读取，并核对预载以外的情节文件有没有实际读取；可再传入 Langfuse CLI 的 observations JSON 文件，核对所有调用编号与用量。验证显式开启观测内容采集，仅用于这个公开隔离副本，产品默认仍关闭。结果 JSON 留在副本旁边；Langfuse 通过 observations API 按 session / task / model_call_id 对账。
