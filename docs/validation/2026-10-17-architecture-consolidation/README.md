## 一、草稿恢复

- 先新增故障测试，原实现因“读取失败没有抛错”失败，证明它会返回默认布局并覆盖原记录。
- 区分无记录与恢复失败；文件草稿基线、消息、附件与待确认提交独立于可归一化的布局校验。错误记录不被丢弃，原始存储保持不动。
- 恢复失败时不挂载可编辑工作面、不建立该作品的持久化入口；提供重试和打开其他作品，不新增横幅或默认覆盖动作。

结果：`npm run check` 通过；工作台单测 76 / 76；真实 Electron 多文件恢复 3 / 3、外部文件与键盘组合 17 / 17，均 0 skip。查看 960 × 640 的恢复页面截图，提示和两个动作完整可达；修复后重试恢复原正文、未发送消息和焦点，切换其他作品不覆盖损坏记录。

测试迭代：首次损坏注入放在重载之前，被应用正常的退出保存覆盖，改到新页面启动、应用读取之前；第二次断言在窄窗寻找已收起侧栏里的作品切换按钮超时，恢复常规窗口后验证该入口。保留失败过程，不将两次测试修正当作产品缺陷。
