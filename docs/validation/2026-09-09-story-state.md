# 2026-09-09 状态查询验收

把隐式全局时点改为作者主动发起的状态查询，设计边界见[可视化设计](../visualization-design.md)。验证使用临时 2 Beat 作品；未改动真实作品，也未使用付费模型。它验证状态语义与操作闭环，不证明长篇质量或作者实际使用收益。

## Runtime

[状态查询测试](../../packages/runtime/test/story-state-context.test.ts)核对：

- 进入前排除本幕变化；结束后包含本幕变化；本幕变化展示两端差异。
- 人物在第一幕知情、读者在第二幕知情，两个范围分别显示；未声明不会解释成不知道。
- 密信在第二幕消耗后，持有者由李牧变为“无”；复用 StateTimeline 的隐含清空规则。
- 承诺在首幕进入前尚未开启、首幕后待兑现、第二幕后已兑现。
- 人物与资源主体筛选、host 与桌面同一查询结果、错误 Beat / 主体 / 任务的拒绝。
- dirty 文件不影响查询；推进 head 后，指定旧 revision 仍返回原结果。

## Electron

[桌面测试](../../apps/desktop/test/desktop.test.ts)的状态查询用例通过真实 typed IPC 验证：

1. 故事轴选择第一幕或第二幕，李牧引用数始终为全书 2 Beat。
2. 第二幕进入前显示持有密信，本幕变化显示持有者清空，结束后显示已消耗。
3. 点击状态行的来源链接打开原文；前进后退、新标签与重载后，查询仍为第二幕结束后。
4. 查询、重载与准备引用均不创建 Run；Beat 页可直接发起新查询，人物页可限定主体。
5. 已准备的引用不受后续浏览和查询影响；退出查询后发送目标，持久 Run 的 goal 包含原 Beat、after 边界、实际 revision 和密信已消耗的结果。

已检查结束后状态与人物查询两张 Electron 截图，控件、来源链接与结果均可见。Markdown 渲染另以中文、空格、`#`、括号文件名核对来源路径；只允许调用方列出的作品链接，不开启外部导航。
