# 斗破留出续写全流程：第二卷整卷留出（2026-10-17）

可用性阶段按[路线图](../../roadmap.md)第 6 节的出口结束后的第一项：让留出评测的整条流程在当前构建上跑完，中间不需要人插手。作者要求这一轮不碰文字细节，所以下面的篇幅、评委名次只记录，不据此改写法。

## 做法

- **作品**：2026-10-03 新流程的 [120 章抽取](../2026-10-03-doupo-segmented/README.md)（153 节、两卷）。它的 Design 在当前 Checker 下仍然通过，旧对话也能读；每节对应原作哪几章，取自那次 Agent 回复里的对应表。
- **留出**：第二卷「山脉历练」整卷，beat-0501–0524，对应原作第 107–120 章（去空白 49,800 字）。第 106 章以前的 129 节放原作正文，`source/` 去掉。
- **一条命令**：[holdout.py](holdout.py) 依次搭作品（用 [build_eval_work.py](../2026-10-03-doupo-agent-gpt/build_eval_work.py)，风格意图按留出点改两句）、发作者消息、算指标（[compare.py](../2026-10-02-doupo-holdout/compare.py)）、跑读者口径评委（每节 Agent 一版对原作一版，去掉章标题，2 轮）。能续跑；没写完只允许替作者说「继续」，最多两次，说过几次照实记下。
- **作者消息**：「按设计写 beat-0501 到 beat-0524 共 24 节的正文，接着前面的原作往下写，语气、节奏和人物说话方式与前文一致。写完独立审稿，按意见修，检查并提交。」
- **模型**：根 Agent 与子任务 `openai/gpt-6.1-sol`（思考 high，ChatGPT 订阅）；评委 `deepseek-v4-pro`。
- 同一套输入独立跑了两次，看流程能不能重复。两次之间只多了一个观测修复（见下）。

```sh
python3 -I docs/validation/2026-10-17-doupo-holdout-pipeline/holdout.py \
  ~/stories/doupo-agent-gpt-2026-10-03c ~/stories/doupo-agent-gpt-2026-10-03c.reply.md \
  ~/stories/doupo-holdout120-2026-10-17 --holdout-from 107
```

作品与原文在作者本机，不进仓库。跑之前先构建；跑的过程中不要重建 dist，脚本每一步核对指纹。

## 流程里看到的

1. **整卷审稿被开场预检拒绝，Agent 自己拆小**。两次都先派一个审 24 节的 Reviewer，预检估计 209,833 / 213,613 token，超过当前模型预留后的 190,400，返回 `delegation_too_large`，没有发请求。根 Agent 随后拆成 12 + 12（第一次）或 8 + 8 + 8（第二次）重审。这是设计内的路径，没有白花调用。
2. **第二次改了一节抽自原作的 Design**。审稿认为萧炎从四星到五星没有交代，根 Agent 把 beat-0521 里的「正在从五星斗者向六星迈进」改成「四星、尚未突破五星」，并在回复里写明「同步修正了情节设计」。原作第 119 章写的就是五星向六星迈进，突破发生在幕后；意图写明前 120 章照原作建模、不改设定。改动对作者可见（回复与 turn 结束对账都列了 Design 改动），不是静默失败；但它破坏了留出评测「两边按同一份 Design 写」的前提，脚本现在把这类改动单列在结果里。
3. **第二次的最后一轮修改没有再审**。复审仍是 revise，Agent 修完就检查提交；作者消息只要求审稿、按意见修，没要求审到通过。回复说「按意见修订并复审」属实，但没说复审后的修改没有再审；`suim status` 显示 5 份审稿全部过时，作者打开能看到。
4. **Reviewer 读不到范围外的邻节**：两次共 7 次 `permission_denied`，都是 Reviewer 想看审稿范围之外的相邻正文查衔接。这是有意的：审稿时效按 subjects 的内容摘要判断（[派生状态设计](../../derived-evidence-design.md)），读了范围外的文件，结论就依赖一份没登记的内容。这次不改。
5. 其余工具报错都是预期内的：writer 写之前先读一下自己的目标文件（不存在，各 6 次）、根 Agent 找已经去掉的 `source/`、一次越过文件末尾的读取范围。第二次有 2 次模型调用以 error 结束，turn 照常完成。

## 搭流程时修掉的

- 120 章那次回复把章内开头句放在章号后面一列，`build_eval_work.py` 原来只认引号块；有一格写成「场景标签：……随后是：……」，回退为取引号里在本章恰好出现一次的片段，其余情况仍然报错。
- 脚本读 `.env` 时没去掉引号，带引号的 `LANGFUSE_BASE_URL` 进了环境变量，`session send` 整轮报 `internal_error`。脚本修了；产品那半边也是缺陷——观测不是模型调用的前置条件，地址无效时现在只关掉观测、打一条 `langfuse_base_url_invalid` 诊断（`3b46f45`）。
- 作品仓的 main 分支没有提交，`git status` 会把整个目录算成未跟踪；未提交改动与过时审稿改读 `suim status`。
- 续跑出汇总时原来报的是续跑那一刻的 dist；现在第一轮开始前把构建身份写进 `logs/build.json`，dist 变了且没写完时拒绝续跑。

## 只记录、这一轮不处理的

- **篇幅**：合计是原作的 1.87 / 1.92 倍，每节 1.08–3.56 倍。10-03 前 24 章的留出是 1.24 倍。属于写法，排在流程跑稳之后。
- **评委位置偏差**：读者口径每节 2 轮，两轮名次互换（平均名次持平）的节数第一次 12 / 24、第二次 20 / 24；不持平的节里原作 9 : Agent 3、原作 4 : Agent 0。2 轮时大多数节的结论只是候选顺序决定的，做一致率之前要先定评委轮数。
- **没有背书**：两次的 13 字片段重合最高 0.1%，最长原样重合 16 / 18 字。
- **章号**：Agent 一节一章，把 24 节编成第 107–130 章（原作是 14 章）；评委比较前去掉了标题。

## 证据边界

- 走的是 CLI，不是桌面窗口；同一个 Runtime 与 Agent。
- 两次都是一个完整 turn，没有中断与续做；Langfuse 上全部调用都是执行调用，摘要没有触发。
- 评委与指标不说明文学质量；作者没有读这些稿子。
