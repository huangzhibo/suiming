# 作品可视化设计

视图编码与边界以本文为准。状态：第 7 节第 1–4 步已于 2026-09-09 实现，第 5 步卷级聚合待做；完成度见[当前状态](current-status.md)。

本文从[桌面 UI / UX 与可视化重审](history/desktop-ux-rethink.md)第 4 节的 48 个作者视角里，挑出**数据已经就绪**的那一部分，收敛成一套可实现的视图，遵守 1.1 的事实边界。实现前的[故事轴原型](design/2026-09-09-story-axis/story-axis.html)用 eval-022 的真实结构数据（只有标题、引用与锚点，不含正文）做成，是当时的设计稿。

下文的「承诺」即 StoryContract，作者界面显示为「读者期待」，用语规则见[作者工作台设计](web-product-design.md) 7.2。

## 1. 可视化要替作者回答什么

长篇作者在工作台里反复问的是下面这些问题，它们决定视图，而不是反过来：

| 问题 | 视角编号 | 数据现在在哪 |
| --- | --- | --- |
| 全书怎样组织，哪一段还缺正文、哪一段 Design 变了正文没跟上、哪里有未处理的审稿 | B1、F3 | index.yaml、`storyText`、`workspace.reviews` |
| 一条承诺何时建立、推进了几次、有没有在期限前兑现，兑现之后还有没有被"推进" | D5 | `contracts.open / advance / resolve`、`deadline` |
| 后果依赖哪些更早的选择，哪些依赖跨得太远 | B4 | `refs.beat` |
| 一个人物出现在哪些 Beat、什么时候死、哪些秘密对他揭示了 | C2、C5、D4 | `refs.character`、`changes.world.<人>.dead / location`、`changes.character.<人>.secret:<x>.revealed` |
| 主线、人物线、承诺线在哪里交汇，哪一卷谁缺席 | B3 | 同上，按 Beat 顺序叠放 |
| 一件东西到了谁手里 | D3 | `initial.holder`、`changes.*.holder / location` |
| 改一个 Beat 或设定会牵连什么 | F5 | 反向链接（`deriveLinks`） |

以 eval-022 为例，这些字段的真实用量是：69 个 Beat 全部有 `refs.character / refs.world`，25 个 Beat 有 `refs.beat`（72 条边），承诺锚点 6 open / 63 advance / 5 resolve，`changes` 记录了 18 次死亡、3 次位置变化和 3 次秘密揭示。这就是可视化的原料，不需要为了画图再让作者填字段。

### 1.1 事实边界

每个可视化都标明当前作品、对象或选区、阅读范围和版本。涉及时点的视图要标出是「进入这个 Beat 前」还是「这个 Beat 之后」，并分清叙述顺序、故事世界时间和运行时间；只有相关视图才显示这些控件，不加全宽的参数栏。

视图上的数据分三类，各自标注，不能混画：

- **确定性投影**：作品中记录的顺序、引用、硬状态、承诺锚点、版本与实际输入。它准确表达「记录了什么」，不证明文学质量，也不代表完整的世界真相。故事轴与邻域图只画这一类。
- **语义解释**：人物动机、情感关系、读者体验、节奏、没有明写的因果。由模型结合原文分析，必须标注来源、适用版本、不确定性和反例，不能画成测量出来的事实。本轮不实现，第 6 节只给它留一个开关位置。
- **创作候选**：尚未采用的方向、局部修订或反事实推演。视觉上与当前稿区分，采用时走已有的作品修改和提交能力。

视图状态、分析缓存和图布局都可以删除。作者采用的长期结论写回相应的 Intent、Character、World、StoryBeat 或其他已有 artifact，不新增与它们平行的知识图谱 Canon；也不能为了画图，强迫每个 Beat 填满情绪、时间、地点和关系字段。

作者看全局事实与创作意图，读者看截至当前位置已经披露的内容，人物看自己的经历与认知，此外还有结构、协作和证据三种视角。这六种是同一个作者工具里的观察方式，不是六种用户角色或权限，也不因此新增独立的 Reader 产品。

### 1.2 六种不能混用的图

能画成节点和边的图有六种，业务含义互不通用：

1. 故事因果图：选择与后果之间的故事关系；显式引用与模型解释分别标记。
2. 人物 / 世界关系图：人物、家族、场所、资源之间的特定关系，可随时点变化，不等于共同出现。
3. 知情与披露视图：世界、人物、读者之间的信息边界，优先用矩阵和轨道表达。
4. 作品影响与证据图：版本、Artifact、Context、审稿和可能受影响范围之间的联系。
5. Task 依赖图：实际工作需要哪些结果先完成。
6. 委派与交接树：谁发起了什么任务、结果交给谁；与 Task 依赖不是一回事。

它们可以互相定位，但不能因为都是节点和边就共用一套含义。界面用图形表示，不要求引入 LangGraph、预规划的执行图或第二份运行真源。

## 2. 一个坐标系：故事轴

所有全局视图共用一条横轴：**index.yaml 里的 Beat 顺序**，按卷分段。它表示故事顺序，不是日历时间，也不是作品版本历史。全书视图默认保留完整信息；选中 Beat 只用于定位与突出相关关系，不过滤人物、承诺或反向链接。

故事轴不是一张图，而是一组可开关、可折叠的**泳道**叠在同一横轴上。作者从上到下读到的是同一时间坐标下的不同层：

```
卷           │ 黄天将裂 ─────────┤ 无主之地 ────────┤ 许都与江东 ───┤ …
Beat         │ 01 02 03 04 05 06 07 08 09 │ 10 11 … 16 │ 17 …
覆盖         │ ● ● ● ● ● ● ○ ○ ○ │ ○ ○ … │        ● 有正文 ○ 仅设计 ◐ Design 已变
审稿         │       ▲       ▲   │        │        ▲ 有效 △ 已 stale
承诺 · 活人的要求 │ ├─────────────────── … ──────────────────┤ 67
承诺 · 汉名归处   │       ├──·──·──── … ──┤ 39 (deadline 39)
承诺 · 三人同到太平│    ├──·─── … ──┤ 45                    resolve 之后若再 advance，画红点
因果         │   ╭───────╮   ╭──────────────╮        弧线：refs.beat，从被依赖的 Beat 指向依赖它的 Beat
人物 · 诸葛亮 │                         ● ● ● ● ● ● …     ✕ 死亡  ◆ 秘密对他揭示
人物 · 刘备   │ ● ● ●   ●   ● ● ● …
世界 · 汉廷名义与官爵 │ ▪ ▪   ▪ ▪ …
```

每一格都是一份 artifact 或一条 frontmatter 记录，点击回到原文，hover 说明"这是什么、来自哪个字段"。轴上没有任何一处是模型解释出来的。图例与操作说明只在左下角「?」打开的帮助模态框里常驻（故事轴头部的「图例与操作」按钮也开它），左栏不再放图例，行上的 hover 提示当场解释；空泳道不画，只有一条泳道的组不设组头。

**层级与缩放**：默认全书，点轴上的卷名进入那一卷，点面包屑「故事轴」回到全书，不设单独的切换控件。两级都默认按窗口宽度适应列宽，保留小数精度，避免逐列取整在右侧累积空白。泳道底色和横线至少铺满可视区，与内容区右边界对齐；标题列或侧栏调宽时同步重算，数据标记保留边缘留白，少量 Beat 与手动缩小时也不截短行背景。作者可用 ⌘ 滚轮 / 触控板捏合与「−」「+」「适应窗口」连续缩放。表头每个 Beat 一个空心圆作列标，不显示 id（id 与标题在 hover 里，列够宽时显示标题）；卷名按列宽截断，Beat 数在 hover 里。头部只放状态条没有的信息（审稿 current、Design 冻结），正文计数只在状态条，选中 Beat 与查看状态入口放在轴头部。几百万字的作品（上千 Beat）适应窗口后每列不足 1px，需要卷级聚合的全书档（每列一卷）再点卷下钻，见第 7 节第 5 步。

**选择与状态查询**分开。竖线标记选中的 Beat，可拖动或按方向键移动；未来泳道不因此变淡。点击「查看此处状态」才打开状态侧栏。状态查询固定观察位置、进入前 / 本幕变化 / 结束后三种边界和可选主体；打开原文、切换标签、前进后退都不改变观察条件。切换右栏模式保留查询；收起与展开恢复原模式。

**状态查询的用途与边界（2026-09-09 确认）**：

- 右栏固定「故事状态」入口；Beat 页点击时查询当前幕，三种边界只在侧栏切换。进入前用于恢复写作依据；变化展示两端实际状态差异（含资源转移隐含的清空）；结束后用于核对这一幕的结果。
- 人物、资源、承诺页点击「故事状态」直接限定当前主体，沿用上次明确查询的位置；没有位置时提示选择，不替作者默认首幕。可通过「更换位置」查询其他位置或查看全部。人物知情必须区分 world、character 与 reader 的声明。
- 侧栏使用既有 `workspace.context` / host `context compile` 的共享 Runtime 投影，只读明确的已提交 revision。硬状态复用 StateTimeline，承诺复用 Contract lifecycle；未记录显示未知，不推断人物心理或幕内时刻。每项依据可回到源文件。
- 引用给 Agent 时附观察位置、边界、主体、实际查询 revision 与结果；点击引用只准备上下文，作者发送之后才开始或接续一个 turn。
- 引用计数默认全书，刷选时才切换到区间；关系图和人物 / 承诺轨迹始终展示全貌。移除旧的累计引用计数、未来灰显与全局知情筛选，避免浏览动作改变查询答案。
- 状态查询是派生读取和客户端 view state，不新增 Artifact、持久领域实体或执行状态。

**范围刷选**：在卷行上拖出一个区间，上下文栏的身份计数改成"区间内引用数"，Agent 面板出现"引用这个区间"的 chip。这是"这一卷谁缺席"这类问题的入口。

## 3. 泳道

每条泳道回答一个问题，声明它读哪个字段、怎么编码、点什么去哪里。没有列出来的字段不画。

### 3.1 覆盖与审稿

- **正文**：● 已提交 StoryText 且正文时效 `current`；◐ 有正文但 Design 已变化（`design-changed`）；仅设计留空，不画缺席（63 个空心圈比 6 个实心点还重，2026-09-09 验收后改）；候选未提交的 Beat 画琥珀空心。数据：`workspace.show` 的 `storyText`（由 `textCurrencies` 从 git 历史派生）、`files[].dirty`。
- **审稿**：▲ 当前有效报告，△ stale；颜色按 verdict（pass 绿，revise 与 insufficient_context 琥珀，block 红）。同一 Beat 多份报告叠成数字。点开审稿页。数据：`workspace.reviews`。
- **finding 密度**：可选，把有效报告的 finding 数画成格子深浅；默认关。

### 3.2 承诺生命周期

每条 StoryContract 一条泳道，只显示与当前范围有交集的承诺：

- open 处画左端点，resolve 处画右端点，两者之间实线；只有 open 没有 resolve 时虚线延伸到 deadline 或轴末端。
- advance 画成线上的小圆点；**resolve 之后出现的 advance 单独画成红点**，Checker 只查结构生命周期不报这个。判断用的是 index.yaml 顺序而不是 id 大小：eval-022 的 `beat-0068 / 0069` 就排在第一卷内，按 id 看像是"兑现后又推进"，按轴看只是第一卷里的两个 Beat，原型第一次画出来才发现。
- deadline 画成竖短线；全书范围内已到 deadline 仍未 resolve 时标琥珀；具体位置的承诺状态由显式查询回答。
- `subjects.character` 在 hover 时列出，点击人物行高亮该人物泳道。
- 承诺页顶部放同一条泳道的单行版本，见第 4 节。

### 3.3 因果弧

`refs.beat` 是作品里唯一显式的跨 Beat 依赖。画成轴上方的弧线，从被依赖的早 Beat 指向依赖它的晚 Beat；弧高与跨度成正比，所以远距离依赖自然突出。hover 一条弧显示两端标题；点击某个 Beat 只留与它相关的弧，其余淡出。相邻顺序和主题相似不连边，这是 Story Language 的规定，不是视图的省略。

### 3.4 人物

- 每个人物一条泳道，按首次出现排序，默认展开引用最多的 8 个，其余折叠成"还有 15 人"。
- ● 该 Beat 的 `refs.character` 含此人。它表示"这个 Beat 实质使用了这个人物"，不表示出场或 POV，图例照此写。
- ✕ `changes.world.<人>.dead: true`，之后的格子画成空心，表示人物已不在世但仍可被引用（回忆、遗产）。
- ◆ `changes.character.<人>.secret:<x>.revealed`，hover 显示秘密 id。这是人物知情矩阵（C5）在当前数据下能确定的那一部分；未记录不等于不知道，图例照此写。
- ⌖ `changes.world.<人>.location` 变化，hover 显示目的地。

### 3.5 世界与资源

- **世界文档**：`refs.world` 一条泳道一份文档，▪ 表示被引用；默认折叠，只在作者展开时显示。回答 D1"这条规则在哪里起作用"。
- **资源**：只对有 `initial.holder` 或 `changes.*.holder` 的 Resource 画：持有者变化处画一个带人名的节点，中间连线；consumed / destroyed 画终止符。eval-022 只有两件，泳道自然很短；斗破类作品会长得多。

## 4. 局部视图：围绕一份 artifact

全局轴解决"在哪"，局部视图解决"这一份和什么有关"。它们出现在设计与对象页内，不另开标签页，也不是切换模式：邻域图放在页面末尾（承诺页除外，顶部轨迹已列出全部锚点），Beat 设计文档本身不长，读完顺势看到关系，省一次点击。小说正文不附带邻域图；阅读时需要核对结构，可并排打开设计。

### 4.1 邻域图

邻域图取代了原来的圆形结构图：那张图把一跳节点均匀摆在圆上，超过二十个节点就重叠，圆形也不表达方向。邻域图分三列：

```
上游（它依赖的）        当前                下游（依赖它的）
refs.beat → beat-0031   ┌──────────┐      beat-0044 ← refs.beat
refs.world → 汉廷名义    │ beat-0039 │      汉名归处 ← contracts.resolve
refs.character → 刘协   │ 玺落谁手  │      奉天子以止乱 ← contracts.resolve
                        └──────────┘
```

- 列内按 kind 分组（Beat、承诺、人物、世界、地点、资源），组标题带计数；边是贝塞尔曲线，粗细一致，颜色按 kind。
- 点击任一节点打开它的页面，页末就是以它为中心的邻域图；没有二跳开关，二跳就是再点一次。
- 每组默认显示 8 项，其余收成「还有 N 项，展开」。
- 数据全部来自 `deriveLinks`，键名就是边的说明。

### 4.2 承诺页

标题下放一行本承诺的生命周期条（第 3.2 节的单行版），每个锚点标注 Beat 标题与是否有正文；下面是 subjects 人物的在场条（只取这条承诺 open 到 resolve 之间的 Beat）。页尾的通用反向链接列表删除，右栏保留。

### 4.3 人物页

标题下放该人物的轨迹条：在场、死亡、位置变化、秘密揭示，加上他是 subject 的承诺区间。轨迹与揭示记录展示全书；具体位置的已声明知情由状态侧栏查询，每项依据回到源文件。

### 4.4 Beat 页

前因后果就是设计页末邻域图的左右两列（`refs.beat` 指向的 Beat 在左，引用它的 Beat 与承诺锚点在右），不再单独做一行。关系取自已声明的引用结构，不据此断言小说正文已经写出这些关系；正文与空正文视图均不显示。

## 5. 交互约定

- hover 只解释，不改变状态；点击才导航或选中。
- 选中一个 Beat（点轴、点左栏、打开它的页面三者等价）后，全局轴高亮它那一列，因果弧只留与它相关的，承诺泳道上的它的锚点放大。
- 视图状态（缩放档、展开了哪些泳道、刷选区间）存 `view-state`，与标签页一起丢弃，不进作品。
- 键盘：选择标记上的 ← → 改变选中 Beat；Beat 列支持 Enter 选择，查看状态通过明确按钮发起。
- 所有颜色沿用工作台的语义色：绿 = 有正文 / 通过，琥珀 = 待处理 / 过期 / 未提交，紫 = Review 证据，红 = 冲突与异常，灰 = 缺席或未记录。承诺、人物、世界三类泳道用不同的**形状**而不是新颜色区分。

## 6. 不做什么

- 不做力导向图、不做全书级"知识图谱"。作者问的问题都有明确的坐标轴或中心，散点图回答不了任何一个。
- 不画情绪曲线、张力分数、关系强度。这些没有记录来源；1.1 的「语义解释」层留一个开关位置，本轮不实现。
- 不为了画图要求作者补字段。泳道对缺失字段显示"未记录"，不显示 false。
- 没有坐标数据时不画精确地图；地点引用不证明人物到过那里。发布章节来自 Release，不把 Beat 直接当章节。
- 不把重排 Beat 做成拖画布：顺序改变必须经 `workspace.file.save` 与 Checker，视图只能发起命令。
- 不做 Cloud Web 版本；视图组件写在 `apps/web`，Cloud 解冻后自然复用。

## 7. 实现顺序与验收

全部在 renderer 内完成，数据来自 `workspace.show` 与 `workspace.reviews` 已有投影，不需要新的 Runtime 通道。SVG 由 React 直接生成，坐标是线性映射，不引入布局库。

第 1–4 步已于 2026-09-09 落地（`apps/web/src/axis/`），eval-022 上的脚本化验收见[可视化操作验收](validation/2026-09-09-visualization.md)；作者本人在自己作品上的解释负担还没验收。

1. **故事轴骨架**（替换谱页，已落地）：卷分段、Beat 列、覆盖与审稿泳道、承诺泳道、Beat 选择拖动、卷 / 全书缩放。验收：样例作品 E2E 能点 Beat 打开页面、改变轴选择不影响全书引用计数，显式查询才读取状态；eval-022 上第一卷的 Beat 列顺序是 `1 68 2 3 4 5 69 6 7`，与 index.yaml 一致。
