# Agent 输入能力方案

2026-09-10：补充输入器的「＋」、附件和语音能力。现有约 104px 高的中性色输入框作为样式基础。作品引用与 UTF-8 文本附件已实现，语音输入与实时语音仍待服务选择和设备验收。实现边界及证据见[原生对话交互验收](validation/2026-09-10-agent-composer/README.md)。

源码参考与交互边界见 [assistant-ui 对话功能源码参考](assistant-ui-reference-review.md)，包含安全发送、附件并发、滚动、运行中补充及中文输入适配。

## 输入器布局

当前底部操作行采用「＋　弹性留白　发送」。麦克风在实际听写服务接通后加入。发送保持黑底白色箭头；其余按钮使用中性色图标与灰色悬停反馈。快捷键放到发送按钮提示中，为窄侧栏保留空间。

「＋」打开添加内容菜单，按来源提供以下入口：

- 引用当前内容：当前选段优先，否则引用当前文档；选择后出现可预览、可移除的引用条。
- 选择作品文件：可搜索中文标题、设计 / 正文类型和相对路径，逐次加入多份文件；`@` 在输入开头或空白之后打开同一个选择器；显示设计或正文类型，避免只凭名称混淆。
- 添加文本文件：文件选择、拖放和粘贴文件共用读取链路，实际解码 UTF-8 内容；引用总量限制为 256 KB。图片和 PDF 显示不支持的原因，不当作已读文字发送。

选中的附件显示在输入区上方，发送前可以预览、移除；读取或解析中的附件有明确状态，失败可以重试。不能把尚未能解析或交给模型的文件展示为已添加成功。

模型选择是否进入底部操作行，沿用[作者工作台设计](web-product-design.md)的 profile 边界；不新增只改变标签、没有实际绑定效果的模型菜单。

## 附件与作品的边界

引用当前内容和作品文件时，记录实际路径、版本、内容指纹及选段；未保存编辑明确标识为工作草稿。选中附件是准备输入，发送才把内容交给 Agent。

本地附件是会话输入，不因添加或发送自动成为作品 Artifact。Agent 需要将长期结论写回作品时，仍走已有候选、Checker 与提交边界。项目文件引用、外部原始文件与从文件解析出的文字应能区分，不以文件名冒充已读内容或 evidence。

纯文本已沿用当前文本消息通道；图片需要真实的多模态消息传递，PDF 等文档需要实际解析。当前 `run.launch` / `run.steer` 只接受文字，不能只加文件选择按钮就声称已支持通用附件。后续应在现有命令和消息边界中接入附件，统一处理初始委托和运行中补充，不新建一套会话或运行服务。

未发送附件与目标草稿按作品、委托隔离；切换右栏、委托和重载后恢复。文件读取完成时按附件与读取身份写回原草稿；新委托回执移动草稿后也能定位，移除或重新读取会使旧回包失效。发送先冻结本次内容与命令 ID，后续输入独立保留；重载后的不确定提交由作者显式确认，不自动重发。

## 语音的两种范围

建议默认以语音输入为入口：点击麦克风开始听写，录音中显示时间及「取消」「完成」，结束后转为可编辑文字，作者确认后发送。转写补入开始听写的草稿位置；取消不改写文字，也不启动委托。

实时语音对话是另一项能力：连续收音、语音播放、打断、静音和结束对话需要完整状态，模型调用与 Agent 的任务执行也需要协调。不能让同一个麦克风按钮在没有说明的情况下既表示听写又表示实时通话。

当前项目没有录音、转写、语音播放或实时音频链路。需要选择并验证实际的转写或实时语音服务；不能默认现有文字模型、OAuth 登录或产品订阅能调用音频 API。

macOS 系统听写可作为待验证的本地接入选择，但不能伪装成应用自有的录音状态。必须确认能在当前 Electron 文本框中启动、停止和回填；若依赖系统配置，应明确说明。转写服务、凭据和录音权限问题在使用入口内给出可执行指引。

## 验收

- 普通、窄栏、展开状态均能操作「＋」、语音和发送，保持统一图标尺寸与中性色样式。
- 添加、预览、移除、多附件、解析失败、切换委托和重载均保留正确内容；点击添加不启动 Run。
- 引用准确区分已提交版本与未保存草稿；外部附件不自动写入作品。
- 听写覆盖首次权限、拒绝、录音、取消、完成、转写失败；不覆盖原草稿、不自动发送，离开输入器后停止占用设备。
- 实时语音若纳入本轮，另验收连接恢复、打断和播放生命周期；不能用文字回填测试替代真实音频闭环。
