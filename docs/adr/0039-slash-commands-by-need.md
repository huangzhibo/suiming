# ADR-0039：`/` 命令按需要重设，协作模式收成讨论开关

- 日期：2026-10-19
- 状态：Accepted。取代 [ADR-0038](0038-collaboration-modes-goal-and-slash-commands.md) 的决定一（三种协作模式）与决定三（`/` 命令）；决定二（目标）不变

## 背景

作者看到输入框的命令菜单，问了三件事：Codex、Claude Code 都没有「自主」这样的切换，为什么我们有？为什么要做模式切换？两家的新对话也不是用 `/` 命令开的。随后要求按我们的需要重新设计 `/` 命令。

本机核对过 Claude Code 2.1.302 和 codex-cli 0.162.1：

| | Claude Code | Codex |
| --- | --- | --- |
| 模式 | 桌面输入框左下角是权限模式（如 Auto），终端用 Shift+Tab 轮换 | `/permissions` 选 Read Only、Default、Full Access |
| 斜杠里直达模式 | 只有 `/plan` | 只有 `/plan` |
| 新对话 | 终端用 `/clear`（别名 `/new`、`/reset`），桌面用侧栏按钮 | 终端用 `/new`、`/clear`，桌面用侧栏按钮 |

作者随后给了 Codex 桌面版的 `/` 菜单。在 GUI 里它是键盘入口：「模型」「推理」在输入框底部已经有下拉，照样列进菜单，带子菜单，行里显示当前值（如「推理 极高」）；另有代码审查、初始化、工作树、用量等动作。它的新对话仍在侧栏。

两家的权限模式管的是哪些动作要先经用户批准，比如跑命令、改工作区外的文件、联网，这些动作做了收不回来。plan 是另一回事：在几轮里把 Agent 按在「只出方案」上。

ADR-0038 照两家的形状做了三档，又给每个界面动作配了一条命令：`/讨论` `/协作` `/自主` `/模型` `/新对话` `/提交`，外加作者存在配置目录里的自定义命令。

## 作者实际需要什么

先列我们的作者在输入框里需要什么，再看每条命令和每档模式能不能对上：

1. **商量方案的那几轮里，Agent 不抢先动手。**作者给方案提意见时，话常常写得像指令。这有两次真实运行可以对照：
   - 第二次留出运行，作者说「检查并提交」，Agent 当成全权授权，没问就把一节抽自原作的 Design 改成了与原作相反。
   - [AI 代作者使用](../validation/2026-10-18-doupo-proxy-author/README.md)第二轮，作者说「节奏慢，苦修和升级压进第一节……」，这句是在讨论模式里说的，Agent 只改了方案。

   抢跑一次就是一轮自主运行，那次第三轮用了 63 分钟、3.36 美元。作者得先停下它，再撤销改动。
2. **跨很多轮推进到一个目标。**设目标除了 `/goal` 没有别的入口。
3. **打字时不离开键盘，就能调这段对话怎么跑**：目标、讨论、模型与思考强度。这是 Codex 桌面版 `/` 菜单的用法。
4. **离开这段对话、改作品是另一类动作**：新对话、提交版本。两家桌面版的新对话都在侧栏；我们的提交版本在版本区有按钮，平常 Agent 也自己提交。

## 决定

### 一、协作模式收成一个「讨论」开关

讨论是对话上的一个开关，默认关。开着时，Agent 的工具面与 ADR-0038 的讨论模式相同：
- 只读，不派子任务，不审稿，不续子任务，不提交；
- 这一轮读文件时不保存作者在编辑器里的草稿。

关掉就是原来的「自主」，全部能力都在，包括提交。作者关掉讨论、再说一句「照这个做」，就是两家里批准 plan 的那一步。

| 原来 | 现在 | 理由 |
| --- | --- | --- |
| 讨论 | 讨论开关 | 对应需要 1。光靠提示里「只有作者要求执行才修改」不够：多轮改方案时，作者的意见本身就像指令。由工具面保证，不靠模型自觉 |
| 协作 | 删除 | 见下文 |
| 自主 | 不再是一档，就是讨论关着 | 没有可以与它并列的另一档，留着名字只会让作者以为要选 |

协作删掉，原因有三：
- **它保护的东西本来就收得回、看得见。**提交要过 Checker，可以回滚。提交结果会列出连带进版本的作者未提交修改，并要求 Agent 在回复里点名。turn 结束的对账也会列出 Design 改了什么。
- **它没解决起因。**第二次留出运行改反 Design 那件事，换成协作模式，改动只会停在候选里，作者照样得翻差异才能发现。对症的是 Agent 遇到大的取舍先问：提示里已经有「需要作者决定的事直接问」，目标里有 `blocked`。
- **没人用过。**除了 ADR-0038 自己的验收回归，没有一次真实使用切到过协作。

Session 记录里的 `collaboration` 改成布尔的 `discuss`。CLI 的 `--mode discuss|collaborate|autonomous` 改成 `--discuss` / `--no-discuss`，与原来一样从这一轮起生效，之后沿用。旧记录里的 `collaboration` 不再读取，按关着处理；这是开发期执行数据，不做迁移。

### 二、`/` 命令管这段对话怎么跑

| 命令 | 做什么 | 为什么留 |
| --- | --- | --- |
| `/目标 <目标>` | 设目标并开始跑；`/目标 暂停`、`/目标 继续`、`/目标 清除` 改已有目标 | 设目标没有别的入口。暂停、继续、清除和目标栏上的按钮是同一个动作，留下它们是因为不认的话，`/目标 暂停` 会被当成一个新目标去跑 |
| `/讨论` | 打开或关上讨论；`/讨论 <话>` 打开讨论并把这句话发出去 | 对应两家的 `/plan`（Claude Code 的 `/plan <描述>` 也是这样）；与输入框里的开关是同一个状态 |
| `/模型` | 打开输入框里同一个模型与思考强度面板 | 需要 3；Codex 桌面版同样把模型和推理列进菜单 |

- 菜单行里按当前状态写说明：讨论关着时写「打开讨论……」，开着时写「关上讨论……」。这是照 Codex 在行里给当前值的做法，开关类命令不写明当前状态，作者不知道选了会怎样。
- 删掉 `/协作` `/自主`（模式没了），`/新对话` `/提交`（需要 4，走按钮）。
- 删掉自定义命令（应用配置目录下的 `commands/<名字>.md`）：
  - **作者找不到也建不了。**它在应用配置目录里，界面没有入口；Agent 只能写作品目录，也替作者建不了。
  - **该放进去的话都有更合适的去处。**对以后一直成立的要求，写回 `intent/**`，这是产品的核心路径，Agent 会自己写回；多步的固定流程用 `/目标`；一次性的话直接说。
  - **没用过。**没有任何真实使用里出现过。等真实使用里出现作者反复敲同一段长话，再连同创建入口一起设计。
- 命令名用中文，与界面一致。按前缀筛选时也认英文别名 `goal`、`plan`，不开输入法也能打，原来的 `/goal` 照样能用。
- 不做内置的创作命令（如 `/写下一节`、`/审稿`）。固定创作配方已经删除，这些都是对 Agent 说一句话的事。Codex 的「代码审查」是一个独立的审查模式，我们的审稿是 Agent 自己能调的能力，不对应。
- 不把 host 的 Skill 做成命令（作者问过：Codex / Claude Code 里的 `suiming` Skill 也用 `/` 调起）。那是给通用 host agent 按需加载的一份说明，教它跑 `suim`、派自己的子 agent；桌面 Agent 的系统提示、Story Language（`story_guide`）与写作方法一直都在，Harness 也刻意不加载 host 接入文件（[Harness 设计](../harness-design.md)「host 接入文件不进 Harness」），`/suiming` 什么也不会多给。host 的研究、候选、写手、审稿子 agent，在桌面是 Agent 自己派的子任务，作者说一句「审一下这节」就行。
- 不做「使用情况和计费」。Codex 的这一项打开 ChatGPT 套餐的用量与账单；我们没有账单，作者直接付给模型提供方。这段对话的累计用量与估算花费显示在执行记录上方，防空转的每轮用量检查点在设置里。

## 后果

- 输入框底部的「协作模式」下拉删掉。讨论与目标用同一种模式标记，照 Codex 的计划 / 目标：只在开着时出现，图标加名字，悬停换成 ⊗、点一下取消，提示语跟着模式换；选 `/目标` 进入目标输入，下一条话设为目标。作者先问过为什么还有常驻的「讨论」按钮，又问讨论和目标为什么交互样式不一样（同日两次改）。对话正在回复时切换讨论，与换模型一样写「待生效」或「待关上」，随下一条消息生效。模型入口挪到右边；输入框窄时模式标记与模型入口只留图标。
- 删掉 `commands.list` 命令、`readAuthorCommands`，以及工作台里读取自定义命令的查询。
- 回归里的 `mode-collaborate` 删掉，`mode-discuss` 保留。
- 现行规范同步：[作者工作台设计](../workbench-design.md)的对话区与命令菜单，[Harness 设计](../harness-design.md)里提到协作模式的地方，[需求与目标](../vision-and-requirements.md) 5.1 节，以及 Skill 里 `session send` 的参数。

## 验收

- **机制**
  - 讨论开着时工具面只读，一轮之后 checkout 逐字节不变，草稿没有被保存。
  - 关着时工具面完整，包括 `commit`。
  - 切换从下一个 turn 起生效，重启后保留。
  - 讨论开着时设目标，Agent 只能讨论。
- **CLI**
  - `--discuss` 打开，之后的 `session send` 沿用；`--no-discuss` 关上。
  - `session show` 的摘要里有 `discuss`。
- **桌面 E2E**
  - 菜单只列 `/目标`、`/讨论`、`/模型`；输入 `/g` 筛出 `/目标`；讨论那一行随开关状态写「打开」或「关上」。
  - `/讨论` 与开关是同一个状态，讨论下发一句「改第二节」，文件与草稿都不变。
  - `/模型` 打开同一个模型面板。
  - `/目标 清除` 清掉已有目标，不会被当成新目标去跑。
  - 输错命令名只报错，不发出去。
- **真实模型**：回归 `mode-discuss` 跑一次。
