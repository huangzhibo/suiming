# ADR-0034：收敛草稿恢复、Artifact 转换与文档职责

- 日期：2026-10-17
- 状态：Accepted

## 背景

外层 Story / Runtime / SDK / 桌面边界保持清晰，本轮不更换执行架构。代码审查发现三个具体负担：工作区恢复将作者草稿当作可丢弃的界面偏好；包转换仍通过仅测试使用的内存版本库；文档窗格同时承担导航、编辑事务与展示。

## 决定

1. 工作区存储不存在才创建默认布局。读取失败或草稿内容无法完整恢复时保留原记录，阻止该作品进入编辑和自动持久化，提供重试与打开其他作品。布局偏好可归一化，作者正文、未发送消息与待确认提交不能静默丢弃。不迁移存储格式，不新增草稿数据库或恢复副本；草稿仍属于桌面应用数据，作品目录备份不含它。
2. Open Story 文件与候选转换使用现有生产路径；删除仅被旧测试使用的 `InMemoryArtifactStore` 和依赖它的导入导出入口。格式与纯变更验收转到真实转换函数，提交、历史和隔离验收使用 Git Canon。保留 Open Story Package 能力，不另建模拟版本库替身。
3. 文档编辑动作和窗格导航按职责整理；查询、草稿状态、CAS 保存、编辑历史、导航纯函数继续使用现有实现。组件负责展示及必要的 DOM 交互，不增加通用 controller、状态库或第二套导航。外壳全局 effect 仍只运行一次，窗格 effect 仍按窗格运行。

## 边界与验收

不修改 Story Language、Canon 格式、Harness loop 或现有页面视觉。分步提交；恢复故障先有失败用例，涉及内容与导航的整理必须经隔离 Electron 验证多文件、切页返回、冲突、删除恢复、分屏、窄窗和焦点。测试辅助退出产品面时保留其有意义的领域断言，明确说明被删除的模拟实现测试。

实际进度与结果见[验收记录](../validation/2026-10-17-architecture-consolidation/README.md)，完成度与后续队列分别维护在当前状态与路线图。
