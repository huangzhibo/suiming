# ADR-0037：Agent 的界面上下文与展示能力

- 日期：2026-10-17
- 状态：Accepted

## 背景

文件能力已经能按需同步作者草稿，但作者说“这里、这段”时，Agent 仍不知道当前文档与选区；找到结果后也不能主动展示。要求作者先引用文件、再点击结果，把界面协调工作转嫁给了作者。与此同时，后台创作不能不断切走作者正在看的页面。

## 决定

1. 发送消息时冻结当前页面、物理文件、视图、未保存标记、比较基线及选区。选区最多 4000 字符并标明截断，不自动读取所有打开文件的全文。沿用已有消息文本与引用展示，发送回执丢失后重试仍使用原快照，不重新采集当前页面。
2. 桌面根 Agent 获得 `workbench` 工具：查询当前上下文；打开文件，可按行号或精确引文定位；展示当前 Canon 或磁盘与作者草稿 / 候选的差异。查询另含有界的打开文件元数据。CLI 与子任务不声明此工具，文件创作仍走原领域能力。
3. 查询不触发保存。展示复用 `openDocument`、`openComparison` 与 CodeMirror，不建立另一套导航、编辑器或草稿。打开正文必须落在正文物理文件；重复引文须消歧，不能默默跳到第一处。
4. 导航须使用刚查询到的界面位置，异步读取后再次核对作品、位置与取消状态。作者切页、切作品、停止或 renderer 重载后，迟到操作不得继续导航；重载不重放界面操作。关窗后不为展示能力创建或唤起窗口。按需文件同步仍可按 ADR-0036 重接隐藏编辑器，两者共用临时请求传输，但生命周期策略不同。
5. 只有作者要求展示、定位或比较时才操作页面；普通创作不因修改文件就自动切页。导航不调用键盘聚焦，保留对话里继续输入的内容。所有操作沿用文件路径边界，不提供 DOM、坐标点击、系统桌面控制或新执行协议。

## 代价与边界

发送时快照可能过时，不能作为当前文件真源；Agent 需要最新内容时仍应读取。界面位置只用于防止迟到导航，不是作品版本或权限凭证。精确定位使用源码编辑视图，保留现有撤销与草稿，不修改内容。作者是否要求展示由模型理解，不引入关键词闸门；路径保护、取消与迟到检查由系统保证。

验收与未覆盖场景见[界面能力验证](../validation/2026-10-17-agent-workbench/README.md)。
