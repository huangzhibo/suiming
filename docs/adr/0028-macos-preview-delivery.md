# ADR-0028：macOS 预览先交付自含应用，升级复用完整冷备份

- 状态：Accepted
- 日期：2026-10-15

## 背景

开发入口和 Electron E2E 依赖仓库的构建目录，不能证明安装后的应用可独立启动。现有 Canon、执行库与对象目录已经能完整恢复，不需要再造安装专属的迁移任务或版本副本。

## 决定

使用官方 Electron Packager 构建本机架构的 `.app`，以 zip 携带，应用内部用 ASAR 保存编译产物。npm 已安装的桌面生产依赖闭包决定打包范围，不重新求解版本、不复制整个开发仓库。生产入口、preload、renderer 和 Runtime 仍是同一份实现，安装测试从解压后的可执行文件启动，不加载测试入口。

稳定使用 Suiming 名称与 `org.suiming.desktop` bundle ID。作品和对话始终在应用包外；替换应用不迁移作品。当前验收范围限定为 v6 执行库与当前 Story Language 的兼容构建替换。回退复用完整旧应用、完整作品冷备份和独立用户配置保全；不承诺旧 schema 转换，不新增自动更新器或第二份 Canon。

启动时重开作品失败必须留在可见界面，保留错误原因与重新打开入口。不能只记录日志、伪装成首次启动，更不能删除数据换取启动成功。

## 代价与边界

手工替换应用需要退出写入进程并保留备份，但避免在尚无正式版本跨度时提前引入更新服务。将来跨格式发布仍必须有具体迁移或旧版可读的恢复方案，不能以本轮同格式成功替代。

未签名、公证的本机预览不能算正式 macOS 安装交付。签名、公证、下载隔离、独立机器和其他架构须分别验收；本轮不向作者索取身份或凭据来制造未经授权的外部发行。

操作与验证见[macOS 预览](../macos-preview.md)和[安装验收](../validation/2026-10-15-macos-install/README.md)。

## 2026-10-15：签名准备补充

签名是同一构建的后处理，使用 `@electron/osx-sign` 和 Apple 原生命令完成，不增加第二个打包器或更新状态库。只签独立副本，显式指定 Developer ID 指纹及钥匙串公证 profile；公证编号与日志只是发行诊断文件。最终归档必须在 Accepted、staple 和系统校验之后生成。缺身份时仅允许明确标注的 ad-hoc 本地演练，不能称为正式发行；其无 Team ID 所需的库校验例外不进入正式签名配置。
