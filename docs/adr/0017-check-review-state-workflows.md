# ADR-0017：检查、审稿与状态查询分别组织工作流

- 日期：2026-10-12
- 状态：Accepted

## 背景

延续 ADR-0016 的逐页设计。现场检查 231 节作品时，检查结果的 437 条警告只能纵向浏览，正常通过状态重复占行；人工构造的长摘要、多意见审稿报告挤压了稿件区域。故事状态把位置标签、位置名和更换按钮分开，设置重复解释默认模型的作用。

## 决定

- 检查页保留总结果、检查时间、版本基线、过期和失败提示，分类通过状态合为紧凑一行。所有可处理诊断（含阻塞正文的问题）共用严重性与文件 / 字段 / 内容筛选，明确显示过滤量和总量；筛选无结果不表示检查通过。诊断契约没有稳定类型码，不从文案推断分类，也不新增领域类型。
- 审稿页以当前意见为工作单位。完整结论与范围按需查看；宽工作面显示意见列表，窄工作面用选择器。证据与建议跟随选中意见；长证据独立滚动，文件入口和单条复核留在滚动区外。稿件区域只在实际内容宽度充足时并列被审稿与当前稿，否则切换查看；过期提示始终可见。整份复核独立保留在报告头部。
- 故事状态的位置本身就是选择控件；查询保持显式选择的位置；与当前情节一致时省略重复选择器，不一致时保留选择器并提供「查看当前情节」。三种观察边界、主体范围和已提交版本直接显示，长语义解释按需展开，引用内容与领域查询保持原样。
- 设置仍是分类表单，只删除默认模型的重复说明，不压缩认证状态、错误和保存反馈。

筛选与稿件选择进入既有页面 view state，按标签、分屏隔离并随重载恢复；不新增持久领域实体，不建立通用页面配置引擎。地点的说明与关系、资源的开场状态保留直接展示；读者期待保留回应状态与期限，只移除长篇中重叠的卷名刻度。Secret 没有独立文件页，沿相关情节与状态查询验收，不建立新页面。

## 验证

真实 Electron 验证筛选和总量、空结果、文件跳转、报告过期、意见选择、稿件切换与重载，以及原有状态引用、模型保存和认证流程。生产窗口在 1460×940、960×640 与分屏状态复核。人工构造的审稿仅作布局与交互证据，不当作文学质量评测。
