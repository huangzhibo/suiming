# ADR-0029：搜索与编辑之间保持键盘现场

- 日期：2026-10-15
- 状态：接受

## 问题

搜索入口、结果按钮、编辑器和弹层分别可用，不代表它们连成一条可用的键盘路径。新标签没有输入焦点、重复唤起搜索不转移焦点、长结果返回时焦点和滚动位置脱节，都会迫使作者重新使用鼠标。侧栏前 60 项之外没有入口，也让键盘导航只能覆盖部分作品。

## 决定

焦点只随明确操作移动：新选择页进入搜索，打开对象后可直接切换编辑；返回选择页优先回到刚打开的条目，条目不存在时回到搜索。记住的是现有页面快照中的对象路径，不保存 DOM 身份，不建立新的导航存储。异步目录加载完成前若作者已移到别处，不再补做迟到的聚焦；切换活动窗格也不重复执行页面进入时的聚焦。

两个搜索入口共用方向键与结果扩展后的焦点交接函数，结果仍是原有按钮，继续保留 Tab 与 Enter 的原生语义。中文组合期间不导航；Home / End 只在结果中定位首尾，不抢输入框编辑键。侧栏按批增加结果，与空白选择页一样提供明确数量和更多入口；不引入虚拟列表或服务端分页。

菜单和确认框继续由 Base UI 管理焦点与退出，不另造弹层焦点栈。未保存关闭、保存冲突、取消、撤销重做与窗口重载以真实 Electron 连续操作验收，不因为测试步骤缺少产品行为就用 `focus()` 补过去。

## 边界

这是既有工作台导航规则的落实，不扩展 Story Language、Canon、Runtime 或 Agent。搜索范围与排序保持各入口原有用途；完整读屏验收、所有系统输入法候选面板不在本切片中。当前规则见[工作台设计](../workbench-design.md#33-导航选择与恢复)，证据见[键盘验收](../validation/2026-10-15-keyboard-flow/README.md)。
