# ADR-0027：仓库迁移与恢复复用现有存储

日期：2026-10-15。状态：已实施，正式升级交付仍待验收。

## 问题

作品虽是 repo-native，默认 Git 传输不携带自定义 Canon ref，对话也不在 Git 中。原错误提示把移走执行库重新初始化当作优先操作，混淆恢复与重置；只保存 SQLite 会漏掉外置的执行对象。

## 决定

完整恢复以停止写入后的自含目录副本为单位，保留 `.git`、整个 `.suiming`、未提交文件与辅助文件。只传 Canon 历史时复用显式 Git ref 传输或 bundle；作品交换快照不扩展为部署备份。根据目录位置重新登记继续使用已有实现，沿原 Session 继续使用原 checkpoint 与 inbox，不新增迁移身份、任务或状态。

恢复提示优先保全并找回原数据。Canon 丢失不新建权威，旧执行库不强行解释；可用兼容版本打开完整副本。只继续作品时才在另一副本中移出完整执行目录，明确旧对话不自动迁入。

## 取舍

不维护影子 Canon 分支、不把对话再存进作品 Git、不造通用备份包、manifest 或导入转换层。它们会复制现有真源而没有本次故障证明的收益。热备份需要跨文件一致性，不能用普通复制冒充；目前不增加该机制。

正式发行的升级保全是必要能力，不能继续要求用户以丢失对话换取升级。本轮明确其边界与冷恢复依据；实际安装版本跨度和转换尚不存在，不为假设的 schema 预建迁移框架。验证和剩余限制见[验收记录](../validation/2026-10-15-repository-recovery/README.md)，当前操作规范见[迁移与恢复](../repository-recovery.md)。
