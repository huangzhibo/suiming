# ADR-0035：共享 checkout 的双向覆盖保护

- 日期：2026-10-17
- 状态：Accepted

## 背景

作者的多个文件草稿与 Agent 共用 checkout。作者保存已有 `expectedSHA` 检查，但 Agent 的整篇 `write` 只在工具执行时取写前 hash：模型读完文件后，作者在模型思考期间保存，迟到的整篇结果仍可能覆盖作者的新内容。`copy` 覆盖和 `delete` 同样可能基于旧认识操作。`move` 读取源内容与准备删除之间也有遗漏的版本核对。

## 决定

1. 复用现有文件工具与 `FileMutation`：完整覆盖或删除已有文件，必须与本轮 `read` 观察的版本一致。hash 按原始字节计算；非 UTF-8 文件的 `read` 只确认版本和大小，不展开内容。工具闭包只记路径与 hash，不保存正文，不写入 checkpoint。换轮、恢复或另一子任务没有可继承的写入许可，重新读取即可。
2. 新建文件无需先读；自己的完整写入成功后可继续写。读取确认文件不存在后可明确重建；不能拿删除前的读取结果直接复活旧稿。`copy` 到已有不同内容的目标也核对读取版本，同内容复制不需重读。
3. `edit` 按当前文件中的唯一 `oldText` 精确替换，允许作者同时修改其他段落；发现整篇已变化时，不把局部修改成功当成见过其他段落的证明，之后整篇替换须重新读取。自己已知版本上的局部修改可推进内存中的 hash。
4. `move` 在准备阶段核对待删除源文件的 hash 与实际复制的字节一致；落盘阶段继续使用原来的写入临界区与 hash 检查。批量动作不改成事务：执行到一半发生冲突，已完成的动作仍保留，模型检查现状后继续。
5. 桌面保持手动保存、共享草稿和现有冲突比较；迟到保存回执只能确认当时提交的内容，不能清掉后续输入，也不能抢另一文档焦点。合并基线被更新后，若磁盘再次变化，必须再次处理冲突。

## 边界

这不是文件锁、自动合并或动作重放机制。保护 Suiming 的受控写入，不阻止外部编辑器或 host shell 直接覆盖文件；对其他进程在最终 hash 检查与 rename 之间的竞态仍是尽力检测，不宣称跨进程文件系统 CAS。未保存草稿仍属于桌面应用数据，Agent 看不到且不会代存；Agent 的提交仍扫描磁盘候选，不包含编辑器草稿。

允许在窗口中持续编辑与 Agent 工作，但不推断哪个版本在语义上正确，不自动接受一方。无需新草稿存储、worktree、CRDT 或文件服务。实现与隔离验收见[验证记录](../validation/2026-10-17-concurrent-editing/README.md)。
