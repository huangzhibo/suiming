# ADR-0038：协作模式、目标与斜杠命令

- 日期：2026-10-17
- 状态：Accepted；决定一（协作模式）与决定二（目标，Runtime 与 CLI）2026-10-17 已实现，三未实现

## 背景

2026-10-17 的[斗破留出全流程](../validation/2026-10-17-doupo-holdout-pipeline/README.md)用一句话让 Agent 写完 24 节、审稿、修订、提交，两次都没有人插手。作者问：这是固定模式吗？能不能人与 AI 交互着一起完成？又指出 Codex、Claude Code 都有多种模式、goal 和 `/` 命令。

产品没有固定流程：Agent 的系统提示写明「没有必须遵循的创作步骤」「只有作者要求执行……才修改作品」，作者可以讨论、插话、停止、直接改正文、选段提问。缺的是**作者能明说、系统能保证的协作方式**：协作方式现在全靠作者那句话怎么说、模型怎么理解。第二次留出运行里，作者说了「检查并提交」，Agent 就当成全权授权，把一节抽自原作的 Design 改得与原作相反，没有先问作者。改动可见，但作者事后才看到。

本机核对（codex-cli 0.162.1、Claude Code 2.1.302 的发行包与 `--help`）：

| | Codex | Claude Code |
| --- | --- | --- |
| 模式 | 沙箱 read-only / workspace-write / danger-full-access × 审批 on-request / never / 自动审查；功能开关 `collaboration_modes` 已标 removed | 权限模式 default、acceptEdits、plan（只出计划，不实际执行工具）、auto（分类器审批）、dontAsk（未预先批准即拒绝）、bypassPermissions；Shift+Tab 在前四种之间切换 |
| goal | `/goal [<目标>\|clear\|edit\|pause\|resume]`；目标随 thread 持久，状态 active / paused / blocked / usage_limited / budget_limited / complete，token 预算可选。turn 结束而目标仍 active 时，系统以「Continue working toward the active thread goal」自动续下一轮；模型逐条有证据才可标 complete，同一阻塞连续三轮才可标 blocked；只在用户明确要求时创建 | `/goal <条件>`：每次准备停下前，由另一个评估模型判断条件是否满足，未满足就继续；模型也可提议一个条件，用户一键批准；同一时刻一个目标 |
| `/` 命令 | 内置命令与自定义 prompt | 内置命令、自定义命令与 Skill |

## 约束

逐条核对过的：

1. **不重建已删除的层**（[Harness 设计](../harness-design.md)第 16 节）。已删除的包括：权限预设，即 scope、`run.design` / `run.write`、`writableRoots`，理由是「长会话第二轮作者顺口一句『顺便改下大纲』就不成立」；`finish`、交付协议与 `ask_author`；`RunBudget` 与预算；`paused`。判据是终局需不需要、是不是我们自己设的闸，对照物是 Codex / Claude Code 有没有同样的东西。
2. **turn 结束不等于作者的目标达成，系统不做这个判断**（AGENTS.md 工程边界）。
3. **失控成本必须有界**：用量检查点保证没人看着时一轮最多用掉约 600 万折算用量（第 10 节）。现在每个 turn 都由作者的一句话开始，所以「按轮计」等于「按作者说一句计」。任何自动开下一轮的机制都会绕过这道保证。
4. **AI-native 能力对等**：作者能做的作品操作 Agent 也能做，不能让点击成为 Agent 的前置步骤；反过来，作者也可以主动收回某项权限。
5. **工具面每次组装请求时用当前的**（第 3、4 节）：模式切换不需要新的执行状态，下一次请求就生效。
6. Agent 读文件会先把作者在编辑器里的未保存修改存到磁盘（[ADR-0036](0036-agent-editor-sync.md)），所以「只读」必须连这次存盘一起关掉；`read(editor: true)` 本来就能只看草稿、不写文件。
7. 一个 Project 同一时刻只有一个 running session；Session 只有 idle / running 两态。
8. 新增领域实体、持久状态或协议前，要证明终局必需、现有边界表达不了。

## 决定

### 一、三种协作模式

协作模式按对话设置，作者随时可以切换，从下一次模型请求起生效。对话第一次就用默认的「自主」，此后沿用上一次的选择，直到作者再改。

| 模式 | Agent 能做什么 | 系统怎么保证 |
| --- | --- | --- |
| **讨论** | 读、搜索、检查、看 Design 与正文、在界面上定位和展示，在回复里出方案；不改文件、不派子任务、不审稿落盘、不提交 | 工具面不含写入、`delegate`、`review`、`resume_task`、`commit`；这一轮的文件访问不同步作者草稿；需要看草稿时用 `read(editor: true)` |
| **协作** | 改候选、派子任务、审稿；不提交，改完在回复里说明候选里有什么 | 工具面不含 `commit`；作者用现有的候选差异与提交入口提交 |
| **自主**（默认） | 现在的全部能力，包括阶段提交 | 不变 |

为什么是这三种：

- **讨论**对应 Claude Code 的 plan、Codex 的 read-only，是两家都有、作者最常用的「先商量再动手」。它由工具面结构性保证，不靠模型自觉。作者觉得方案可以，切到协作或自主再说「照这个做」，就是 plan 模式的批准。
- **协作**管的是 Canon。作品目录是作者与 Agent 共用的一份候选，Agent 提交时作者未提交的修改也会一起进版本（Harness 设计第 2 节）。想自己决定什么时候成版本的作者，需要把提交权收回来。对照物是两家对有后果的动作要求批准。
- **自主**保留现状，作为默认值：真实创作闭环、回归与留出评测都在这种行为上验证过。默认值以后按作者实际使用再议。

不做的，及理由：

- **按次批准写入**（Claude Code 的 default / acceptEdits、Codex 的 on-request）：我们的写入都只是候选，过 Checker 提交才算数，提交了也能回滚。按次弹窗在长篇里一节就是几十次，是负担，不是保护。
- **按路径限定写入范围**（例如「只改正文，设计先问我」）：这就是第 16 节删掉的 scope 预设。作者顺口一句「顺便改下大纲」，它就得作者先切模式才能办。Design 被改的风险由两样东西兜住：turn 结束的对账列出 Design 改动，事后可见；讨论 / 协作模式，事前可控。第二次留出运行那种情况，在协作模式下会停在候选里等作者看。
- **auto / dontAsk / bypass**：没有需要逐次审批的副作用，也就没有要交给分类器或要绕过的审批。

### 二、目标（goal）

作者用 `/goal <目标>` 或 CLI 给对话设一个目标。目标存在 Session 上，是执行数据，不是作品事实；作品要长期遵守的约束仍写回 `intent/**`。同一时刻一个对话最多一个目标。

- **续跑**：目标 active 时，turn 结束后系统往消息列表放一条「按目标继续」的系统消息并开下一轮。这条消息不是作者说的：界面不显示成作者气泡，turn 结束对账里「作者说了几条」不算它。
- **完成与停下由模型判断，系统只核对事实**。模型用 `update_goal` 标 `complete` 或 `blocked`，都要写理由。`blocked` 包括「需要作者拍板」：意图与 Design 都定不下来的取舍，模型标 `blocked` 并在回复里问清楚，续跑停下。这正是第二次留出运行缺的那一步。作者回一句话，目标就回到 active。标 `complete` 时，系统附一份确定性对账，供作者核对：这一段改了哪些文件、检查结果、有没有过时审稿、有没有未提交候选、有没有未写的 Beat。系统不据此否决模型的判断（约束 2）。
- **有界**：
  1. 用量检查点按「作者开的那一轮」计，目标自动续的轮次都计入同一个窗口，作者再说一句才重新计。这样「没人看着时最多用掉一个检查点的量」不因 goal 改变（约束 3）。撞线就停在 idle，目标仍 active，作者说「继续」就接着跑。
  2. 自动续的一轮如果什么都没改——checkout 与 Canon 都没变，目标也没更新——系统停止续跑，记 `goal_no_progress`。
  3. 作者停止当前 turn，目标随即转为 paused，直到作者 `/goal resume`；作者在目标 active 时插话照常进 inbox。
  4. 进程重启后不自动续跑：目标保持原状态，作者的下一句话或 `/goal resume` 才继续。这和「重连不重执行」一致。
- **模式照常生效**：在讨论模式里设目标，Agent 只能讨论；在协作模式里，目标里的「提交」由作者来做，模型应在需要提交时标 `blocked` 说明。

为什么做，以及为什么不是把删掉的东西加回来：

- 长篇（不少于 3 卷 30 Beat）要跨很多轮推进。现在 turn 一结束就停，作者不在场时只能等着说「继续」，而模型也会在中途停下汇报。
- 删掉的 `finish` 是每一轮都必须声明交付，由系统判断目标是否达成。goal 是作者主动开的；不设目标时一切照旧；完成由模型判断。两家现在都有同样的东西。
- 不另设 token 预算（第 16 节删掉的 `RunBudget`）：用量检查点已经覆盖，而且现在按作者开的那一轮计。
- 不用独立的评估模型判断完成（Claude Code 的做法）：每次停下多一次调用。我们有确定性对账，需要时还有独立审稿。真实运行证明模型自评不够用时再加。
- 模型不自己创建目标。Claude Code 的「提议目标、作者一键批准」以后可以加，现在不做。

### 三、`/` 命令

桌面输入框在行首输入 `/` 打开命令菜单，可以用键盘选择，输入法组字时不触发。命令只是现有能力的入口，不新增能力；与按钮做同一件事，行为、名称与快捷键一致（[作者工作台设计](../workbench-design.md)第 7 节）。

- **内置**：`/goal`（设定、清除、暂停、继续）、`/讨论` `/协作` `/自主`（切模式）、`/模型`（打开模型选择）、`/新对话`、`/提交`（打开候选差异与提交）。
- **自定义**：作者把常用的话存成命令，放在应用配置目录 `commands/<名字>.md`，与 `config.toml` 同处，`$ARGUMENTS` 替换为命令后面的文字。发出去的就是作者自己的消息，界面上显示展开后的原文。工作流习惯不是作品事实，不放进作品目录；作品要长期遵守的约束仍写回 `intent/**`。
- 不做：作者触发的 `/compact`（系统自动摘要已经覆盖）、让模型调用的命令或 Skill（Harness 不加载 host 的 Skill，第 6 节）、CLI 的斜杠命令（CLI 已有子命令）。

## 接口位置

- Session 记录加 `collaboration`（模式）与 `goal`（目标原文、状态、理由、设定时间）；命令目录的 `session.send` 加 `mode`；新增 `session.goal`（set / clear / pause / resume），CLI 是 `suim session goal`，`set` 跑到续跑停下才返回。两份命令目录各加一条，摘要投影共用 `domain-schema.ts`。
- 根 Agent 的工具面按模式组装；协作模式不给 `commit`；讨论模式下根 Agent 的文件环境只读，读取不触发草稿保存。goal 的 `update_goal` 只在目标 active 时声明。
- 用量检查点的窗口从「这一轮」改为「作者开的那一轮加它自动续的轮次」；`goal_no_progress` 与 `turn_usage_checkpoint` 一样回 idle，加一句原因。
- AG-UI：模式与目标随 `suiming.session` 扩展事件下发；续跑消息作为系统消息进事件流。

## 验收

按顺序实现，每项单独提交，先补失败用例：

1. **协作模式**
   - 机制：三种模式的工具面逐个核对；讨论模式下根 Agent 尝试写入被拒，一轮之后 checkout 逐字节不变，作者草稿没有被保存；协作模式里没有 `commit`；切换从下一次请求起生效，并写进 turn 开头的系统附注；重启后模式保留。
   - 桌面 E2E：在输入框切换模式；讨论模式下发一句「改第二节」，文件与草稿都不变；协作模式下候选进入差异页，由作者提交。
   - 真实模型：在样例作品上，讨论模式的「把第二节改紧凑些」只出方案，不碰文件；协作模式改完不提交，并说明候选里有什么。回归脚本各加一项。
2. **目标**
   - 机制：turn 结束后续跑；`complete` / `blocked` 停下；无改动的续跑轮次停下；用量检查点跨自动轮次累计，撞线停下且目标保持 active；作者插话、作者停止转 paused；进程重启不自动续跑；续跑消息不计入作者消息对账；CLI `session goal set` 等到停下才返回。
   - 真实模型：用[留出流程](../validation/2026-10-17-doupo-holdout-pipeline/holdout.py)加 goal 跑一次，记下续跑轮数、停下原因与对账；再用调低的检查点验证撞线即停。
3. **`/` 命令**
   - 桌面 E2E：菜单只在行首出现；输入法组字不触发；方向键、回车、Esc；每个内置命令与对应按钮结果相同；自定义命令从配置目录读出并展开参数，发出的消息就是展开后的文字。

现行规范在实现时同步：AGENTS.md「turn 结束不等于作者的目标达成」一段、[Harness 设计](../harness-design.md)第 3、6、10、16 节、[作者工作台设计](../workbench-design.md)的对话区、[需求与目标](../vision-and-requirements.md) 5.1 节。本 ADR 只记录决定与理由。
