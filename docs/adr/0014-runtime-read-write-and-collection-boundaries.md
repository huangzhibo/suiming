# ADR-0014：复用现有边界修正读取、并行写入与执行对象回收

- 状态：Accepted
- 日期：2026-10-07

## 背景

代码审查复现了四种失败：并行组越过前面的串行动作；Writer 的文件读取被拒后仍能经搜索读到 Source 原文；并行子任务的写范围重叠且 hash 检查与落盘之间可被另一写入插入；GC 扫描期间新 turn 已经开始又结束，仍按旧引用集合删除新 checkpoint 复用的节点。

这些是已有边界没有贯彻到所有调用路径，不需要新的领域实体、执行引擎或持久调度状态。

## 决定

1. loop 按模型调用顺序执行和交付。只有当前位置相邻、独占输出标识没有交集的动作才并行；重叠号段自动串行。标识只活在这次响应的内存中，不成为任务图。
2. 文件工具和领域查询共用角色的读取谓词。任务的候选扫描结果按它过滤，状态查询的已提交侧也按同一范围过滤。Source 子任务显式指定检查本 Source，根候选缺失 Target 仍报错；Source 与 Writer 不再提前编译无关的 Target Frame。
3. Source Reader 的笔记按原委派动作 id 分配一个独占路径，续做仍使用同一路径。分段 extractor 沿用 Beat 号段和笔记路径。受限环境的写入临界区由同一进程里的所有实例共享，检查 hash 与落盘一起串行化。
4. GC 每批删除都在写事务内检查：没有活跃 turn，且 Session / Task 的版本集合与引用扫描开始时一致。发生变化即放弃余下删除，下次重新扫描。复用现有实体版本，不新增 GC 世代。引用对象丢失或损坏时不删除任何对象，也不记录为成功回收；后台路径输出维护诊断。
5. checkpoint 缓存不可变的编码节点，按数量与字节数限制缓存大小；每次解码仍产生独立可变结果。读取失败不保留在缓存里。缓存不拥有执行对象生命周期，turn 开始清除 Harness 的归档缓存。

## 后果与限制

- Writer、Reviewer 和 Source 角色的领域工具不再绕过文件读取范围，留出评测不只依赖工具名列表隔离原文。
- 模型仍可以自主拆任务；范围重叠只改变执行顺序，不拒绝合法工作。
- 写入临界区保证同一进程的受控写入互斥。任意外部编辑器与 host 不参加这个锁，hash 检查仍是尽力发现冲突，不能宣称普通文件系统上有跨所有程序的原子 CAS。
- GC 诊断当前在 Runtime 返回值与进程诊断输出中，尚无独立的桌面维护面板。
