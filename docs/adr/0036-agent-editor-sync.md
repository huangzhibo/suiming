# ADR-0036：Agent 按需同步作者编辑

- 日期：2026-10-17
- 状态：Accepted

## 背景

[保存时机实验](../validation/2026-10-17-save-policy/README.md)确认了两件不同的事：Agent 文件工具需要看到作者的新编辑；语法合法的半句话可能进入候选并被提交。最初据此设计「引用 → 选择保存范围 → 保存并发送」，虽能保护未交付文件，却让作者承担了上下文与同步调度。作者明确要求按 AI-native 原则调整，普通工作应尽量只需表达需求并发送。

核对 Claude Code 2.1.301 的官方发行包与隔离函数探针，保存按 Read / Edit / Write 的目标路径触发，不遍历所有 Tab。其失败或超时后继续使用磁盘内容；本产品选择把失败交给模型处理，不能默认为已同步。证据与限度见[验证记录](../validation/2026-10-17-agent-editor-sync/README.md)。

## 决定

1. **作者操作不做 Agent 的前置步骤。**作品能力应同时供作者与 Agent 使用；作者能比较、合并和恢复的文件，Agent 也必须具备对应能力。仅因实现依赖按钮或编辑器操作而要求作者接手，是能力缺口。保留路径权限、版本核对、Checker 和 Canon 提交边界。
2. 普通消息直接发送，引用可选，不增加保存范围、逐文件勾选或「保存并发送」按钮。编辑器不做全局定时保存；Agent 实际读写某个文件时，系统把该路径的共享草稿通过原 `workspace.file.save` 保存到 checkout。目录列举、全书派生搜索、纯对话与 Canon 提交不偷偷冲刷所有草稿。复制 / 移动 / 删除及子任务经过同一个受限文件环境。
3. 保存、候选与 Canon 提交分离。自动保存不是完成度判定，也不推进 Canon；明确调用既有 `commit` 后仍由 Checker 核对整个候选。可以保存工作中间态，不能承诺 Checker 能判断语义完整性。未被访问的其他文件草稿不自动落盘。
4. 保存失败返回模型，原草稿与磁盘都保留。复用 `read(editor: true)` 读取草稿、原基线与磁盘，`write(draftSHA)` 提交合并内容；同时校验模型读过的磁盘版本与草稿 hash。文件缺失可以经同一路径明确恢复；根 Agent 与子任务仍受既有角色权限约束。没有额外合并队列、第二份候选、强制作者确认或新工具家族。
5. 保存过程中仍可编辑。普通保存迟到时沿用 `savedDocument` 推进基线、保留新输入；基线已被新保存推进时忽略旧回执。合并期间继续输入则保留旧基线与新草稿，下一次访问重新合并，防止把新磁盘合并结果盖回旧稿。同步命令携带预期作品 ID，停止后切换作品的迟到请求不能写到另一作品的同路径。整个过程不切页、不抢焦点。
6. 编辑器协作是可选的临时文件端口，不是新的执行状态。桌面经 typed IPC 请求活动工作台，恢复成功后才接收请求；重载可重接保存 / 检查，合并结果未知时不自动重放。关窗后需要草稿时恢复隐藏工作台，不要求作者重开窗口。CLI / host 继续使用同一 checkout，外部进程不会取得桌面未保存缓冲；不扩张为跨进程编辑器同步协议。

## 验收与取舍

范围与并发用受控时序和真实文件断言，界面通过隔离 Electron 实际操作；真实模型另验模型能否理解并完成冲突合并。保持一条保存与覆盖保护路径，不照搬 Claude 在同步失败时静默继续的行为。

隐藏工作台复用原 localStorage 草稿和恢复逻辑，有初始化成本，但避免新建主进程草稿库或让运行依赖可见窗口。草稿损坏、权限不足等故障仍应如实返回；AI-native 不等于静默丢弃冲突的一边。
