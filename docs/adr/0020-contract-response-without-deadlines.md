# ADR-0020：期待的回应记录与叙事期限分开

- 日期：2026-10-13
- 状态：接受

## 问题

StoryContract 的 `deadline` 同时承担故事内承诺、作者节奏计划和 Checker 阻塞条件。界面在实际回应处标「回应期限」，混淆计划与事实；Checker 还建议前移回应标记以过检查，可能诱导失真的作品记录。

## 决定

删除结构化 `deadline`，不以范围字段或软警告复制这套推断。故事内期限与局部节奏要求留在 Contract 主体，全局作者要求留在 Intent。语义规则见 [Story Language](../../story-language/outline.md)。实际处理过程可跨多节：以 advance 记录推进，以 resolve 声明处理完成；回应不等于承诺成功兑现。

保留引用和生命周期顺序检查，保留完整作品的处理记录对账；未完待续 Target 和 Source 允许已建立的期待开放。完整性缺口作为设计诊断显示，沿用现有提交分层，不新增 Canon 提交门槛。Checker 只检验记录是否完整、是否自洽；回应是否充分、是否符合作者节奏要求由 Review 判断。诊断不再引导前移或伪造标记。

Runtime 的写作上下文、状态查询与影响分析，及界面状态、路径、故事轴、反向导航都只使用实际锚点。取消期限徽标、到期状态、计划期限连边；保留路径可视化及对非法候选的警示。

## 数据与代价

这是验证门前的格式变更，不增加旧格式兼容层。旧字段会被严格 schema 拒绝。迁移前备份作品与版本：实际锚点已表达的重复期限可以移除；独立创作节奏意图必须转入正文，不能丢弃或伪造回应。公共示例中的 12 个期限均对应已有回应位置，移除重复字段，保留正文和锚点。历史阅读笔记与验收记录保留原貌。

已有版本保持原始字节，当前格式不保证旧版本能重新通过 Checker；版本查看仍可读原文。迁移应作为新的候选提交，经 Checker 推进 Canon，不改写旧历史。

现场验证发现旧格式历史使正文时效回退成全书已变。派生层改为明确的 `unknown`，工作台以灰色和「时效无法确认」显示，发布仍须满足 current；不加载旧 schema、不改写版本、不伪造时效。
