# ADR-0025：子任务失败反馈必须给出可用的续做入口

- 日期：2026-10-14
- 状态：Accepted

## 背景

连续创作与异常恢复组合验收发现：独立审稿模型失败后，Task 与 checkpoint 已保留，父模型却只收到失败原因，没有 Task ID。`resume_task` 已能续做失败任务，但父模型缺少参数，只能猜测或重新委派。作者停止时已有的 `childProgress` 提示没有覆盖这条失败路径。

## 决定

调用失败、输出截断和未提交结果这三类可继续处理的子任务失败，在原有工具错误中附上 `childProgress`：真实任务编号、已完成调用数、候选仍在以及 `resume_task` 用法。是否继续或调整方向仍由父模型决定；系统不自动重建任务。

开场超窗、原模型已不可用、反复无进展仍保留原来的范围或配置诊断，不建议原样续做。既有瞬时请求自动重试不变；本决定处理自动重试耗尽后交回父模型的结果。

不新增恢复状态、持久实体、预检所有角色模型或 UI 确认流程。沿用同一 Task、模型绑定、checkpoint、工具结果、活动事件与 Canon 提交路径。Langfuse 只核对执行过程，不承担恢复真源。

## 验收

修复前父模型缺少编号的回归失败；修复后独立模型失败、重载、原任务续做与单次提交均有回归。真实创作、受控故障与真实主模型的证据分别见[组合验收](../validation/2026-10-14-continuous-recovery/README.md)，不把合成审稿当文学评价。
