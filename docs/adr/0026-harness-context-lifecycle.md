# ADR-0026：对齐 pi 的通用执行机制

日期：2026-10-15。状态：已实施，真实长篇验收继续。

## 问题

对照 pi `b45e0ebcc`（包版本 1.2.0）后，确认旧作者消息在压缩后仍全部发送、超限时没有摘要恢复机会、单行读取没有字节边界，以及重试与工具执行阶段不可见。当前 pi-durable 已有完整持久执行实现，仍标记 Experimental；coding-agent 仍使用 agent-core，不能混称为一个实现。

## 决定

直接复用 pi-ai 的模型协议、错误分类与纯工具；持久执行仍由现有 Session、Task、checkpoint 和 AG-UI 承担，不引入平行存储或通用任务图。

已升级发布版 pi-ai / pi-telemetry 1.2.0，直接复用其错误分类与 token 估计工具。读取按 50 KiB 和行数双限，并为小说长段落提供码点续读；没有为复用文件工具而引入 pi 的完整执行环境。Source 补全按号段预载，跨段依据按需读取。原始消息始终保存；请求可以总结旧作者消息，保留当前要求、近期原话、未完成事项与任务开场。摘要不是 Canon。超限恢复与常规压缩共用机制，不靠清空信息后盲目重发。需要长期保留的作品约束继续写回 Intent。

## 验收

故障用例先行，覆盖改口、长段落续读、调用与结果配对、压缩失败与重启、窗口切换和用量关联；实际连续创作通过 Langfuse 与执行存储对账。机制通过不等于真实质量通过。分步结果见[验收记录](../validation/2026-10-15-harness-alignment/README.md)。

自动摘要和超限恢复共用现有 loop；删除工具结果清空与两档压缩附注，模型主动摘要复用同一投影。执行进度复用 AG-UI，强退活动收尾复用 SQLite 执行状态提交事务；没有新增执行真源、持久服务或任务图。尚未发布的 pi main 修复和 Experimental 的 pi-durable 不在此次依赖升级中。
